1. Enunciat i arquitectura del gestor de productes

Construirem una aplicació Windows Forms per gestionar un catàleg de productes. L'usuari podrà consultar les dades, cercar-les, filtrar-les, crear productes, editar-los i eliminar-los. La informació es guardarà en PostgreSQL i la interfície no contindrà SQL ni detalls de connexió.

Aquest és el projecte integrador del bloc. Cada secció explicarà i construirà una peça verificable sobre la mateixa base, amb el codi necessari perquè l'aplicació final sigui executable. No deixarem cap part essencial com una tasca pendent ni obligarem l'alumnat a completar fragments imprescindibles pel seu compte.

Figura

Què ha de poder fer l'aplicació

  • obrir una finestra principal amb la llista de productes;
  • obrir una finestra separada per crear o editar un producte;
  • validar el nom, el preu i les unitats abans de desar;
  • mostrar els productes en un DataGridView;
  • cercar per text i aplicar filtres sense modificar les dades originals;
  • persistir les dades en una base de dades PostgreSQL;
  • informar dels errors sense afirmar que una operació ha funcionat quan no ho ha fet;
  • permetre depurar el recorregut d'una alta, una edició i una eliminació.

Què queda fora del projecte

Per mantenir un abast assumible, no implementarem autenticació, usuaris, permisos, sincronització remota ni una API web. El projecte treballarà amb un entorn local de pràctiques i una base de dades preparada específicament per a aquest exercici.

Decisions de dades

La taula productes tindrà una identitat estable i les regles mínimes que ja hem practicat: nom obligatori, preu no negatiu i unitats no negatives. La interfície ajudarà l'usuari a corregir els valors, però PostgreSQL també els protegirà amb les seves restriccions.

La connexió s'obtindrà de la configuració local. No posarem cap contrasenya dins del codi, de les captures ni del repositori.

Definir la classe Producte

La classe conté les dades que PostgreSQL guardarà. L'identificador és necessari per editar o eliminar una fila sense dependre del nom, perquè dos productes poden tenir el mateix text descriptiu.

CSHARP Models/Producte.cs 
namespace GestorProductes.Models;

public sealed class Producte
{
    public int Id { get; set; }

    public string Nom { get; set; } = "";

    public decimal Preu { get; set; }

    public int Unitats { get; set; }
}

Fem servir decimal per als preus perquè representa millor els valors monetaris que un tipus de coma flotant. Les unitats són un enter perquè no volem permetre fraccions de producte en aquest catàleg.

Posar les regles a prop de les dades

La interfície donarà missatges adaptats a l'usuari, però el model també pot exposar una validació comuna perquè cap altra finestra accepti regles diferents:

CSHARP Models/Producte.cs 
public IReadOnlyList<string> Validate()
{
    var errors = new List<string>();

    if (string.IsNullOrWhiteSpace(Nom))
    {
        errors.Add("El nom és obligatori.");
    }

    if (Preu < 0)
    {
        errors.Add("El preu no pot ser negatiu.");
    }

    if (Unitats < 0)
    {
        errors.Add("Les unitats no poden ser negatives.");
    }

    return errors;
}

Aquest mètode completa la classe anterior; no és una classe alternativa. Afegeix-lo dins de Producte, després de les propietats. La pantalla el podrà utilitzar abans d'enviar dades al repositori i el repositori el podrà tornar a comprovar abans d'un write.

Implementar el repositori CRUD

CSHARP Data/ProducteDbRepository.cs 
using GestorProductes.Models;
using Npgsql;

namespace GestorProductes.Data;

public sealed class ProducteDbRepository : IProducteRepository
{
    private readonly string connectionString;

    public ProducteDbRepository(string connectionString)
    {
        this.connectionString = connectionString;
    }

    public IReadOnlyList<Producte> GetAll()
    {
        const string sql = """
            SELECT id, nom, preu, unitats
            FROM productes
            ORDER BY nom, id;
            """;

        using var connection = new NpgsqlConnection(connectionString);
        connection.Open();
        using var command = new NpgsqlCommand(sql, connection);
        using NpgsqlDataReader reader = command.ExecuteReader();
        var productes = new List<Producte>();

        while (reader.Read())
        {
            productes.Add(new Producte
            {
                Id = reader.GetInt32(0),
                Nom = reader.GetString(1),
                Preu = reader.GetDecimal(2),
                Unitats = reader.GetInt32(3)
            });
        }

        return productes;
    }

    public void Add(Producte producte)
    {
        Validate(producte);
        ExecuteProducteCommand("""
            INSERT INTO productes (nom, preu, unitats)
            VALUES (@nom, @preu, @unitats);
            """, producte, includeId: false);
    }

    public void Update(Producte producte)
    {
        Validate(producte);
        ExecuteProducteCommand("""
            UPDATE productes
            SET nom = @nom, preu = @preu, unitats = @unitats
            WHERE id = @id;
            """, producte, includeId: true);
    }

    public void Delete(int id)
    {
        using var connection = new NpgsqlConnection(connectionString);
        connection.Open();
        using var command = new NpgsqlCommand(
            "DELETE FROM productes WHERE id = @id;", connection);
        command.Parameters.AddWithValue("id", id);

        if (command.ExecuteNonQuery() != 1)
        {
            throw new InvalidOperationException("El producte no existeix.");
        }
    }

    private void ExecuteProducteCommand(
        string sql,
        Producte producte,
        bool includeId)
    {
        using var connection = new NpgsqlConnection(connectionString);
        connection.Open();
        using var command = new NpgsqlCommand(sql, connection);

        if (includeId)
        {
            command.Parameters.AddWithValue("id", producte.Id);
        }

        command.Parameters.AddWithValue("nom", producte.Nom);
        command.Parameters.AddWithValue("preu", producte.Preu);
        command.Parameters.AddWithValue("unitats", producte.Unitats);

        if (command.ExecuteNonQuery() != 1)
        {
            throw new InvalidOperationException("El producte no s'ha pogut modificar.");
        }
    }

    private static void Validate(Producte producte)
    {
        IReadOnlyList<string> errors = producte.Validate();
        if (errors.Count > 0)
        {
            throw new ArgumentException(string.Join(" ", errors));
        }
    }
}

Les consultes estan parametritzades i el repositori torna a validar abans d'escriure. PostgreSQL reforça les regles amb NOT NULL i CHECK; cap operació pot informar d'èxit si no ha modificat exactament la fila esperada.

Validar abans de tancar

El botó Acceptar converteix el text en un model, executa la validació comuna i només tanca el diàleg si no hi ha errors:

CSHARP Forms/ProducteEditorForm.cs 
private void btnAcceptar_Click(object? sender, EventArgs e)
{
    if (!decimal.TryParse(
        txtPreu.Text,
        NumberStyles.Number,
        CultureInfo.CurrentCulture,
        out decimal preu))
    {
        MessageBox.Show("Escriu un preu vàlid.");
        txtPreu.Focus();
        return;
    }

    var producte = new Producte
    {
        Id = id,
        Nom = txtNom.Text.Trim(),
        Preu = preu,
        Unitats = (int)nudUnitats.Value
    };

    IReadOnlyList<string> errors = producte.Validate();
    if (errors.Count > 0)
    {
        MessageBox.Show(string.Join(Environment.NewLine, errors));
        return;
    }

    Resultat = producte;
    DialogResult = DialogResult.OK;
    Close();
}

Aplicar la cerca sense perdre la col·lecció completa

productes conserva totes les files retornades per PostgreSQL. El DataGridView rep una llista filtrada nova; mai eliminem elements de la col·lecció original només perquè no coincideixin amb la cerca actual:

CSHARP ProducteFilter.cs 
using GestorProductes.Models;

namespace GestorProductes;

public static class ProducteFilter
{
    public static IReadOnlyList<Producte> Aplica(
        IEnumerable<Producte> productes,
        string text,
        bool nomesDisponibles)
    {
        IEnumerable<Producte> resultat = productes;
        string cerca = text.Trim();

        if (cerca.Length > 0)
        {
            resultat = resultat.Where(producte =>
                producte.Nom.Contains(
                    cerca,
                    StringComparison.CurrentCultureIgnoreCase));
        }

        if (nomesDisponibles)
        {
            resultat = resultat.Where(producte => producte.Unitats > 0);
        }

        return resultat.ToList();
    }
}
CSHARP Forms/ProductesForm.cs 
private void AplicaFiltre()
{
    IReadOnlyList<Producte> visibles = ProducteFilter.Aplica(
        productes,
        txtCerca.Text,
        chkDisponibles.Checked);
    binding.DataSource = visibles;
    lblEstat.Text = $"{visibles.Count} de {productes.Count} productes visibles";
}

El filtre no canvia les dades ni el repositori. Si l'usuari crea, edita o elimina un producte, CarregaProductes torna a llegir totes les files i després reaplica els criteris actius.

Evitar resultats incoherents

Hi ha tres errors habituals que aquest patró evita:

  • filtrar la mateixa llista i perdre definitivament les files que no coincideixen;
  • fer una consulta a la base de dades en cada pulsació, carregant innecessàriament el servidor;
  • mostrar un comptador que no coincideix amb les files visibles.

La cerca és una ajuda de presentació. Les operacions d'edició i eliminació continuen utilitzant el Producte seleccionat i el seu Id, encara que la graella estigui filtrada.

Comprovar la cerca i el filtre

  1. carrega diversos productes amb noms diferents i almenys un sense existències;
  2. escriu una part del nom i comprova que només queden coincidències;
  3. activa «Només amb existències» i comprova que desapareix el producte buit;
  4. neteja el text i desactiva la casella: torna a aparèixer tot el catàleg;
  5. edita una fila filtrada i comprova que després de desar continua respectant el filtre;
  6. elimina una fila filtrada i comprova que el comptador i la graella es recalculen.
Èxit

La finestra permet cercar i filtrar sense tocar les dades de PostgreSQL ni duplicar la lògica del repositori. Les operacions CRUD continuen funcionant sobre el model i l'identificador real de cada fila.

Ampliació opcional: filtres combinats

Com a ampliació, pots afegir un rang de preus o ordenar els resultats. Mantén un únic mètode de filtratge i deixa clar quins criteris són visuals i quins haurien de convertir-se en consultes PostgreSQL quan el volum de dades ho justifiqui.

9. Tests unitaris del model i dels filtres

Les comprovacions manuals ens han permès verificar les finestres i la connexió, però no substitueixen els tests unitaris. Un test unitari comprova una peça petita del programa, de manera ràpida i sense obrir cap finestra ni connectar-se a PostgreSQL.

Figura

La idea en quatre passos

Tots els tests d'aquesta secció segueixen el mateix esquema:
