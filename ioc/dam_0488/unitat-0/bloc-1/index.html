1. Variables: tipus, nom i valor

Abans de crear una finestra, un botó o una classe, un programa necessita representar informació. Un inventari necessita saber quants productes hi ha; una aplicació de reserves necessita saber el nom d'una persona i si una plaça està disponible; un formulari necessita guardar temporalment el que l'usuari hi ha escrit.

En C#, aquesta informació es guarda en variables. Una variable té tres parts que hem de saber llegir:

  • el tipus, que indica quina mena de dada pot contenir;
  • el nom, que és com la identificarem dins del programa;
  • el valor, que és la dada que conté en un moment concret.
Figura

Un primer exemple: les unitats d'un producte

Imaginem que volem guardar les unitats disponibles d'un producte. El valor inicial és 12:

CSHARP Programa.cs 
int unitats = 12;

La lectura és directa:

PartValorQuè significa
TipusintUn nombre enter, sense decimals.
NomunitatsEl nom que farem servir per consultar o canviar la dada.
Valor inicial12La quantitat disponible quan comença el programa.

El signe = no vol dir «és igual que» en el sentit matemàtic. En aquesta instrucció vol dir «assigna aquest valor a aquesta variable». Primer s'avalua el que hi ha a la dreta i després es guarda el resultat a l'esquerra.

El valor d'una variable pot canviar

Una variable no és una etiqueta enganxada per sempre a una dada. Durant l'execució podem actualitzar-la:

CSHARP Programa.cs 
int unitats = 12;
unitats = unitats + 3;

Console.WriteLine(unitats);

Després de la segona instrucció, unitats val 15. El programa ha llegit el valor actual, hi ha sumat 3 i ha desat el resultat en la mateixa variable.

Aquesta forma d'actualitzar una dada apareixerà sovint en els exemples del mòdul:

  • quan entra un producte nou, augmenten les unitats;
  • quan es fa una venda, disminueixen les unitats;
  • quan es carrega un formulari, les variables reben les dades de l'usuari.

Triar el tipus adequat

El tipus no és un detall estètic. Ajuda el compilador a detectar errors i ens diu quines operacions tenen sentit.

CSHARP Producte.cs 
string nomProducte = "Teclat";
int unitats = 12;
decimal preu = 24.95m;
bool actiu = true;
TipusExempleQuan el farem servir
string"Teclat"Text, noms, descripcions o codis.
int12Quantitats enteres, com unitats o posicions.
decimal24.95mImports i valors on els decimals han de ser fiables.
booltrueSituacions amb dues possibilitats: actiu/inactiu, sí/no.

Observa la lletra m després de 24.95. Indica que volem tractar el literal com un decimal. És una petita convenció de C# que convé començar a reconèixer des del principi.

Un exemple complet i llegible

Ara ajuntem les quatre dades per descriure un producte. Encara no hem creat cap classe: simplement estem practicant com identificar la informació que el programa haurà de gestionar.

CSHARP Programa.cs 
string nomProducte = "Teclat";
decimal preu = 24.95m;
int unitats = 12;
bool actiu = true;

Console.WriteLine($"Producte: {nomProducte}");
Console.WriteLine($"Preu: {preu} €");
Console.WriteLine($"Unitats: {unitats}");
Console.WriteLine($"Actiu: {actiu}");

La interpolació de cadenes, que comença amb el símbol $, permet inserir el valor d'una variable dins d'un text. És més llegible que anar concatenant fragments amb molts signes +.

Errors habituals

Important
  • Intentar guardar text dins d'una variable int.
  • Canviar el nom de la variable en una línia i oblidar actualitzar-lo en les altres.
  • Confondre l'assignació (=) amb una comparació, que treballarem quan estudiem les condicions.
  • Fer servir un double sense entendre les seves particularitats quan treballem amb imports.

2. Condicions i bucles: fer que el programa reaccioni

Una aplicació útil no es limita a mostrar sempre el mateix resultat. Ha de poder prendre decisions i repetir una operació tantes vegades com calgui. Un gestor d'estoc, per exemple, ha de distingir entre un producte disponible i un producte esgotat, i ha de poder revisar tots els productes d'una llista.

En C# fem aquestes dues coses amb:

  • condicions, per escollir quin camí segueix el programa;
  • bucles, per repetir un bloc d'instruccions.
Figura

Una primera decisió amb if

Comencem amb una pregunta molt concreta: hi ha unitats disponibles?

CSHARP Programa.cs 
int unitats = 12;

if (unitats > 0)
{
    Console.WriteLine("El producte està disponible");
}

La condició que hi ha entre parèntesis es calcula abans d'executar el bloc. Si és certa, s'executen les instruccions entre claus. Si és falsa, el programa continua després del bloc.

Podem indicar també què ha de passar quan la condició no es compleix:

CSHARP Programa.cs 
int unitats = 0;

if (unitats > 0)
{
    Console.WriteLine("El producte està disponible");
}
else
{
    Console.WriteLine("Producte esgotat");
}

Els operadors de comparació més habituals són:

OperadorPreguntaExemple
==És igual?unitats == 0
!=És diferent?nom != ""
>És més gran?unitats > 0
<És més petit?preu < 10
>= / <=Inclou el límit?unitats <= 5

Un error molt habitual és fer servir un sol signe = quan volem comparar. Recorda: = assigna un valor; == compara dos valors.

Combinar preguntes

Una aplicació real sovint necessita comprovar més d'una cosa. Per exemple, un producte només es pot vendre si està actiu i encara té unitats:

CSHARP Programa.cs 
bool actiu = true;
int unitats = 3;

if (actiu && unitats > 0)
{
    Console.WriteLine("Es pot vendre");
}
else
{
    Console.WriteLine("No es pot vendre");
}

L'operador && vol dir «i». Totes dues condicions han de ser certes. L'operador || vol dir «o» i permet continuar quan n'hi ha prou que se'n compleixi una.

Repetir una operació amb for

Si volem mostrar els números de l'1 al 5, no cal escriure cinc Console.WriteLine. Un bucle for agrupa la inicialització, la condició de continuació i l'increment:

CSHARP Programa.cs 
for (int numero = 1; numero <= 5; numero++)
{
    Console.WriteLine(numero);
}

La variable numero comença valent 1. Després de cada volta augmenta en 1. Quan arriba a 6, la condició numero <= 5 ja no es compleix i el bucle acaba.

Recórrer una col·lecció amb foreach

Quan tenim diversos productes, el que ens interessa normalment no és el seu índex, sinó processar-los un per un. Per això farem servir foreach:

CSHARP Programa.cs 
string[] productes = { "Teclat", "Ratolí", "Pantalla" };

foreach (string producte in productes)
{
    Console.WriteLine($"Producte: {producte}");
}

El bucle assigna cada element de la col·lecció a la variable producte i executa el bloc una vegada per a cada element. Més endavant recorrerem una List<Producte>, però la idea serà exactament la mateixa.

Un exemple que combina decisions i repetició

Podem revisar una petita llista d'estocs i avisar només dels productes que necessiten reposició:

CSHARP Programa.cs 
int[] estocs = { 12, 0, 4, 1 };

foreach (int estoc in estocs)
{
    if (estoc == 0)
    {
        Console.WriteLine("Esgotat");
    }
    else if (estoc <= 2)
    {
        Console.WriteLine("Cal reposar aviat");
    }
    else
    {
        Console.WriteLine("Estoc correcte");
    }
}

Aquest exemple ja s'assembla a una funcionalitat real. Encara no tenim una interfície gràfica, però ja podem expressar una regla de negoci: segons el valor de l'estoc, el programa mostra un missatge diferent.

Important
  • No posar les claus del bloc al lloc correcte.
  • Crear un bucle que no modifica mai la seva condició i no acaba.
  • Fer servir for quan només necessitem processar cada element d'una col·lecció.
  • Fer comparacions amb textos sense tenir en compte si són buits.

Pràctica guiada: classificar l'estoc

Parteix d'una llista de quatre quantitats d'estoc. Recorre-la amb foreach i mostra un missatge diferent segons si el valor és zero, és baix o és suficient.

Amb variables, condicions i bucles ja podem descriure comportaments. A la secció següent veurem com agrupar instruccions amb noms significatius mitjançant mètodes.

3. Mètodes: posar nom a les operacions

A mesura que un programa creix, és fàcil acabar repetint les mateixes instruccions en molts llocs. Si cada vegada que volem mostrar l'estat d'un producte escrivim totes les comprovacions, el codi es torna llarg i difícil de mantenir.

Un mètode és un bloc d'instruccions amb un nom. El podem invocar quan necessitem fer aquella operació. Un bon nom explica què fa el mètode i ens permet llegir el programa com una seqüència d'accions.

Figura

Un mètode que fa una acció

Comencem amb un mètode que només mostra un missatge. La paraula void indica que no retorna cap valor:

CSHARP Programa.cs 
static void MostrarBenvinguda()
{
    Console.WriteLine("Benvingut al gestor de productes");
}

MostrarBenvinguda();

La definició del mètode i la crida són dues coses diferents:

  • la definició explica quines instruccions s'executaran;
  • la crida, MostrarBenvinguda(), demana que s'executin en aquell punt.

Podem cridar el mateix mètode més d'una vegada, però normalment és més útil donar-li dades perquè actuï segons el cas concret.

Passar dades amb paràmetres

Un paràmetre és una dada que el mètode rep quan el cridem. En aquest exemple el mètode rep el nom d'un producte:

CSHARP Programa.cs 
static void MostrarProducte(string nom)
{
    Console.WriteLine($"Producte: {nom}");
}

MostrarProducte("Teclat");
MostrarProducte("Ratolí");

nom és el paràmetre del mètode. Les cadenes "Teclat" i "Ratolí" són els arguments que hi passem en cada crida. El mètode és el mateix, però el resultat canvia segons la dada rebuda.

També podem rebre més d'un paràmetre. Per exemple, per mostrar el resum d'un producte:

CSHARP Programa.cs 
static void MostrarResum(string nom, int unitats)
{
    Console.WriteLine($"{nom}: {unitats} unitats");
}

MostrarResum("Teclat", 12);
MostrarResum("Ratolí", 0);

Un mètode que retorna un resultat

Moltes operacions no només mostren informació: calculen un resultat que el programa haurà de fer servir després. En aquest cas, en lloc de void indiquem el tipus del valor que retornarem.

CSHARP Programa.cs 
static decimal CalcularTotal(decimal preu, int unitats)
{
    return preu * unitats;
}

decimal total = CalcularTotal(24.95m, 3);
Console.WriteLine($"Total: {total} €");

El mètode rep un preu i unes unitats, multiplica les dues dades i les retorna amb return. El resultat de la crida es pot guardar en una variable, mostrar o passar a un altre mètode.

El tipus de retorn forma part de la signatura del mètode. Si hem declarat decimal, totes les rutes del mètode han d'acabar retornant un decimal.

Extreure una regla del programa

La classificació d'estoc que hem fet a la secció anterior és una regla que pot aparèixer en diferents pantalles. La podem convertir en un mètode reutilitzable que retorni el missatge:

CSHARP Programa.cs 
static string ClassificarEstoc(int unitats)
{
    if (unitats == 0)
    {
        return "Esgotat";
    }

    if (unitats <= 2)
    {
        return "Cal reposar aviat";
    }

    return "Estoc correcte";
}

string estat = ClassificarEstoc(1);
Console.WriteLine(estat);

Ara el programa principal no necessita saber com es calcula cada estat. Només ha de cridar ClassificarEstoc. Aquesta separació fa que la regla sigui més fàcil de provar i de modificar.

Variables locals i responsabilitats

Les variables declarades dins d'un mètode són locals: existeixen mentre s'executa aquell mètode. No s'han de confondre amb les variables d'altres mètodes que casualment tinguin el mateix nom.

CSHARP Programa.cs 
static decimal CalcularSubtotal(decimal preu, int unitats)
{
    decimal subtotal = preu * unitats;
    return subtotal;
}

decimal resultat = CalcularSubtotal(10m, 2);

El mètode té una responsabilitat concreta: calcular un subtotal. No hauria de crear controls, demanar dades a l'usuari i escriure fitxers al mateix temps. Aquesta separació serà essencial quan comencem a treballar amb formularis i classes.

Informació

Un mètode no ha de ser llarg per ser útil. Un mètode curt, amb un nom clar i una responsabilitat concreta, és més fàcil de llegir, provar i reutilitzar.

Errors habituals

Important
  • Definir un mètode però oblidar cridar-lo.
  • Passar els arguments en un ordre o amb un tipus incorrecte.
  • Declarar un retorn i no retornar cap valor en alguna branca.
  • Fer que un mètode calculi, modifiqui la interfície i escrigui dades alhora.
  • Posar noms genèrics com FerCoses en lloc d'explicar l'operació.

Pràctica guiada: separar càlculs

Parteix d'un programa que té el preu i les unitats d'un producte. Extreu els càlculs a mètodes independents i fes que el programa mostri el subtotal i una classificació de l'estoc.

  • Fes que el mètode de classificació retorni un string.
  • Prova almenys els estocs 0, 1 i 10.

Els mètodes ens permeten donar estructura al programa. A la secció següent farem el primer pas cap a una aplicació visual: crear el projecte de Windows Forms i entendre què aporta Visual Studio.

4. Crear el primer projecte Windows Forms

Fins ara hem treballat amb programes de consola perquè ens permeten concentrar-nos en la lògica. Ara farem el pas cap a una aplicació gràfica: una finestra amb controls que l'usuari podrà utilitzar.

Windows Forms és un model d'aplicacions basat en finestres, controls i esdeveniments. Visual Studio ens ajuda a crear la finestra i disposa d'un dissenyador visual, però el projecte continua sent un programa C# amb classes i mètodes.

Figura

Preparar l'entorn

Abans de crear el projecte cal tenir Visual Studio instal·lat amb la càrrega de treball de desenvolupament d'escriptori amb .NET. Si aquesta càrrega no està instal·lada, la plantilla de Windows Forms pot no aparèixer o el dissenyador pot no funcionar correctament.

  1. Obre Visual Studio.
  2. Comprova que tens instal·lada la càrrega .NET desktop development.
  3. Assegura't que el SDK de .NET que utilitzen els exemples del mòdul està disponible.
Informació

El projecte ha d'utilitzar el moniker de plataforma .NET indicat en les instruccions de l'activitat. No triïs automàticament l'opció més nova que aparegui a l'assistent: comprova sempre que coincideixi amb l'entorn del mòdul i amb els exemples que hauràs d'obrir.

Escollir la plantilla correcta

A la pantalla de creació d'un projecte, cerca Windows Forms App i comprova que la plantilla és per a C#. Hi ha una diferència important entre dues opcions que poden semblar iguals:

PlantillaDecisióMotiu
Windows Forms AppTriar aquestaÉs la plantilla moderna basada en .NET que fan servir els exemples del mòdul.
Windows Forms App (.NET Framework)No triar-laÉs la plantilla antiga i utilitza un entorn diferent del que treballarem.

Dona al projecte un nom clar, com ProvaFormulari, i desa'l en una carpeta pròpia. Evita crear projectes dins de carpetes amb noms molt llargs o amb caràcters estranys: els camins complicats poden provocar errors del dissenyador.

Important

No confonguis Windows Forms App amb Windows Forms App (.NET Framework). Si tries la plantilla antiga, pots acabar amb un projecte que no coincideixi amb les dependències i els fitxers dels exemples.

Què ha creat Visual Studio?

Quan finalitzes l'assistent, l'Explorador de solucions mostra diversos fitxers. No cal editar-los tots de seguida; primer hem d'entendre la responsabilitat de cadascun.

FitxerResponsabilitatRegla de treball

Form1.cs i Form1.Designer.cs formen una mateixa classe parcial. Visual Studio els separa per poder mantenir el codi que escrivim nosaltres diferenciat del codi que genera l'editor visual.

Executar la primera finestra

Executa el projecte amb el botó d'inici o amb la tecla corresponent de Visual Studio. Hauria d'aparèixer una finestra buida. En aquesta primera prova no cal que facis cap control: l'objectiu és comprovar que l'entorn, el projecte i el framework funcionen.

Quan la finestra s'obri, tanca-la i torna al dissenyador. Encara no hem programat cap esdeveniment; simplement hem verificat el circuit mínim:

  1. crear un projecte;
  2. compilar-lo;
  3. executar-lo;
  4. aturar l'execució i tornar al codi.
Èxit

Si has pogut obrir la finestra buida, ja tens una base funcional sobre la qual afegirem controls. Si el projecte no compila, no continuïs copiant codi: primer resol l'error de l'entorn o de la plantilla.

5. Vista Disseny, vista Codi i esdeveniments

Una aplicació Windows Forms es construeix combinant dues maneres de treballar. A la vista Disseny col·loquem els controls i configurem les seves propietats. A la vista Codi escrivim què ha de fer l'aplicació quan l'usuari hi interactua.

No són dos projectes diferents ni dues versions de la mateixa finestra: són dues vistes de la mateixa classe. El disseny ens ajuda a descriure l'aspecte; el codi ens permet expressar el comportament.

Figura

Què fem a cada vista?

VistaQuè hi femQuè hem d'evitar
DissenyArrosseguem controls, canviem propietats com Name, Text o Size i ordenem la finestra.Posar tota la lògica de l'aplicació en propietats o en noms poc clars.
Codi del formulariEscrivim mètodes, validacions i handlers d'esdeveniments.Modificar a mà el codi generat pel dissenyador sense saber quin efecte tindrà.
PropietatsConfigurem la identitat i l'aspecte de cada control.Confondre el nom intern del control amb el text que veu l'usuari.

Un control té identitat i comportament

Per fer un exemple petit i comprensible, afegirem tres controls al formulari:

  • un TextBox amb Name txtNom perquè l'usuari escrigui el seu nom;
  • un Button amb Name btnSaluda i Text Saluda;
  • un Label amb Name lblResultat per mostrar el resultat.

El valor de Name és el nom que farem servir en C#. El valor de Text és el que es mostra a la interfície. Separar aquestes dues idees evita que el codi depengui d'un text que pot canviar.

Figura

Un esdeveniment inicia una acció

Windows Forms funciona de manera orientada a esdeveniments. El programa queda esperant una acció: un clic, un canvi de text, una finestra que es tanca o una tecla. Quan aquesta acció passa, s'executa el mètode que hi hem associat.

Figura

Per crear l'acció del botó, selecciona btnSaluda en el dissenyador i obre l'esdeveniment Click des de la finestra de propietats. Visual Studio crearà el mètode handler al fitxer del formulari. Escriu-hi només la lògica que necessitem:

CSHARP Form1.cs 
private void btnSaluda_Click(object? sender, EventArgs e)
{
    string nom = txtNom.Text.Trim();

    if (string.IsNullOrWhiteSpace(nom))
    {
        lblResultat.Text = "Escriu el teu nom.";
        return;
    }

    lblResultat.Text = $"Hola, {nom}!";
}

Observa la seqüència: primer llegim la dada del control, després la validem i finalment actualitzem un altre control. El formulari no ha de saber només “pintar”: ha de coordinar una petita operació amb dades i regles clares.

Què fa Visual Studio per nosaltres?

  1. El dissenyador crea i posiciona els controls.
  2. La finestra de propietats permet associar el botó amb l'esdeveniment Click.
  3. El fitxer del formulari conté el mètode que escrivim nosaltres.
  4. Quan l'usuari prem el botó, Windows Forms crida aquest mètode.
