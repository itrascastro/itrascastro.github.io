1. Com funciona una aplicació Windows Forms?

Una aplicació de consola executa instruccions en un ordre fins a acabar. Una aplicació de finestres, en canvi, crea una finestra i espera esdeveniments: clics, tecles, canvis de selecció, tancament, etc. Això s'anomena programació orientada a esdeveniments. No escrivim un while infinit per preguntar si s'ha clicat un botó: Windows Forms gestiona l'espera i ens crida quan passa alguna cosa.

Figura

Encara treballem amb el projecte ProvesCSharp del bloc 1; el bloc 4 en crearà un de nou. El formulari és una classe derivada de Form. Els fitxers Form1.cs i Form1.Designer.cs en defineixen dues parts gràcies a partial. El constructor crida InitializeComponent(), el mètode generat que crea i col·loca els controls. No esborreu aquesta crida.

CSHARP
namespace ProvesCSharp;

public partial class Form1 : Form
{
    public Form1()
    {
        InitializeComponent(); // crea els controls dissenyats visualment
    }
}

2. Dissenyador: controls, noms, textos i propietats

Obriu el dissenyador de Form1. Des de View → Toolbox, arrossegueu controls sobre la finestra. Per cada control, obriu Properties (F4). (Name) és l'identificador que farem servir en C#; Text és el que veu l'usuari. No són intercanviables.

Propietats útils: Text, Enabled, ReadOnly (caixes), Visible, Anchor, Dock, TabIndex, AutoSize i AccessibleName. Ordeneu la navegació amb tabulador: TabIndex 0, 1, 2... segons l'ordre de lectura. Apliqueu Anchor o Dock perquè la taula s'adapti en redimensionar la finestra.

Pràctica: creeu una etiqueta «Nom», un TextBox anomenat txtNom i un Button anomenat btnSaludar amb text «Saluda». No cal escriure codi encara. Executeu l'aplicació i comproveu que podeu escriure al quadre de text.

3. Esdeveniments: com es connecta Click a un mètode?

  1. Al dissenyador, seleccioneu btnSaludar.
  2. A Properties, cliqueu el llamp i busqueu Click. Feu doble clic a la casella buida; Visual Studio crea un mètode de controlador i connecta l'esdeveniment.
  3. Al mètode nou, escriviu les dues instruccions següents.
CSHARP
private void btnSaludar_Click(object sender, EventArgs e)
{
    string nom = txtNom.Text.Trim();
    MessageBox.Show($"Hola, {nom}!");
}

La signatura (object sender, EventArgs e) és la del controlador de l'esdeveniment; sender és el control que el provoca, i e inclou informació de l'esdeveniment (en un clic ordinari no hi ha dades addicionals). No cal invocar manualment btnSaludar_Click: el formulari l'invoca quan toca.

Figura

Eviteu duplicats: no afegiu també btnSaludar.Click += btnSaludar_Click; si ja heu connectat l'esdeveniment des del dissenyador, perquè el controlador es podria executar dues vegades. Si al clicar no passa res, comproveu la casella Click a Properties i el nom real del botó.

4. Validar abans d'utilitzar: Trim i TryParse

El text que una persona escriu no és necessàriament correcte. TextBox.Text sempre retorna text; per obtenir un int o un decimal cal convertir-lo. int.Parse i decimal.Parse fallen amb una excepció si la cadena és invàlida. En un formulari és millor TryParse, que retorna false i permet mostrar una indicació clara.

CSHARP
string nom = txtNom.Text.Trim();
if (string.IsNullOrWhiteSpace(nom))
{
    MessageBox.Show("Introduïu un nom.");
    txtNom.Focus();
    return; // surt només d'aquest mètode
}

if (!decimal.TryParse(txtPreu.Text, out decimal preu) || preu < 0m)
{
    MessageBox.Show("Introduïu un preu vàlid (0 o superior).");
    txtPreu.Focus();
    return;
}

if (!int.TryParse(txtEstoc.Text, out int estoc) || estoc < 0)
{
    MessageBox.Show("Introduïu un estoc enter no negatiu.");
    txtEstoc.Focus();
    return;
}

El prefix ! nega una condició. El símbol || significa «o». out decimal preu crea una variable amb el valor convertit quan l'operació és correcta. return talla el controlador per no continuar afegint dades incorrectes. Aquest fragment pressuposa tres caixes de text amb els noms indicats; no funcionarà si no les heu creat abans.

Figura

Quatre proves imprescindibles: cadena buida, lletres en un nombre, un número negatiu i el valor límit zero. Per als preus amb coma o punt, proveu el separador decimal propi de la configuració regional de Windows; decimal.TryParse segueix la cultura actual.

5. Mostrar, seleccionar i cercar files en un DataGridView

El DataGridView és una vista dels objectes, no el lloc on haurien de viure les dades originals. Quan volem mostrar una llista, l'assignem a DataSource. Quan seleccionem una fila, obtenim l'objecte que representa, si n'hi ha. La llista continua sent responsabilitat del gestor.

CSHARP
// Després de crear els controls al dissenyador:
dgvProductes.AutoGenerateColumns = true;
dgvProductes.ReadOnly = true;
dgvProductes.AllowUserToAddRows = false;
dgvProductes.SelectionMode = DataGridViewSelectionMode.FullRowSelect;
dgvProductes.MultiSelect = false;

// Després de modificar les dades del gestor:
dgvProductes.DataSource = null;
dgvProductes.DataSource = gestor.Llistar();

Aquest fragment és un patró que utilitzarem al bloc 4; no és un programa independent. gestor serà un camp declarat com GestorProductes, i Llistar() retornarà una nova llista de productes.

Quan la fila seleccionada canvia, s'executa SelectionChanged, si l'heu connectat al dissenyador. Llegim el producte amb DataBoundItem, no copiant cèl·lules arbitràriament:

CSHARP
if (dgvProductes.CurrentRow?.DataBoundItem is Producte p)
{
    txtNom.Text = p.Nom;
    txtPreu.Text = p.Preu.ToString();
    txtEstoc.Text = p.Estoc.ToString();
}

El signe ?. evita accedir a una fila nul·la. is Producte p comprova el tipus i crea p només si coincideix. Al bloc 4 també incorporarem una bandera actualitzantTaula per evitar que un canvi automàtic de selecció ompli els camps mentre es refresca la graella.

Figura

Error molt habitual: fer productes = productes.Where(...).ToList() per filtrar i després conservar només aquest resultat. Això perd els productes que no coincideixen. El filtre ha de crear una vista temporal, sense substituir la col·lecció mestra.

6. Executar, depurar i entendre tres tipus d'error

TipusExempleCom es detecta
CompilacióMessageBox.Show("Hola" sense tancar parèntesi.Llista d'errors; no s'arriba a executar.
ExecucióAccedir a CurrentRow sense tenir cap fila.Excepció durant l'execució o depuració.
LògicAplicar un descompte del 15 % quan tocava 10 %.El programa funciona, però els resultats no són correctes.
Figura
  1. Poseu un punt d'interrupció (F9) a la línia que converteix el preu.
  2. Executeu amb F5 i cliqueu el botó que fa la validació; Visual Studio s'aturarà allà.
  3. Passeu el cursor sobre variables i mireu Locals; premeu F10 per avançar una instrucció i F11 per entrar en una crida.
  4. Premeu F5 per continuar, o Shift+F5 per aturar la depuració.

No ignoreu la primera línia rellevant del missatge d'error. Si un programa «no fa res», comproveu primer si l'esdeveniment està connectat, després si arriba al punt d'interrupció, i finalment quines condicions fan sortir amb return.

7. Preparació per al cas pràctic

Construïu un formulari de prova amb txtNom, txtPreu, btnSaludar i un DataGridView. Connecteu el Click, mostreu un missatge amb el valor de la caixa de text i impediu que s'accepti el nom buit. Després mostreu una llista de dos objectes Producte a la taula.

Comproveu-ho sense copiar: sabeu diferenciar (Name) i Text, explicar InitializeComponent, identificar el mètode Click, detectar un error amb F9/F10 i utilitzar TryParse. Amb això ja es pot abordar el projecte complet del bloc 4.
