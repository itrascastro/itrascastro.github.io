1. De quatre variables a una classe: Producte

Tenir codi, nom, preu i estoc en quatre variables soltes funciona amb un sol producte, però amb cent productes és impossible mantenir ordenades totes les dades. Una classe defineix com és un tipus de dada propi. Un objecte és un exemplar concret d'aquella classe. Producte és el motlle; el teclat P001 n'és un objecte.

Figura

A Visual Studio, clic dret al projecte → Add → Class, nom Producte.cs. Poseu-hi exactament:

CSHARP
namespace MiniInventari;

public class Producte
{
    public string Codi { get; set; } = "";
    public string Nom { get; set; } = "";
    public decimal Preu { get; set; }
    public int Estoc { get; set; }

    public decimal ValorEnEstoc()
    {
        return Preu * Estoc;
    }
}

public vol dir que el codi d'altres classes podrà utilitzar aquest membre; class declara la classe; les propietats { get; set; } ofereixen lectura i escriptura. El valor inicial "" evita deixar sense inicialitzar les propietats de text. El namespace agrupa les classes del mateix projecte. El nom MiniInventari ha de coincidir amb el vostre espai de noms (es pot triar aquest nom al bloc 4).

Per crear un objecte i fer servir una propietat, s'utilitza new i el punt .:

CSHARP
Producte primer = new Producte();
primer.Codi = "P001";
primer.Nom = "Teclat";
primer.Preu = 25.50m;
primer.Estoc = 10;

Producte segon = new Producte
{
    Codi = "P002",
    Nom = "Ratolí",
    Preu = 18m,
    Estoc = 5
};

MessageBox.Show($"{primer.Nom}: {primer.ValorEnEstoc():C2}");

Predicció: el missatge indicarà Teclat: 255,00 € en un Windows amb configuració regional catalana; el format de moneda dependrà de la configuració de cada equip. Canvieu primer.Estoc a 2: el segon objecte continua igual.

Error freqüent: Producte p; declara una variable, però no crea un objecte. Fins a executar new Producte() no teniu cap producte inicialitzat que pugueu utilitzar.

2. Una llista de productes: List<Producte>

Una col·lecció guarda molts elements del mateix tipus. List<Producte> guarda productes; Add incorpora un element; Count dona la quantitat; foreach els recorre. Si productes és una variable local, la llista només existeix a l'abast del mètode que la declara. Al gestor del bloc 4 serà un camp de la classe, perquè pugui conservar dades mentre l'aplicació estigui oberta.

CSHARP
List<Producte> productes = new List<Producte>();
productes.Add(new Producte { Codi = "P001", Nom = "Teclat", Preu = 25.50m, Estoc = 10 });
productes.Add(new Producte { Codi = "P002", Nom = "Ratolí", Preu = 18m, Estoc = 5 });

decimal valorTotal = 0m;
foreach (Producte p in productes)
{
    valorTotal += p.ValorEnEstoc();
}
MessageBox.Show($"Productes: {productes.Count}; valor: {valorTotal:C2}");
Figura

En aquesta pràctica el resultat de la suma és 345,00 € (255 + 90). Si obteniu 345, heu connectat correctament classe, objecte, llista, bucle i mètode.

Canvi de nivell: productes[0] és el primer element (els índexs comencen a zero). No accediu a productes[5] si només hi ha dos elements: fallarà en execució. Utilitzeu Count o foreach abans d'accedir per posició.

3. CRUD: crear, consultar, modificar i eliminar

CRUD és l'abreviatura de Create, Read, Update i Delete. No vol dir quatre botons arbitràriament connectats a la finestra: són quatre operacions de negoci que s'han de poder explicar, executar i comprovar. Abans de programar, establiu les regles: el codi de producte és obligatori i únic; el nom no pot ser buit; el preu i l'estoc no poden ser negatius.

Figura
OperacióExempleComprovació
CreateAfegir P003El recompte augmenta i no es duplica el codi.
ReadMostrar productes o cercar ratApareix P002 sense perdre la resta.
UpdateCanviar l'estoc de P001És el mateix producte, no un de nou.
DeleteEliminar P001Desapareix de la llista després de confirmar.

La cerca es pot fer recorrent la llista i comprovant una propietat:

CSHARP
Producte? trobat = productes.Find(
    p => p.Codi.Equals("P002", StringComparison.OrdinalIgnoreCase));

if (trobat is not null)
{
    MessageBox.Show(trobat.Nom);
}

p => ... és una expressió lambda: significa «per a cada producte p, comprova aquesta condició». Producte? indica que la cerca pot no trobar res, de manera que cal comprovar el resultat abans d'utilitzar-lo. OrdinalIgnoreCase compara el codi sense distingir majúscules i minúscules.

Atenció: una col·lecció en memòria no desa les dades en disc. Si tanqueu el programa, desapareixen. Exportar CSV és una operació addicional; el bloc 4 mostra aquesta exportació però no promet cap càrrega automàtica.

4. Dictionary: trobar ràpidament a partir d'una clau

Amb una llista podeu filtrar i conservar l'ordre. Quan cada objecte té una clau única i voleu recuperar-lo per aquesta clau, un diccionari també és útil: Dictionary<string, Producte> relaciona cada codi amb el seu producte. No substitueix automàticament totes les llistes: resol un problema diferent.

CSHARP
Dictionary<string, Producte> perCodi =
    new Dictionary<string, Producte>(StringComparer.OrdinalIgnoreCase);

perCodi.Add("P001", primer);
perCodi.Add("P002", segon);

if (perCodi.TryGetValue("p002", out Producte? producte))
{
    MessageBox.Show(producte.Nom); // Ratolí
}

bool jaExisteix = perCodi.ContainsKey("P001");
perCodi.Remove("P002");
Figura

Regla: Add amb una clau repetida genera un error. Per això sovint és preferible comprovar primer ContainsKey o utilitzar TryAdd. Al nostre exemple complet emprarem una llista amb cerca del codi únic per no introduir dues estructures a la vegada.

5. Separar responsabilitats: objecte, gestor i formulari

Si posem tot el codi a Form1.cs, ben aviat serà difícil de provar, reutilitzar o entendre. Per això repartim la feina. Cada classe respon a una pregunta concreta:

Figura
  • Producte.cs: què és un producte? Propietats i càlcul de valor.
  • GestorProductes.cs: quines operacions es poden fer? Afegir sense duplicats, modificar, eliminar, cercar i comptar.
  • Form1.cs: què ha fet la persona usuària? Llegir caixes de text, mostrar errors, cridar el gestor i actualitzar el llistat.
  • Form1.Designer.cs: com es distribueixen els controls? Ho manté el dissenyador visual.

El flux correcte és clic → validar dades → cridar gestor → actualitzar la vista. Si l'afegit falla per codi repetit, el gestor informa del problema i el formulari el mostra; el gestor no hauria de fer aparèixer un MessageBox, perquè no és responsabilitat seva. Aquesta separació també facilita les proves sense haver d'obrir una finestra.

6. Exercici de transició: canvia les regles sense tocar la finestra

Sobre el codi de les seccions anteriors, afegiu dos productes i calculeu el valor total. Després creeu a Producte el mètode següent i invoqueu-lo des del botó de prova:

CSHARP
public bool CalReposar()
{
    return Estoc < 5;
}

Comproveu tres casos: estoc 0 (cert), 4 (cert) i 5 (fals). Per què CalReposar és un bon nom? Perquè expressa la intenció, no un detall visual. Si aquesta regla canvia a «menys de 10», només modificareu un lloc.

Abans del bloc 3: heu de poder explicar de memòria la diferència entre Producte i new Producte(), identificar List<Producte>, utilitzar foreach i descriure què fa cada classe de l'arquitectura. No cal memoritzar cada instrucció, però sí saber on trobar-la i per què existeix.
