1. Tipus de manuals

Tipus de manualDestinatari i objectiu
Manual d'usuariUsuari final: com utilitzar les funcions de l'aplicació pas a pas.
Guia de referènciaUsuari que ja coneix l'aplicació i necessita consultar un detall concret ràpidament.
Guia ràpidaResum molt breu de les tasques més habituals, per a un primer contacte.
Manual d'instal·lacióCom instal·lar l'aplicació i els seus requisits previs.
Manual de configuracióCom ajustar paràmetres i opcions un cop instal·lada.
Manual d'administracióTasques de manteniment, còpies de seguretat, gestió d'usuaris, per a perfils tècnics.

Més enllà dels manuals estàtics, també existeixen sistemes d'ajuda sensible al context i tutorials guiats pas a pas.

2. Escriure i generar un manual DocBook

DocBook és un format de marcatge basat en XML pensat específicament per escriure documentació tècnica de manera estructurada, independent de com es presenti finalment.

XML 
<book xmlns="http://docbook.org/ns/docbook" xmlns:xlink="http://www.w3.org/1999/xlink" version="5.1">
  <info><title>Manual d'usuari de BibliotecaInformes</title></info>
  <chapter xml:id="introduccio">
    <title>Introducció</title>
    <para>...</para>
    <section xml:id="objectiu">
      <title>Objectiu de l'aplicació</title>
      <para>...</para>
    </section>
  </chapter>
  <index/>
</book>
ElementÚs
<book>Element arrel de tot el document.
<chapter> / <section>Divisió jeràrquica del contingut.
<figure> amb <imagedata>Incrustar una imatge amb el seu peu de figura.
<table>Taules de dades dins del text.
<itemizedlist> / <orderedlist>Llistes sense ordre o numerades.
<xref linkend="...">Referència creuada cap a un altre punt del document (ha d'apuntar a un xml:id que existeixi).
<footnote>Nota a peu de pàgina.
<note>, <warning>, <caution>Avisos destacats de diferent gravetat.
<indexterm> i <index/>Marcar termes per a l'índex alfabètic final i generar-lo.

2.1. Instal·lar les eines necessàries

Per transformar un document DocBook (XML) en HTML o PDF calen dues coses: un processador XSLT que apliqui un full d'estil, i el full d'estil mateix.

SistemaOpció
Linux (Ubuntu/Debian) o WSLsudo apt install xsltproc docbook-xsl.
macOS (amb Homebrew)brew install libxslt docbook-xsl.
Windows, sense WSLxsltproc no sempre és fàcil d'instal·lar. L'alternativa que fem servir en aquesta unitat: Python amb el paquet lxml (inclou libxslt).
BASH 
pip install lxml

Amb lxml, la transformació es fa amb un petit script en lloc d'una comanda de terminal:

PYTHON 
from lxml import etree

xml = etree.parse('manual_bibliotecainformes.xml')
xslt_doc = etree.parse('docbook_html_minim.xsl')
transform = etree.XSLT(xslt_doc)
result = transform(xml)

with open('manual_bibliotecainformes.html', 'wb') as f:
    f.write(etree.tostring(result, pretty_print=True, encoding='utf-8'))

El full d'estil docbook_html_minim.xsl és propi (no l'oficial de DocBook, que és molt més gran): defineix, amb plantilles XSLT senzilles, com convertir cada element de DocBook (chapter, section, xref, table, footnote...) en el seu equivalent HTML.

Informació

Concepte clau: com resol xref el seu text

Un full d'estil XSLT pot definir una clau (xsl:key) que indexa tots els capítols i seccions pel seu xml:id. Quan es processa un <xref linkend="generar-informe"/>, el full d'estil busca a la clau l'element amb aquest identificador i n'agafa el <title> per generar automàticament un enllaç com «Com generar l'informe». Així, si mai es canvia el títol d'una secció, tots els xref que hi apunten s'actualitzen sols la propera vegada que es transforma el document.

Un cop generat l'HTML, per obtenir el PDF sense necessitat d'un processador XSL-FO dedicat, LibreOffice el pot obrir i exportar directament:

BASH 
soffice --headless --convert-to pdf manual_bibliotecainformes.html

El requisit clau que sol demanar-se és que totes dues sortides (HTML i PDF) provinguin del mateix XML, no que s'utilitzi un mètode concret per al pas final.

2.2. El manual de BibliotecaInformes

El manual complet té 4 capítols i 8 seccions, amb 3 figures, 1 taula, 2 llistes, 3 referències creuades, 3 notes a peu de pàgina, 2 avisos i 5 termes d'índex: molt per sobre dels mínims estructurals que se solen demanar, i tot generat des d'un únic fitxer XML.

Èxit

Per què DocBook i no un processador de textos normal

En separar el contingut (XML) de la presentació (full d'estil), es pot generar automàticament més d'una sortida (HTML, PDF...) a partir de la mateixa font, i es pot validar l'estructura del document de manera automàtica, per exemple comprovant amb un script que hi ha com a mínim 4 capítols abans de donar per bo el lliurament.

3. Errors habituals

ErrorPer què passa i com evitar-lo
Justificar puntuacions d'usabilitat de manera genèricaUna avaluació d'usabilitat ha d'anar acompanyada d'observacions concretes sobre la interfície analitzada, no valoracions vagues del tipus "és intuïtiu".
Redissenyar un missatge d'error sense oferir accionsReescriure el text amb un to més amable no és suficient: cal oferir com a mínim una acció concreta que l'usuari pugui prendre.
Generar un informe amb totals que no corresponen a les dadesEls valors calculats s'han de verificar contra el joc de dades real utilitzat, no donar-se per fets.
Confondre "informe generat amb una eina" amb "informe generat amb codi"Utilitzar únicament un assistent visual sense escriure ni modificar cap línia de codi no cobreix els criteris relacionats amb la generació de codi d'informes.
Referències creuades (xref) que apunten a un xml:id inexistentProvoca que el document no sigui vàlid o que la referència no funcioni en generar l'HTML/PDF.
Redactar l'HTML o el PDF del manual a part, sense generar-los des del XMLTrenca l'objectiu de DocBook (una sola font per a diverses sortides) i sol ser fàcilment detectable en revisar-ho.
Connectar el botó que genera l'informe a mà al constructorIgual que a la Unitat 1: si algú fa doble clic sobre el botó al dissenyador pensant que li falta l'esdeveniment, es crea un gestor duplicat. Cal deixar que el dissenyador escrigui la connexió a InitializeComponent().
