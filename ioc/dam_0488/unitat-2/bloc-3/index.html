1. Model de dades relacional

Abans de dissenyar un informe cal tenir clar d'on surten les dades. Un model de dades relacional descriu les entitats, els seus camps i com es relacionen entre elles:

Element del modelDescripció
EntitatUn concepte del domini que es vol representar (per exemple, "Llibre", "Préstec").
CampUna dada concreta d'una entitat, amb un tipus (text, número, data...) i si és obligatori o no.
Clau primàriaEl o els camps que identifiquen de manera única cada fila d'una entitat.
Clau foranaUn camp que apunta a la clau primària d'una altra entitat, per representar una relació.
CardinalitatQuantes files d'una entitat es poden relacionar amb quantes de l'altra: 1 -- N (un a molts), N -- M (molts a molts), etc.

El model de BibliotecaInformes té quatre entitats: Llibres, Socis, Prestecs i Incidencies, totes dues últimes relacionades amb Llibres i Socis per clau forana:

Figura

El diagrama mostra les relacions, però el model complet també s'ha de documentar camp a camp, amb el tipus, si és obligatori i quina és la clau. Per exemple, l'entitat Prestecs:

CampTipusObligatoriClauDescripció
IdPrestecstringSíPrimàriaIdentificador únic del préstec.
IdLlibrestringSíForana → LlibresLlibre prestat.
IdSocistringSíForana → SocisSoci que fa el préstec.
DataPrestecdateSí(cap)Data en què s'ha fet el préstec.
DataRetorndateNo(cap)Data de retorn; buida mentre el llibre no s'ha tornat.
DiesintSí(cap)Durada del préstec, ja calculada.

Les relacions amb la seva cardinalitat: Llibres 1 -- N Prestecs, Socis 1 -- N Prestecs, Llibres 1 -- N Incidencies.

Decisions de disseny d'aquest model, justificades:

  1. Per què Incidencies és una entitat pròpia i no un camp de text dins de Llibres: un llibre pot tenir diverses incidències al llarg del temps, i barrejar-les totes en un sol camp de text faria impossible comptar-les o filtrar-les per separat.
  2. Per què Categoria és un camp de text dins de Llibres i no una entitat pròpia: amb només quatre valors fixos (Novel·la, Assaig, Infantil, Còmic) que no canvien sovint, crear-hi una taula a part només afegiria una relació més sense cap benefici real per a aquest volum de dades.
  3. Per què DataRetorn pot quedar buida: mentre el préstec és actiu encara no hi ha data de retorn; obligar a omplir-la forçaria a inventar una data falsa, que després distorsionaria qualsevol càlcul sobre préstecs actius.

2. Informes: incrustats i no incrustats

TipusCaracterístiques
Informe incrustatEs genera i es visualitza dins de la mateixa aplicació (per exemple, en un control de visualització d'informes integrat al formulari).
Informe no incrustatEs genera des de l'aplicació però s'exporta o s'obre com a document independent (normalment PDF), fora de la interfície principal.

Cap dels dos és "millor" en abstracte: la tria depèn de si l'usuari necessita consultar l'informe sense sortir del flux de treball (incrustat) o si el necessita per imprimir, arxivar o compartir (no incrustat). BibliotecaInformes genera un informe no incrustat: un PDF independent que s'obre amb el lector de PDF del sistema.

3. Estructura general d'un informe

La majoria d'eines i biblioteques d'informes, amb independència de la tecnologia concreta, organitzen el contingut en les mateixes seccions clàssiques. Així és com es reparteixen a l'informe de préstecs:

SeccióEs repeteixA BibliotecaInformes
Capçalera de l'informeUn cop, a l'iniciTítol, alumne, data de generació i filtres.
Capçalera de pàginaA cada pàgina"Biblioteca Municipal" i número de pàgina.
Capçalera de grupA l'inici de cada grupCategoria del llibre i exemplars totals.
DetallPer cada fila de dadesUna línia per préstec, numerada dins de cada setmana.
Peu de grupAl final de cada grupPréstecs, dies totals, percentatge d'ús i incidències de la categoria.
Peu de pàginaA cada pàginaData i hora d'impressió.
Peu de l'informeUn cop, al finalTotals generals i gràfic d'incidències per categoria.

4. Filtres, agrupacions, valors calculats i gràfics

  • Filtres: restringeixen quines dades apareixen a l'informe (per exemple, un rang de dates). Un bon informe documenta explícitament quins filtres s'han aplicat.
  • Agrupacions: organitzen les files de detall segons un o més criteris. A BibliotecaInformes, primer per categoria i, dins de cada categoria, per setmana.
  • Valors calculats: recomptes, sumes, mitjanes i percentatges, calculats per grup i en el total general.
  • Gràfics: generats a partir de les dades reals de l'informe (no dibuixats a mà).
Informació

Concepte clau: GroupBy de LINQ

Agrupar files "primer per categoria i, dins de cada categoria, per setmana" és exactament el que fa GroupBy de LINQ: prestecs.GroupBy(p => p.Categoria) retorna una col·lecció de grups, un per cada valor diferent de Categoria, i cada grup és alhora una col·lecció amb totes les files que hi pertanyen (grup.Key és el valor de la categoria, i es pot recórrer amb un segon foreach o un segon GroupBy per la setmana). És la manera estàndard en C# de convertir una llista plana en una estructura agrupada, sense haver d'escriure bucles manuals amb diccionaris.

5. Generar l'informe amb QuestPDF

Al llarg dels anys, l'ecosistema .NET ha tingut diverses eines per generar informes; és important conèixer el panorama actual, ja que algunes eines clàssiques ja no són viables amb les versions modernes de .NET:

EinaEstat actual
RDLC / ReportViewer (Microsoft.Reporting.WinForms)Clàssica en projectes de .NET Framework, però no funciona amb .NET modern (.NET 5 i posteriors, inclòs .NET 8): falla en temps d'execució per dependències internes que ja no existeixen en aquestes versions.
Crystal ReportsMolt utilitzada històricament, però amb un suport limitat i llicències complexes en projectes moderns .NET.
Biblioteques de generació de PDF per codi (per exemple, QuestPDF)Alternativa moderna i totalment compatible amb .NET actual: l'informe es defineix amb codi (una API fluida en C#) en lloc d'un assistent visual.
Eines externes a l'IDE (per exemple, Jaspersoft Studio)Permeten dissenyar informes visualment i, en molts casos, ampliar-ne el comportament amb codi (scriptlets).
Important

Per tenir en compte

El fet que una eina generi informes "bàsics a partir d'assistents" no substitueix la necessitat de saber generar i modificar el codi corresponent a l'informe: un informe fet només amb un editor visual, sense cap línia de codi pròpia, no és suficient.

5.2. El model de dades combinat: PrestecRow

Igual que a la Unitat 1, primer cal una classe que combini les dades de diverses entitats en una sola fila, llesta per mostrar:

CSHARP 
public class PrestecRow
{
    public string IdLlibre { get; set; } = string.Empty;
    public string Titol { get; set; } = string.Empty;
    public string Categoria { get; set; } = string.Empty;
    public int Exemplars { get; set; }
    public int Setmana { get; set; }
    public string IdPrestec { get; set; } = string.Empty;
    public string Soci { get; set; } = string.Empty;
    public string DataPrestec { get; set; } = string.Empty;
    public string DataRetorn { get; set; } = string.Empty;
    public int Dies { get; set; }
}

El DataLoader llegeix els quatre CSV i "aplana" les dades combinant-les (quin llibre, quin soci, quina categoria correspon a cada préstec):

CSHARP 
foreach (var f in prestecsCsv)
{
    var idLlibre = f[1];
    var llibre = llibres[idLlibre];
    var dataPrestec = DateTime.ParseExact(f[3], "yyyy-MM-dd", CultureInfo.InvariantCulture);

    prestecs.Add(new PrestecRow
    {
        IdLlibre = idLlibre,
        Titol = llibre.Titol,
        Categoria = llibre.Categoria,
        Exemplars = llibre.Exemplars,
        Setmana = NumSetmana(dataPrestec),
        IdPrestec = f[0],
        Soci = socis.TryGetValue(f[2], out var nom) ? nom : f[2],
        DataPrestec = dataPrestec.ToString("dd/MM/yyyy"),
        DataRetorn = f[4],
        Dies = int.Parse(f[5]),
    });
}

5.3. Definir el document amb IDocument

CSHARP 
using QuestPDF.Fluent;
using QuestPDF.Helpers;
using QuestPDF.Infrastructure;

public class InformeBuilder : IDocument
{
    private readonly InformeDades dades;
    private readonly string nomAlumne;

    public InformeBuilder(InformeDades dades, string nomAlumne)
    {
        this.dades = dades;
        this.nomAlumne = nomAlumne;
    }

    public DocumentMetadata GetMetadata() => DocumentMetadata.Default;

    public void Compose(IDocumentContainer container)
    {
        container.Page(page =>
        {
            page.Size(PageSizes.A4);
            page.Margin(30);

            page.Header().Row(row =>
            {
                row.RelativeItem().Text("Biblioteca Municipal").Bold();
                row.RelativeItem().AlignRight().Text(text =>
                {
                    text.Span("Pàgina "); text.CurrentPageNumber();
                    text.Span(" de "); text.TotalPages();
                });
            });

            page.Footer().AlignRight().Text($"Imprès el {DateTime.Now:dd/MM/yyyy HH:mm}");

            page.Content().Column(column =>
            {
                column.Item().Element(ComposeCapcaleraInforme);

                foreach (var grup in dades.Prestecs.GroupBy(p => p.Categoria).OrderBy(g => g.Key))
                {
                    column.Item().Element(c => ComposeGrupCategoria(c, grup.Key, grup.ToList()));
                }

                column.Item().PaddingTop(15).Element(ComposePeuInforme);
            });
        });
    }
    // ComposeCapcaleraInforme, ComposeGrupCategoria i ComposePeuInforme
    // segueixen exactament el mateix patró vist a la Unitat 1.
}
Informació

Concepte clau: per què IDocument

IDocument és una interfície: un contracte que diu "qualsevol classe que la implementi ha de saber donar les seves metadades (GetMetadata) i com es compon (Compose)". QuestPDF no necessita conèixer InformeBuilder per endavant: només necessita rebre qualsevol objecte que compleixi el contracte IDocument per poder-lo convertir en PDF amb document.GeneratePdf(...). Aquest patró (programar contra una interfície, no contra una classe concreta) és el que permet que la mateixa biblioteca serveixi per a informes completament diferents entre si.

5.4. El gràfic: SVG amb CultureInfo.InvariantCulture

Per als gràfics, la manera recomanada actualment és generar una cadena de text en format SVG (l'antiga API .Canvas() de QuestPDF ha quedat obsoleta) i incrustar-la amb .Svg(cadenaSvg):

TEXT 
static string F(float valor) => valor.ToString("0.0", CultureInfo.InvariantCulture);

svg.Append($"<rect x=\"{F(x)}\" y=\"{F(yTop)}\" width=\"{F(amplaBarra)}\" height=\"{F(alcadaBarra)}\" fill=\"#154e9c\"/>");
Problema

Parany habitual: els decimals dins del SVG

Si es construeix la cadena SVG combinant text amb números, cal formatar-los amb punt decimal, no amb la coma que un sistema en català o castellà fa servir per defecte. Un valor escrit amb coma dins d'un atribut XML/SVG (x="44,7") el trenca i el contingut no es renderitza correctament.

5.5. Connectar-ho a un botó real

Al formulari, el botó es connecta des del dissenyador (vegeu Unitat 1, apartat 6, sobre per què no s'ha de fer a mà al constructor):

CSHARP 
// A Form1.Designer.cs, dins d'InitializeComponent():
this.btnGeneraInforme.Click += new System.EventHandler(this.BtnGeneraInforme_Click);

// A Form1.cs:
private void BtnGeneraInforme_Click(object? sender, EventArgs e)
{
    var dades = DataLoader.Carrega(Path.Combine(AppContext.BaseDirectory, "dades"));
    var document = new InformeBuilder(dades, "NOM_ALUMNE");

    var rutaSortida = Path.Combine(AppContext.BaseDirectory, "informe_prestecs.pdf");
    document.GeneratePdf(rutaSortida);

    lblEstat.Text = $"Estat: informe generat a {rutaSortida}";
}
