1. El projecte d'exemple d'aquesta unitat

Tota aquesta unitat es construeix al voltant d'un únic projecte d'exemple, pas a pas: una petita aplicació de gestió d'estoc d'una botiga, GestorEstocBotiga. No és el mateix exercici que es demanarà a l'activitat avaluable, però treballa exactament les mateixes tècniques: un formulari principal dissenyat amb l'editor visual, un component visual reutilitzable propi, persistència en fitxer, proves unitàries i documentació de codi.

Informació

Què construirem

Un formulari amb un llistat de productes i un panell de detall, i un component propi anomenat IndicadorEstoc que mostra l'estoc d'un producte com a percentatge, amb un color diferent segons si l'estoc és disponible, baix o esgotat.

Es recomana seguir els passos escrivint el codi vosaltres mateixos dins de Visual Studio, en lloc de copiar-lo directament: és la millor manera d'interioritzar l'ús de l'editor visual abans d'enfrontar-vos a un exercici propi.

2. Preparar l'entorn de treball

Abans de crear cap projecte cal tenir instal·lat:

  • Visual Studio Community (versió 2022 o superior), amb la càrrega de treball .NET desktop development activada.
  • El .NET SDK 8 (normalment s'instal·la automàticament amb aquesta càrrega de treball).
  1. Descarregar l'instal·lador de Visual Studio Community des del lloc oficial de Microsoft.
  2. Durant la instal·lació, a la pantalla de càrregues de treball, marcar ".NET desktop development" (Desenvolupament d'escriptori amb .NET).
  3. Confirmar i esperar que finalitzi la instal·lació.
  4. Un cop instal·lat, comprovar la versió del SDK obrint una terminal i executant dotnet --version: hauria de mostrar una versió 8.x (o superior, si es vol utilitzar una versió més nova cal ajustar-ho al .csproj de cada projecte).

Important

Problema habitual: el dissenyador de formularis no s'obre

Just després d'instal·lar o actualitzar Visual Studio, és relativament freqüent que en fer doble clic sobre un formulari (Form1.cs) el dissenyador visual es quedi en blanc, no respongui, o no passi res en absolut, encara que el projecte compili sense errors (Ctrl+Shift+B correcte). Sol ser un problema de la memòria cau de components de Visual Studio, que ha quedat en un estat inconsistent. La solució, en aquest ordre:

  1. Tancar Visual Studio completament (totes les finestres).
  2. Obrir l'Explorador de fitxers i anar a %LocalAppData%\Microsoft\VisualStudio\; hi haurà una carpeta amb un nom com 18.0_xxxxxxxx (la part numèrica canvia segons la instal·lació).
  3. Dins d'aquesta carpeta, esborrar (si existeixen) les subcarpetes ComponentModelCache, WinFormsDesigner i MEFCacheBackup. Són només memòria cau: Visual Studio les torna a generar soles.
  4. Tornar a obrir Visual Studio i el projecte. La primera vegada trigarà una mica més del normal a preparar el dissenyador (fins a un minut): cal esperar sense tancar-ho.

3. Crear el projecte des de zero

  1. A Visual Studio, Crea un projecte nou.
  2. Es cerca i tria la plantilla Windows Forms App (en C#). Cal parar atenció: no s'ha de triar "Windows Forms App (.NET Framework)", que és la plantilla antiga.
  3. Es dona nom al projecte (per exemple, GestorEstocBotiga) i es tria la carpeta on desar-lo.
  4. A la pantalla de "Informació addicional", es tria el framework .NET 8.0 (Long Term Support).
  5. Es crea el projecte i Visual Studio obre automàticament Form1 en mode disseny.

Informació

Concepte clau: classes parcials (partial)

Si obriu Form1.cs, la classe es declara com public partial class Form1 : Form. La paraula clau partial permet dividir la definició d'una mateixa classe en diversos fitxers: en compilar, el compilador els torna a ajuntar com si fossin un de sol. És exactament el mecanisme que fa possible separar Form1.cs (el codi que escriviu vosaltres) de Form1.Designer.cs (el codi que genera l'editor visual): totes dues meitats formen la mateixa classe Form1, però cadascuna es pot editar (o regenerar) de manera independent sense que l'altra es vegi afectada.

Val la pena obrir el .csproj del projecte (doble clic sobre el seu node a l'Explorador de solucions) i comprovar que conté:

XML 
<TargetFramework>net8.0-windows</TargetFramework>
<UseWindowsForms>true</UseWindowsForms>
