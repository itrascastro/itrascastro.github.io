1. Persistència de dades

Quan un component o formulari ha de recordar dades entre execucions sense necessitat d'una base de dades, una solució senzilla i molt habitual en exercicis d'aquest nivell és desar-les en un fitxer de text pla, encapsulant l'accés en una classe de tipus repositori. Al nostre projecte, primer cal la classe de dades:

CSHARP 
public class Producte
{
    public string Nom { get; set; } = string.Empty;
    public int CapacitatMaxima { get; set; }
    public int Estoc { get; set; }
    public string Proveidor { get; set; } = string.Empty;
}

I el repositori, amb el fitxer productes.txt com a format Nom|CapacitatMaxima|Estoc|Proveidor:

CSHARP 
public class ProducteRepository
{
    public List<Producte> Carrega(string ruta)
    {
        if (!File.Exists(ruta)) return new List<Producte>();

        var resultat = new List<Producte>();
        foreach (var linia in File.ReadAllLines(ruta, Encoding.UTF8))
        {
            if (string.IsNullOrWhiteSpace(linia)) continue;

            var camps = linia.Split('|');
            if (camps.Length != 4) continue;
            if (!int.TryParse(camps[1], out int capacitat)) continue;
            if (!int.TryParse(camps[2], out int estoc)) continue;

            resultat.Add(new Producte
            {
                Nom = camps[0],
                CapacitatMaxima = capacitat,
                Estoc = estoc,
                Proveidor = camps[3]
            });
        }
        return resultat;
    }

    public void Desa(string ruta, IEnumerable<Producte> productes)
    {
        var linies = productes.Select(p => $"{p.Nom}|{p.CapacitatMaxima}|{p.Estoc}|{p.Proveidor}");
        File.WriteAllLines(ruta, linies, Encoding.UTF8);
    }
}

Els punts clau d'un repositori robust: no llançar excepció si el fitxer no existeix (retornar una llista buida), ignorar línies buides o malformades en lloc de fallar, i escriure sempre amb una codificació explícita (normalment UTF-8) per evitar problemes amb accents. Fixeu-vos que Carrega també ignora una línia si algun dels camps numèrics no es pot convertir (int.TryParse retorna false), en lloc de deixar que l'excepció aturi tota la càrrega.

2. Proves unitàries del component

Una prova unitària comprova, de manera aïllada i automàtica, que una peça petita de codi (normalment un mètode) es comporta com s'espera. A .NET, els frameworks més habituals són xUnit, MSTest i NUnit; xUnit és el més utilitzat en projectes moderns. Les proves d'IndicadorEstoc:

CSHARP 
public class IndicadorEstocTests
{
    [Fact]
    public void PercentatgeNegatiu_EsRetallaAZero()
    {
        var indicador = new IndicadorEstoc();
        indicador.PercentatgeEstoc = -15;
        Assert.Equal(0, indicador.PercentatgeEstoc);
    }

    [Fact]
    public void PercentatgeSuperiorA100_EsRetallaA100()
    {
        var indicador = new IndicadorEstoc();
        indicador.PercentatgeEstoc = 150;
        Assert.Equal(100, indicador.PercentatgeEstoc);
    }

    [Theory]
    [InlineData(0, "Esgotat")]
    [InlineData(19, "Esgotat")]
    [InlineData(20, "Estoc baix")]
    [InlineData(49, "Estoc baix")]
    [InlineData(50, "Disponible")]
    [InlineData(100, "Disponible")]
    public void EstatEstoc_CorresponAlPercentatge(int percentatge, string estatEsperat)
    {
        var indicador = new IndicadorEstoc { PercentatgeEstoc = percentatge };
        Assert.Equal(estatEsperat, indicador.EstatEstoc);
    }

    [Fact]
    public void Reaprovisiona_DeixaElPercentatgeAlCent()
    {
        var indicador = new IndicadorEstoc();
        indicador.PercentatgeEstoc = 10;
        indicador.Reaprovisiona();
        Assert.Equal(100, indicador.PercentatgeEstoc);
    }

    [Fact]
    public void EstocBaix_NomesEsLlancaUnCopEnCanviarDEstat()
    {
        var indicador = new IndicadorEstoc();
        int vegadesLlancat = 0;
        indicador.EstocBaix += (s, e) => vegadesLlancat++;

        indicador.PercentatgeEstoc = 30; // entra a "Estoc baix": es dispara
        indicador.PercentatgeEstoc = 35; // continua a "Estoc baix": NO s'ha de tornar a disparar
        indicador.PercentatgeEstoc = 40; // continua a "Estoc baix": tampoc

        Assert.Equal(1, vegadesLlancat);
    }
}

Un detall important: es pot instanciar i testejar un UserControl sense mostrar-lo mai en pantalla ni obrir cap finestra. Les proves creen l'objecte, li assignen valors i comproven el resultat de les seves propietats, mètodes i esdeveniments, igual que amb qualsevol altra classe.

2.1. Crear el projecte de proves des de zero

Els passos per afegir un projecte de proves xUnit a una solució que ja té el projecte principal de Windows Forms:

  1. A l'Explorador de solucions, clic dret sobre la solució → Afegeix → Nou projecte.
  2. Es tria la plantilla xUnit Test Project (a vegades apareix com "xUnit Test Project (.NET)") i se li dona un nom, per exemple el mateix nom del projecte principal amb el sufix .Tests.
  3. Un cop creat, clic dret sobre el nou projecte de proves → Afegeix → Referència de projecte... i es marca el projecte principal.
  4. S'obre el .csproj del projecte de proves (doble clic sobre el seu node a l'Explorador de solucions) i s'hi afegeixen, si no hi són, aquestes línies dins del primer <PropertyGroup>:
XML 
<TargetFramework>net8.0-windows</TargetFramework>
<UseWindowsForms>true</UseWindowsForms>

Això és necessari perquè el projecte de proves pugui instanciar classes que depenen de Windows Forms (com un UserControl), encara que les proves no mostrin cap finestra en pantalla.

Amb l'ordre dotnet (des d'un terminal, a la carpeta de la solució), els mateixos passos equivalen a:

BASH 
dotnet new xunit -n NomDelProjecte.Tests
dotnet add NomDelProjecte.Tests/NomDelProjecte.Tests.csproj reference NomDelProjecte/NomDelProjecte.csproj
dotnet sln add NomDelProjecte.Tests/NomDelProjecte.Tests.csproj

Per executar totes les proves i veure el resultat: des de Visual Studio, Prova → Executa totes les proves (o l'Explorador de proves, Test Explorer); des de terminal, dotnet test.

3. Documentar el codi

.NET permet generar documentació estructurada directament a partir de comentaris especials anomenats comentaris de documentació XML, que comencen per ///. Al nostre component:

CSHARP 
/// <summary>
/// Component visual reutilitzable que mostra l'estoc d'un producte com a percentatge,
/// amb un indicador de color segons l'estat.
/// </summary>
public partial class IndicadorEstoc : UserControl
{
    /// <summary>
    /// Percentatge d'estoc actual, sempre entre 0 i 100. Els valors fora de rang
    /// es retallen automàticament (no es llança cap excepció).
    /// </summary>
    public int PercentatgeEstoc { get; set; }

    /// <summary>Reaprovisiona el producte: posa l'estoc al 100% i actualitza la interfície.</summary>
    public void Reaprovisiona() { /* ... */ }
}

Per activar la generació del fitxer de documentació (un .xml amb tot aquest contingut estructurat, que eines com IntelliSense poden llegir), cal afegir al .csproj:

XML 
<PropertyGroup>
    <GenerateDocumentationFile>true</GenerateDocumentationFile>
</PropertyGroup>

Un cop activat, IntelliSense mostra aquest text en passar el ratolí per sobre del nom de la propietat o del mètode, des de qualsevol altre punt del codi o des d'un altre projecte que faci servir el component.

4. Revisió final de l'aplicació

Amb tots els passos anteriors completats, l'aplicació final permet: triar un producte de la llista, veure el seu estoc representat pel color i la barra d'IndicadorEstoc, ajustar l'estoc amb el NumericUpDown, reaprovisionar-lo amb un clic, i desar els canvis a productes.txt.

5. Errors habituals

ErrorPer què passa i com evitar-lo
Editar el .Designer.cs a màEl dissenyador el pot sobreescriure. Els canvis d'estructura visual s'han de fer sempre des del dissenyador.
Triar la plantilla "Windows Forms App (.NET Framework)"És la plantilla antiga. Cal triar "Windows Forms App" (sense ".NET Framework") i el framework .NET 8.0 al pas següent de l'assistent.
Llançar una excepció per un valor de propietat fora de rangTrenca l'ús normal del component des del dissenyador o des d'un altre formulari. És preferible retallar (clamp) el valor.
Llançar un esdeveniment en cada canvi de valorGenera soroll d'esdeveniments innecessari. Cal comparar l'estat anterior i el nou, i disparar l'esdeveniment només quan l'estat canvia realment.
Crear un "component" que és només un grup de controls dins del formulariNo és reutilitzable ni es pot arrossegar des del quadre d'eines a un altre formulari. Ha de ser un UserControl independent.
No tractar el cas de fitxer inexistent en carregar dadesProvoca que l'aplicació falli en la primera execució, quan encara no existeix el fitxer de dades.
El component de proves no compilaSol faltar afegir <UseWindowsForms>true</UseWindowsForms> i el TargetFramework correcte al .csproj del projecte de proves, o la referència cap al projecte principal.
