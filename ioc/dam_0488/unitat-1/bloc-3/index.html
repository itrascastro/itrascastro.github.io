1. Crear un component visual reutilitzable

Un component visual és una unitat d'interfície reutilitzable que encapsula la seva pròpia estructura visual, propietats i comportament, de manera que es pot arrossegar des del quadre d'eines com si fos un control estàndard més. Windows Forms distingeix principalment dos tipus:

TipusCaracterístiques
User Control (UserControl)Es construeix combinant altres controls existents dins d'un contenidor propi. És la via més habitual i senzilla per crear components a mida.
Custom Control (Control)Es dibuixa des de zero sobre l'esdeveniment Paint, sense combinar controls existents. Dona més control sobre l'aspecte final però requereix més feina (gestionar el redibuixat, l'accessibilitat, etc.).

Per a la majoria de casos pràctics d'aquest mòdul, un User Control és suficient i preferible: aprofita controls ja fets i testejats, i és molt més ràpid de desenvolupar. Construirem IndicadorEstoc com a User Control.

  1. Al projecte, clic dret → Afegeix → Nou element → User Control (Windows Forms), i se li dona el nom IndicadorEstoc.
  2. Visual Studio genera els mateixos dos fitxers que un formulari: IndicadorEstoc.cs i IndicadorEstoc.Designer.cs, més una superfície de disseny en blanc. Són, de nou, dues meitats de la mateixa classe partial (vegeu l'apartat 3): una per al vostre codi, l'altra per al que genera el dissenyador.
  3. Es dissenya l'interior del component arrossegant-hi controls, igual que en un formulari normal: un Panel petit (farà de pastilla de color), un ProgressBar i un Label per al percentatge.
Figura
  1. Es compila el projecte: el nou component apareix automàticament a la part superior del quadre d'eines i es pot arrossegar a qualsevol formulari del mateix projecte, exactament com un control estàndard.

Èxit

Comprovació ràpida

Si el component no apareix al quadre d'eines després de compilar, sol ser senyal que el projecte no ha compilat sense errors, o que el component no hereta correctament de UserControl.

Un cop apareix al quadre d'eines, s'arrossega una instància (indicadorEstoc1) dins de l'espai reservat al TableLayoutPanel del formulari principal (apartat 4).

2. Propietats, atributs i el Property Grid

Informació

Concepte clau: encapsulació

Fixeu-vos que PercentatgeEstoc no és un simple camp públic: per darrere hi ha un camp privat (private int percentatgeEstoc;, declarat a l'inici de la classe) i la propietat pública n'és l'única porta d'accés, amb un get que el retorna i un set que en controla els valors abans d'assignar-lo. Aquest patró és l'encapsulació: amagar l'estat intern d'un objecte i exposar-lo només a través de mètodes o propietats que en garanteixen la validesa. Si percentatgeEstoc fos un camp públic, qualsevol codi extern podria assignar-hi, per exemple, -30 directament, sense passar mai pel retall de rang; en ser privat, l'única manera d'assignar-lo és a través de la propietat, que sempre aplica la regla.

Perquè una propietat pública d'un component es comporti bé dins de la finestra de propietats de Visual Studio (el Property Grid), es decora amb atributs. Al fitxer IndicadorEstoc.cs:

CSHARP 
[Category("GestorEstoc")]
[Description("Percentatge d'estoc del producte, entre 0 i 100.")]
[DefaultValue(0)]
public int PercentatgeEstoc
{
    get => percentatgeEstoc;
    set
    {
        // Retall de rang (clamping): mai llança excepció per un valor fora de rang
        percentatgeEstoc = Math.Max(0, Math.Min(100, value));
        ActualitzaAspecte();
        ComprovaCanviEstat();
    }
}

[Browsable(false)]
public string EstatEstoc
{
    get
    {
        if (percentatgeEstoc < 20) return "Esgotat";
        if (percentatgeEstoc < 50) return "Estoc baix";
        return "Disponible";
    }
}
AtributEfecte
[Category("...")]Agrupa la propietat sota una categoria dins del Property Grid.
[Description("...")]Text d'ajuda que apareix a la part inferior del Property Grid en seleccionar la propietat.
[DefaultValue(x)]Indica el valor per defecte; permet que Visual Studio mostri la propietat en negreta només quan s'ha canviat.
[Browsable(false)]Amaga la propietat del Property Grid: té sentit aquí perquè EstatEstoc és calculada a partir de PercentatgeEstoc, no té sentit "configurar-la" en temps de disseny.

En seleccionar la instància indicadorEstoc1 dins del formulari, la propietat PercentatgeEstoc apareix a la finestra de Propietats sota la categoria "GestorEstoc", amb la seva descripció:

Figura

Una pràctica habitual i robusta és que les propietats numèriques retallin (clamp) els valors fora de rang en lloc de llançar excepcions: és més previsible per a qui utilitza el component des d'un formulari.

3. Esdeveniments i comportament propis

Un component pot declarar els seus propis esdeveniments perquè el formulari que l'utilitza hi pugui reaccionar, seguint el patró estàndard de .NET. IndicadorEstoc declara tres esdeveniments, un per estat possible:

CSHARP 
public event EventHandler? EstocDisponible;
public event EventHandler? EstocBaix;
public event EventHandler? EstocEsgotat;

protected virtual void OnEstocDisponible(EventArgs e) => EstocDisponible?.Invoke(this, e);
protected virtual void OnEstocBaix(EventArgs e) => EstocBaix?.Invoke(this, e);
protected virtual void OnEstocEsgotat(EventArgs e) => EstocEsgotat?.Invoke(this, e);

private void ComprovaCanviEstat()
{
    // Els esdeveniments només es llancen quan l'estat canvia, no en cada assignació.
    if (EstatEstoc == estatAnterior) return;
    estatAnterior = EstatEstoc;

    switch (EstatEstoc)
    {
        case "Disponible": OnEstocDisponible(EventArgs.Empty); break;
        case "Estoc baix": OnEstocBaix(EventArgs.Empty); break;
        case "Esgotat": OnEstocEsgotat(EventArgs.Empty); break;
    }
}

/// <summary>Reaprovisiona el producte: posa l'estoc al 100% i actualitza la interfície.</summary>
public void Reaprovisiona()
{
    PercentatgeEstoc = 100;
}
Informació

Concepte clau: per què ?.Invoke i no .Invoke

Un esdeveniment com EstocDisponible val null mentre cap formulari s'hi hagi subscrit (és a dir, mentre ningú hagi fet indicadorEstoc1.EstocDisponible += ...). Si es cridés directament EstocDisponible.Invoke(this, e) i encara fos null, el programa llançaria una excepció (NullReferenceException) i es tancaria. L'operador d'invocació condicional ?. evita el problema: EstocDisponible?.Invoke(this, e) es tradueix, en essència, a "si EstocDisponible no és null, invoca'l; si ho és, no facis res". És el patró estàndard per disparar qualsevol esdeveniment de manera segura.

Important

Error habitual

Llançar l'esdeveniment cada vegada que el valor canvia, en lloc de fer-ho només quan canvia l'estat. Per exemple, si el percentatge passa de 80 a 85, totes dues xifres corresponen a l'estat "Disponible": no s'hauria de tornar a llançar EstocDisponible. Per això ComprovaCanviEstat() guarda l'estat anterior i compara.

Des del formulari principal, el component s'integra subscrivint-se als tres esdeveniments per actualitzar la barra d'estat:

TEXT 
indicadorEstoc1.EstocDisponible += (s, e) => lblEstatGeneral.Text = "Estat: estoc disponible";
indicadorEstoc1.EstocBaix += (s, e) => lblEstatGeneral.Text = "Estat: estoc baix, cal revisar";
indicadorEstoc1.EstocEsgotat += (s, e) => lblEstatGeneral.Text = "Estat: producte esgotat";

El mètode protected virtual OnXxx(...) és una convenció (no una obligació estricta) que permet que una classe derivada pugui sobreescriure com es dispara l'esdeveniment, mantenint la compatibilitat amb el patró estàndard que fan servir la resta de controls de .NET.
