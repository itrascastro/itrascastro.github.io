A3. Windows Forms i programació per esdeveniments

Del programa seqüencial als botons i formularis

En acabar sabreu:
  • Identificar formularis, controls i propietats.
  • Explicar el flux d'un esdeveniment Click.
  • Escriure i connectar un gestor d'esdeveniment.
  • Separar el codi de pantalla del codi de negoci.

1. Un programa que espera l'usuari

En una aplicació de consola, les instruccions es van executant una rere l'altra. En una aplicació gràfica, la finestra queda oberta mentre l'usuari prem botons, escriu o selecciona elements. Cadascuna d'aquestes accions pot generar un esdeveniment.

Usuari fa clic→Botó genera Click→Gestor d'esdeveniment→S'actualitza la pantalla
Model mental

Un esdeveniment és un avís que ha passat alguna cosa. Un gestor d'esdeveniment és el mètode que nosaltres escrivim perquè l'aplicació respongui a aquest avís. No cal un bucle que consulti contínuament si s'ha premut el botó.

2. Crear un formulari amb l'editor visual

Aquest bloc es fa a Windows. Obriu Visual Studio i creeu un projecte Windows Forms App (C#), anomenat PrimerFormulari. Si us demana el framework, trieu .NET 8 o una versió posterior compatible amb els materials del mòdul. Eviteu confondre'l amb la plantilla antiga Windows Forms App (.NET Framework).

  1. Obriu Form1.cs [Design] (el dissenyador visual).
  2. Arrossegueu un Label i un Button des del Toolbox.
  3. A la finestra Properties, poseu Name = lblComptador i Text = Clics: 0 al Label.
  4. Al botó, poseu Name = btnSumar i Text = Sumar.
  5. Deseu el formulari. Visual Studio generarà codi de disseny al fitxer Form1.Designer.cs.

El Name identifica el control des del vostre codi. El Text és el que veu l'usuari. Un Button i un Label són objectes que tenen propietats i esdeveniments.

3. Respondre a un Click

Obriu Form1.cs (codi), afegiu un camp que compti els clics i connecteu el botó amb un mètode. El constructor s'executa quan es crea el formulari; InitializeComponent() crea i configura els controls definits al dissenyador.

C#Form1.cs
public partial class Form1 : Form
{
    private int clics = 0;

    public Form1()
    {
        InitializeComponent();
        btnSumar.Click += BtnSumar_Click;
    }

    private void BtnSumar_Click(object? sender, EventArgs e)
    {
        clics++;
        lblComptador.Text = "Clics: " + clics;
    }
}

Aquest fragment mostra la classe del formulari, dins del namespace del projecte que Visual Studio ja ha creat. No enganxeu una segona classe Form1 si ja existeix: afegiu-hi el camp, la subscripció i el mètode. sender és qui ha generat l'esdeveniment; EventArgs e representa informació de l'esdeveniment. En aquest primer cas no cal utilitzar-los.

Eviteu subscriure el mateix Click dues vegades

També podeu fer doble clic al botó dins del dissenyador: Visual Studio crea el mètode i connecta l'esdeveniment automàticament. Escolliu una sola tècnica. Si ja teniu la connexió generada al Designer, no torneu a escriure btnSumar.Click += ..., o el mètode podria executar-se dues vegades.

4. Propietats i altres esdeveniments

Una interfície no és només Click. Per exemple, un TextBox té la propietat Text i l'esdeveniment TextChanged. Podeu actualitzar un Label quan algú escriu:

C#Form1.cs (fragment)
private void TxtNom_TextChanged(object? sender, EventArgs e)
{
    lblSalutacio.Text = "Hola, " + txtNom.Text.Trim();
}

Per executar aquest exemple necessiteu també un TextBox anomenat txtNom, un Label anomenat lblSalutacio i associar el seu esdeveniment TextChanged amb el mètode. Podeu fer-ho des de l'apartat d'esdeveniments de la finestra Properties (icona del llamp), o bé amb txtNom.TextChanged += TxtNom_TextChanged; al constructor.

5. No barregeu dades i pantalla

El formulari hauria de recollir el que ha introduït l'usuari, demanar el treball a les classes del programa i mostrar-ne el resultat. Les regles que determinen si una operació és vàlida haurien de viure preferentment a les classes del domini.

C#Idea de separació
// El formulari llegeix dades.
string nom = txtNom.Text.Trim();

// Una classe del domini fa la feina.
Producte producte = new Producte(nom, 5);

// El formulari mostra el resultat.
lblResultat.Text = producte.Nom;

Aquesta estructura serà clau per entendre el projecte GestorEstocBotiga i els components visuals propis.

Practiqueu: Comptador amb dos botons

Afegiu un segon botó btnReiniciar que torni el comptador a zero i actualitzi el Label. Comproveu que la pantalla canvia només després de prémer un botó, i que el valor del camp clics es conserva entre clics.

Comprovació abans de continuar
  • Puc crear un Button i un Label al dissenyador.
  • Sé diferenciar Name i Text.
  • Entenc la línia btnSumar.Click += BtnSumar_Click;.
  • Sé què és un mètode gestor d'esdeveniment.
  • Sé per què convé separar la lògica del formulari.
