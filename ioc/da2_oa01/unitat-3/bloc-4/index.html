Introducció

Després de les 9 lectures de la Unitat 3, disposeu dels conceptes necessaris per construir una aplicació Angular que consumeix dades reals d'una API local, les transforma amb adaptadors, gestiona els seus estats (càrrega, èxit, error) i ofereix formularis avançats amb validacions personalitzades i camps dinàmics.

Aquest cas d'ús integra aquests conceptes en una aplicació funcional: un catàleg d'elements que carrega dades des d'una API local, permet fer cerques amb validació asíncrona, conserva un historial de cerques, gestiona preferits amb notes dinàmiques (FormArray) amb persistència local i crea elements nous amb POST.

L'aplicació que construireu és la base tècnica que podreu ampliar a la Unitat 4 amb navegació, rutes i optimització. Per això és fonamental que acabeu amb una aplicació robusta i ben documentada.

Objectius del cas d'ús

  • Configurar l'accés a un servei local reproduïble amb json-server i documentar la configuració
  • Implementar models TypeScript amb interfícies i adaptadors per transformar dades externes
  • Crear serveis Angular amb HttpClient que gestionen estats de càrrega, èxit i error
  • Construir formularis reactius amb validacions personalitzades síncrones i asíncrones
  • Implementar gestió de historial de cerques amb persistència a localStorage
  • Desenvolupar formularis dinàmics amb FormArray per gestionar col·leccions de mida variable (notes de preferits)
  • Enviar dades a l'API amb POST des d'un formulari reactiu i refrescar el llistat

  • RA3 · Criteri 1 — Defineix models de dades i estructures adequades al cas d'ús.
  • RA3 · Criteri 2 — Utilitza serveis externs (APIs web) per obtenir, enviar i actualitzar informació.

2. Visió general de l'aplicació

2.1. Què construireu

Una aplicació Angular completa amb sis funcionalitats principals:

  1. Llistat d'elements: Carrega automàticament els elements de l'API local
  2. Cerca d'elements: Formulari reactiu que filtra per text i categoria, amb validació síncrona i asíncrona i debounce
  3. Gestió d'estats: Indicadors visuals de càrrega, missatges d'error i gestió de reintents
  4. Historial de cerques: Desa criteris de cerca vàlids a localStorage i permet recuperar-los
  5. Preferits amb notes: Marcatge d'elements preferits i notes dinàmiques amb FormArray, persistits a localStorage
  6. Alta d'elements: Formulari que envia un element nou a l'API amb POST

2.3. Flux de dades

  1. Component CatalegPage crida ElementService.carregarTot(), que emet criteris buits al flux de cerca
  2. Servei fa petició HTTP a l'API
  3. Adaptador transforma resposta JSON → model ElementCataleg
  4. Component rep dades via signal i actualitza la vista
  5. Formulari de cerca valida l'entrada (síncrona i asíncrona) i emet criteris nous; switchMap garanteix que només compti l'última petició
  6. Les cerques confirmades s'emmagatzemen a localStorage i es poden recuperar
  7. L'usuari marca preferits i hi afegeix notes amb un FormArray; també es persisteixen a localStorage
  8. El formulari d'alta envia un element nou amb POST i el servei refresca el llistat

Fitxer src/app/adaptadors/element.adaptador.ts:

TYPESCRIPT 
import { ElementCataleg, ElementApiResponse } from '../models/element.model';

const CATEGORIES_NORMALITZADES: Record<string, string> = {
  electronics: 'Electrònica',
  electronica: 'Electrònica',
  displays: 'Pantalles',
  communication: 'Comunicació',
};

const IMATGE_PER_DEFECTE = 'https://placehold.co/300x200?text=Sense+imatge';

function normalitzaCategoria(categoria: string | undefined): string {
  const neta = (categoria ?? '').trim();
  return CATEGORIES_NORMALITZADES[neta.toLocaleLowerCase()] ?? neta;
}

function numeroSegur(valor: unknown, perDefecte = 0): number {
  const n = Number(valor);
  return Number.isFinite(n) ? n : perDefecte;
}

export function adaptarElementApi(apiElement: ElementApiResponse): ElementCataleg {
  return {
    id: String(apiElement.id),
    nom: (apiElement.nom ?? '').trim(),               // text sense espais sobrants
    descripcio: (apiElement.descripcio ?? '').trim(),
    categoria: normalitzaCategoria(apiElement.categoria),   // valors coherents en català
    preu: numeroSegur(apiElement.preu),                // conversió segura a número
    imatge: apiElement.imatge?.trim() || IMATGE_PER_DEFECTE,   // valor per defecte si falta
    esPopular: apiElement.popular === true,            // canvi de nom i booleà segur
    stock: numeroSegur(apiElement.stock),
    dataAfegit: new Date(),                            // camp calculat
  };
}

export function adaptarElementsApi(apiElements: ElementApiResponse[]): ElementCataleg[] {
  return apiElements.map(adaptarElementApi);
}

export function elementBuit(): ElementCataleg {
  return {
    id: '',
    nom: '',
    descripcio: '',
    categoria: '',
    preu: 0,
    imatge: IMATGE_PER_DEFECTE,
    esPopular: false,
    stock: 0,
    dataAfegit: new Date(),
  };
}

Què fa l'adaptador, a més de canviar noms: retalla espais, converteix números de manera segura, posa una imatge per defecte i unifica categories que l'API pot enviar en anglès o amb majúscules diferents. Aquesta normalització és el que protegeix l'aplicació quan l'API no és del tot neta. Avantatges dels adaptadors com a funcions pures: faciliten les proves unitàries i la reutilització.

5.2. Implementar servei amb signals, switchMap i HttpClient

Substituïu tot el contingut de element.service.ts (conservem el decorador @Service() que genera la CLI):

TYPESCRIPT 
import { HttpClient, HttpErrorResponse, HttpParams } from '@angular/common/http';
import { Service, inject, signal } from '@angular/core';
import { Observable, Subject, catchError, map, of, switchMap, tap } from 'rxjs';

import { adaptarElementApi, adaptarElementsApi, prepararElementApi } from '../adaptadors/element.adaptador';
import { ElementApiResponse, ElementCataleg, EstatElements, NouElement } from '../models/element.model';
import { environment } from '../../environments/environment';

export interface CriterisCerca {
  terme: string;
  categoria: string;   // '' = totes les categories
}

@Service()
export class ElementService {
  private readonly http = inject(HttpClient);
  private readonly apiUrl = `${environment.apiUrl}/elements`;

  // Flux de criteris: cada cerca nova s'emet aquí.
  // Subject (no BehaviorSubject): no volem cap emissió inicial automàtica;
  // la primera petició la dispara el component amb carregarTot()
  private readonly criterisInicials: CriterisCerca = { terme: '', categoria: '' };
  private readonly criteris$ = new Subject<CriterisCerca>();
  private darrersCriteris = this.criterisInicials;

  // Estat únic del servei, exposat com a signal de només lectura
  private readonly estatSignal = signal<EstatElements>({ estat: 'inicial', elements: [] });
  readonly estat = this.estatSignal.asReadonly();

  constructor() {
    this.criteris$.pipe(
      tap((criteris) => {
        this.darrersCriteris = criteris;
        this.estatSignal.set({ estat: 'carregant', elements: [] });
      }),
      // switchMap cancel·la la petició anterior si arriben criteris nous abans que acabi
      switchMap((criteris) => this.obtenirElements(criteris).pipe(
        map((elements): EstatElements => ({ estat: 'exit', elements })),
        catchError((error: HttpErrorResponse) => of<EstatElements>({
          estat: 'error',
          elements: [],
          error: this.gestionarError(error),
        }))
      ))
    ).subscribe((estat) => this.estatSignal.set(estat));
  }

  /** Carrega tots els elements (sense criteris) */
  carregarTot(): void {
    this.cercar(this.criterisInicials);
  }

  /** Emet criteris nous: el flux del constructor fa la petició */
  cercar(criteris: CriterisCerca): void {
    this.criteris$.next({
      terme: criteris.terme.trim(),
      categoria: criteris.categoria,
    });
  }

  /** Repeteix l'última cerca (botó "Reintentar") */
  reintentar(): void {
    this.criteris$.next(this.darrersCriteris);
  }

  /** Crea un element nou amb POST i, si va bé, refresca el llistat */
  crearElement(nou: NouElement): Observable<ElementCataleg> {
    return this.http.post<ElementApiResponse>(this.apiUrl, prepararElementApi(nou)).pipe(
      map(adaptarElementApi),
      tap(() => this.reintentar())
    );
  }

  /** Nombre de resultats per a un terme (per al validador asíncron) */
  comptarResultats(terme: string): Observable<number> {
    return this.obtenirElements({ terme, categoria: '' }).pipe(
      map((elements) => elements.length)
    );
  }

  private obtenirElements(criteris: CriterisCerca): Observable<ElementCataleg[]> {
    let params = new HttpParams();
    if (criteris.categoria) {
      params = params.set('categoria', criteris.categoria);
    }

    return this.http.get<ElementApiResponse[]>(this.apiUrl, { params }).pipe(
      map(adaptarElementsApi),
      map((elements) => this.filtrarPerTerme(elements, criteris.terme))
    );
  }

  private filtrarPerTerme(elements: ElementCataleg[], terme: string): ElementCataleg[] {
    const text = terme.trim().toLocaleLowerCase('ca');
    if (text.length < 3) {
      return elements;
    }
    return elements.filter((element) =>
      `${element.nom} ${element.descripcio}`.toLocaleLowerCase('ca').includes(text)
    );
  }

  private gestionarError(error: HttpErrorResponse): string {
    switch (error.status) {
      case 0:
        return 'No es pot connectar amb l\'API. Comproveu que npm run api està actiu.';
      case 404:
        return 'Recurs no trobat. Verifiqueu la URL de l\'API.';
      case 500:
        return 'Error intern del servidor.';
      default:
        return `Error inesperat (${error.status}): ${error.message}`;
    }
  }
}

Context: Aquest servei implementa el flux complet que demana la unitat:

TEXT 
cercar(criteris) → criteris$ (Subject) → switchMap → HttpClient GET → adaptador → filtre → estatSignal → vista
  • Un sol estat: estat() conté alhora la fase (inicial, carregant, exit, error), els elements i el missatge d'error. Els components només el llegeixen.
  • Subject + switchMap: si l'usuari fa dues cerques seguides, la primera petició es cancel·la i només arriba la resposta de l'última. Sense switchMap, una resposta lenta podria sobreescriure una de més recent. Usem Subject i no BehaviorSubject perquè aquest últim emetria el valor inicial en subscriure's al constructor i, en cridar carregarTot() des del component, es farien dues peticions GET seguides.
  • catchError dins del switchMap: si estigués fora, el primer error tancaria el flux i les cerques següents deixarien de funcionar.
  • Filtre de categoria a l'API i filtre de text al servei: json-server filtra bé per camp (?categoria=Sensors), però el paràmetre de cerca global no és fiable; per això el text es filtra un cop adaptades les dades.
  • POST amb refresc: crearElement() retorna l'observable perquè el formulari sàpiga quan ha acabat, i amb tap repeteix l'última cerca perquè el llistat mostri l'element nou.
  • Signals i canvi de vista: les respostes HTTP arriben fora de qualsevol esdeveniment de plantilla; com que el projecte no usa zone.js, només el canvi del signal fa que Angular repinti.

Afegiu el següent codi. Un validador asíncron retorna directament un Observable<ValidationErrors | null>; el timer(400) inicial retarda la consulta i switchMap encadena aquesta espera amb la petició HTTP. La cancel·lació entre tecleigs no la fa switchMap (que aquí només veu una emissió del timer), sinó el mateix FormControl: a cada canvi de valor es desubscriu de la validació anterior i en comença una de nova; si el timer encara no havia vençut, la petició a l'API no s'arriba a fer mai. Aquest és el debounce efectiu:

TYPESCRIPT 
import { AbstractControl, AsyncValidatorFn, ValidationErrors } from '@angular/forms';
import { Observable, catchError, map, of, switchMap, timer } from 'rxjs';
import { ElementService } from '../services/element.service';

/**
 * Validador asíncron: el terme ha de coincidir amb algun element de l'API.
 * Error retornat: { senseResultats: true }
 */
export function termeAmbResultatsValidator(elementService: ElementService): AsyncValidatorFn {
  return (control: AbstractControl): Observable<ValidationErrors | null> => {
    const terme = (control.value ?? '').toString().trim();

    // Termes curts o buits: no consultem l'API (ja els atura la validació síncrona)
    if (terme.length < 3) {
      return of(null);
    }

    return timer(400).pipe(
      switchMap(() => elementService.comptarResultats(terme)),
      map((total) => (total > 0 ? null : { senseResultats: true })),
      catchError(() => of(null))   // si l'API falla, no bloquegem el formulari
    );
  };
}

Context: mentre el validador espera la resposta, el control queda en estat pending; la plantilla ho aprofita per mostrar "Comprovant...". Si l'API diu que no hi ha resultats, el control passa a invàlid amb l'error senseResultats.

import { Component, EventEmitter, Output, inject } from '@angular/core';
import { FormControl, FormGroup, ReactiveFormsModule, Validators } from '@angular/forms';

import { CriterisCerca, ElementService } from '../../services/element.service';
import { termeAmbResultatsValidator } from '../../validadors/terme-amb-resultats.validator';

@Component({
  imports: [ReactiveFormsModule],
  selector: 'app-formulari-cerca',
  styleUrl: './formulari-cerca.component.scss',
  templateUrl: './formulari-cerca.component.html',
})
export class FormulariCercaComponent {
  private readonly elementService = inject(ElementService);

  @Output() cercaEnviada = new EventEmitter<CriterisCerca>();

  readonly categories = ['Electrònica', 'Sensors', 'Motors', 'Pantalles', 'Comunicació', 'Components', 'Prototipatge', 'Il·luminació'];

  readonly formulari = new FormGroup({
    terme: new FormControl('', {
      nonNullable: true,
      validators: [Validators.minLength(3)],
      asyncValidators: [termeAmbResultatsValidator(this.elementService)],
    }),
    categoria: new FormControl('', { nonNullable: true }),
  });

  /** Enviament explícit (botó o tecla Retorn) */
  enviar(): void {
    if (this.formulari.invalid) {
      this.formulari.markAllAsTouched();
      return;
    }
    this.emetre();
  }

  netejar(): void {
    this.formulari.reset();
    this.emetre();
  }

  private emetre(): void {
    this.cercaEnviada.emit(this.formulari.getRawValue());
  }

  get terme(): FormControl<string> {
    return this.formulari.controls.terme;
  }

  get mostrarErrors(): boolean {
    return this.terme.invalid && (this.terme.dirty || this.terme.touched);
  }

  get missatgeError(): string {
    if (this.terme.hasError('minlength')) {
      return 'Escriviu 3 caràcters com a mínim.';
    }
    if (this.terme.hasError('senseResultats')) {
      return 'Cap element coincideix amb aquest terme.';
    }
    return '';
  }
}

  • Missatges només quan cal: dirty || touched

8. Historial de cerques amb localStorage

8.3. Implementar el servei amb control d'errors

El servei conserva com a màxim vuit cerques, evita repetir dues cerques consecutives i tracta localStorage com un recurs que pot fallar (mode privat, quota plena, dades corruptes):

TYPESCRIPT 
import { Service, signal } from '@angular/core';
import { CercaDesada } from '../models/element.model';

@Service()
export class HistorialCerquesService {
  private readonly clauStorage = 'cataleg-historial-cerques';
  private readonly historialSignal = signal<CercaDesada[]>(this.llegir());

  readonly historial = this.historialSignal.asReadonly();

  desar(terme: string, categoria: string): void {
    const termeNormalitzat = terme.trim();
    if (termeNormalitzat.length < 3) {
      return;
    }

    const novaCerca: CercaDesada = {
      terme: termeNormalitzat,
      categoria,
      data: new Date().toISOString(),
    };
    const anterior = this.historialSignal()[0];

    if (anterior?.terme === novaCerca.terme && anterior.categoria === novaCerca.categoria) {
      return;
    }

    this.historialSignal.update((historial) => [novaCerca, ...historial].slice(0, 8));
    this.escriure();
  }

  netejar(): void {
    this.historialSignal.set([]);
    this.escriure();
  }

  private llegir(): CercaDesada[] {
    try {
      const dades = localStorage.getItem(this.clauStorage);
      const historial: unknown = dades ? JSON.parse(dades) : [];

      if (!Array.isArray(historial)) {
        return [];
      }

      return historial.filter((cerca): cerca is CercaDesada =>
        typeof cerca?.terme === 'string' &&
        typeof cerca?.categoria === 'string' &&
        typeof cerca?.data === 'string'
      );
    } catch {
      return [];
    }
  }

  private escriure(): void {
    try {
      localStorage.setItem(this.clauStorage, JSON.stringify(this.historialSignal()));
    } catch {
      // La cerca continua funcionant encara que el navegador no permeti persistir-la.
    }
  }
}

Decisions del servei:

  • El signal és l'única font d'estat que exposa el servei; la vista es refresca sola quan canvia.
  • Les dades persistides es validen abans d'utilitzar-les: localStorage només guarda text i podria contenir qualsevol cosa.
  • Les excepcions de lectura o escriptura no aturen l'aplicació.
  • La lògica per evitar duplicats consecutius queda centralitzada.

9. Preferits locals i formulari dinàmic amb FormArray

Objectiu: Implementar un sistema de preferits amb persistència a localStorage i un formulari dinàmic amb FormArray per gestionar un nombre variable de notes per a cada preferit.

Integra conceptes de: Lectura 3.3.3 (Formularis complexos i camps dinàmics), Lectura 3.2.3 (Integració reactiva amb components).

L'historial de la secció 8 guarda dades de mida fixa (un terme i una categoria). 9.3. Implementar el servei amb localStorage

Substituïu tot el contingut de preferits.service.ts. Segueix el mateix patró que l'historial: un signal com a única font d'estat, lectura validada i escriptura protegida amb try/catch:

TYPESCRIPT 
import { Service, signal } from '@angular/core';
import { Preferit } from '../models/element.model';

@Service()
export class PreferitsService {
  private readonly clauStorage = 'cataleg-preferits';
  private readonly preferitsSignal = signal<Preferit[]>(this.llegir());

  readonly preferits = this.preferitsSignal.asReadonly();

  afegirPreferit(elementId: string, elementNom: string): void {
    if (this.esPreferit(elementId)) {
      return;
    }
    const nou: Preferit = { elementId, elementNom, notes: [], dataAfegit: new Date().toISOString() };
    this.preferitsSignal.update((preferits) => [...preferits, nou]);
    this.escriure();
  }

  eliminarPreferit(elementId: string): void {
    this.preferitsSignal.update((preferits) => preferits.filter((p) => p.elementId !== elementId));
    this.escriure();
  }

  /** Substitueix totes les notes d'un preferit (les rep del FormArray) */
  desarNotes(elementId: string, notes: string[]): void {
    this.preferitsSignal.update((preferits) =>
      preferits.map((p) => (p.elementId === elementId ? { ...p, notes: [...notes] } : p))
    );
    this.escriure();
  }

  esPreferit(elementId: string): boolean {
    return this.preferitsSignal().some((p) => p.elementId === elementId);
  }

  obtenirPreferit(elementId: string): Preferit | undefined {
    return this.preferitsSignal().find((p) => p.elementId === elementId);
  }

  private llegir(): Preferit[] {
    try {
      const dades = localStorage.getItem(this.clauStorage);
      const preferits: unknown = dades ? JSON.parse(dades) : [];
      if (!Array.isArray(preferits)) {
        return [];
      }
      return preferits.filter((p): p is Preferit =>
        typeof p?.elementId === 'string' &&
        typeof p?.elementNom === 'string' &&
        Array.isArray(p?.notes) &&
        typeof p?.dataAfegit === 'string'
      );
    } catch {
      return [];
    }
  }

  private escriure(): void {
    try {
      localStorage.setItem(this.clauStorage, JSON.stringify(this.preferitsSignal()));
    } catch {
      // Sense persistència, els preferits duren fins que es tanca la pestanya
    }
  }
}

Context: Aquest servei:

  • Carrega els preferits en crear-se (valor inicial del signal) i desa després de cada modificació
  • No muta mai l'array: update retorna sempre un array nou, cosa que manté la reactivitat previsible
  • Exposa desarNotes() en lloc d'afegir/eliminar notes una a una: el formulari és qui gestiona la llista, i el servei només la persisteix

9.5. Implementar el component amb FormArray

Substituïu tot el contingut de preferits-panel.component.ts. El FormArray es reconstrueix cada vegada que l'usuari selecciona un preferit: un control per nota existent més un control buit per escriure'n una de nova:

TYPESCRIPT 
import { Component, inject, signal } from '@angular/core';
import { DatePipe } from '@angular/common';
import { FormArray, FormControl, FormGroup, ReactiveFormsModule, Validators } from '@angular/forms';

import { Preferit } from '../../models/element.model';
import { PreferitsService } from '../../services/preferits.service';

@Component({
  imports: [ReactiveFormsModule, DatePipe],
  selector: 'app-preferits-panel',
  styleUrl: './preferits-panel.component.scss',
  templateUrl: './preferits-panel.component.html',
})
export class PreferitsPanelComponent {
  readonly preferitsService = inject(PreferitsService);

  readonly preferitSeleccionat = signal<Preferit | null>(null);

  readonly formulariNotes = new FormGroup({
    notes: new FormArray<FormControl<string>>([]),
  });

  /** Accés curt al FormArray tipat */
  get notes(): FormArray<FormControl<string>> {
    return this.formulariNotes.controls.notes;
  }

  seleccionarPreferit(preferit: Preferit): void {
    this.preferitSeleccionat.set(preferit);
    this.notes.clear();
    // Un control per cada nota existent...
    for (const nota of preferit.notes) {
      this.notes.push(this.nouControl(nota));
    }
    // ...i un control buit per a la nota nova
    this.notes.push(this.nouControl(''));
  }

  afegirNota(): void {
    const ultim = this.notes.at(this.notes.length - 1);
    if (!ultim || ultim.invalid) {
      ultim?.markAsTouched();
      return;
    }
    this.notes.push(this.nouControl(''));   // el camp que era "nou" passa a ser una nota més
    this.desar();
  }

  eliminarNota(index: number): void {
    this.notes.removeAt(index);
    this.desar();
  }

  eliminarPreferit(elementId: string): void {
    this.preferitsService.eliminarPreferit(elementId);
    if (this.preferitSeleccionat()?.elementId === elementId) {
      this.tancarPanel();
    }
  }

  tancarPanel(): void {
    this.preferitSeleccionat.set(null);
    this.notes.clear();
  }

  /** Persisteix totes les notes vàlides, sense l'últim camp (el buit) */
  private desar(): void {
    const preferit = this.preferitSeleccionat();
    if (!preferit) return;
    const notes = this.notes.getRawValue().slice(0, -1).map((n) => n.trim()).filter((n) => n.length > 0);
    this.preferitsService.desarNotes(preferit.elementId, notes);
    this.preferitSeleccionat.set(this.preferitsService.obtenirPreferit(preferit.elementId) ?? null);
  }

  private nouControl(valor: string): FormControl<string> {
    return new FormControl(valor, { nonNullable: true, validators: [Validators.required, Validators.minLength(3)] });
  }
}

Context: Aquest component implementa:

  • Un FormArray<FormControl<string>> tipat: getRawValue() retorna string[]
  • push(), removeAt() i clear() per fer créixer i decréixer el formulari en temps d'execució
  • Validació per control (required, minLength(3)): el botó "Afegir nota" només s'activa quan el camp nou és vàlid
  • Persistència a cada canvi mitjançant el servei; el preferit seleccionat és un signal perquè el panell es refresqui

  4. Afegiu tres notes i elimineu la del mig amb la ✕: la llista es renumera i es desa

Verificació 3: Persistència

  1. Afegiu 2-3 preferits amb notes i recarregueu la pàgina (F5)
  2. Els preferits i les notes continuen presents; a DevTools → Application → Local Storage hi ha la clau cataleg-preferits

Verificació 4: Eliminar

  1. Elimineu un preferit amb 🗑️: desapareix de la llista i l'estrella de la targeta torna a ☆
  2. Si era el preferit seleccionat, el panell de notes es tanca

### Funcionalitat
Component amb `FormArray` dinàmic per gestionar les notes de cada preferit, amb persistència a `localStorage`.

### FormArray dinàmic
```typescript
formulariNotes = new FormGroup({
```

import { Component, inject, signal } from '@angular/core';
import { FormControl, FormGroup, ReactiveFormsModule, Validators } from '@angular/forms';

import { ElementService } from '../../services/element.service';

@Component({
  imports: [ReactiveFormsModule],
  selector: 'app-formulari-nou-element',
  styleUrl: './formulari-nou-element.component.scss',
  templateUrl: './formulari-nou-element.component.html',
})
export class FormulariNouElementComponent {
  private readonly elementService = inject(ElementService);

  readonly categories = ['Electrònica', 'Sensors', 'Motors', 'Pantalles', 'Comunicació', 'Components', 'Prototipatge', 'Il·luminació'];

  readonly formulari = new FormGroup({
    nom: new FormControl('', { nonNullable: true, validators: [Validators.required, Validators.minLength(3)] }),
    descripcio: new FormControl('', { nonNullable: true, validators: [Validators.required, Validators.minLength(10)] }),
    categoria: new FormControl('Components', { nonNullable: true, validators: [Validators.required] }),
    preu: new FormControl(0, { nonNullable: true, validators: [Validators.required, Validators.min(0.01)] }),
    stock: new FormControl(1, { nonNullable: true, validators: [Validators.required, Validators.min(0)] }),
  });

  // Estat de l'enviament (canvia dins d'una resposta HTTP: per això és un signal)
  readonly enviant = signal(false);
  readonly missatge = signal<string | null>(null);
  readonly error = signal<string | null>(null);

  crear(): void {
    if (this.formulari.invalid) {
      this.formulari.markAllAsTouched();
      return;
    }

    this.enviant.set(true);
    this.missatge.set(null);
    this.error.set(null);

    this.elementService.crearElement(this.formulari.getRawValue()).subscribe({
      next: (element) => {
        this.missatge.set(`S'ha creat "${element.nom}" amb l'identificador ${element.id}.`);
        this.formulari.reset();
        this.enviant.set(false);
      },
      error: () => {
        this.error.set('No s\'ha pogut crear l\'element. Comproveu que l\'API està activa.');
        this.enviant.set(false);
      },
    });
  }

  teError(control: 'nom' | 'descripcio' | 'preu' | 'stock'): boolean {
    const c = this.formulari.controls[control];
    return c.invalid && (c.dirty || c.touched);
  }
}
