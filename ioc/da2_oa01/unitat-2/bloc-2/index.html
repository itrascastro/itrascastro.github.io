1.2. Marc conceptual

1.2.1. Què són els blocs de control de flux

Els blocs de control de flux (control flow blocks) són la sintaxi integrada d'Angular per modificar l'estructura del DOM de manera declarativa: afegir, eliminar o repetir elements sencers segons les dades. A diferència de les vinculacions d'atribut, que només canvien valors d'elements que ja existeixen, els blocs decideixen quins elements hi ha.

Nota històrica: fins a Angular 16 aquesta feina la feien les directives estructurals *ngFor, *ngIf i *ngSwitch, que encara trobareu en molts tutorials. A Angular 22 el control de flux s'escriu amb els blocs @for, @if, @else i @switch: fan la mateixa funció, però formen part del llenguatge de plantilles i no cal importar res.

1.2.2. Problema sense control de flux a la plantilla

Situació abans d'Angular:

Abans de frameworks, mostrar una llista dinàmica d'elements requeria manipular el DOM manualment amb JavaScript:

JAVASCRIPT 
// JavaScript pur: crear llista de 50 elements manualment
const contenidor = document.getElementById('llista-elements');
const elements = [
  { id: 1, titol: 'Colors corporatius', categoria: 'Paletes' },
  { id: 2, titol: 'Pack d\'icones', categoria: 'Icones' },
  { id: 3, titol: 'Sistema tipogràfic', categoria: 'Tipografia' }
  // ... 47 elements més
];

// Construir HTML manualment
let html = '<ul class="grid-targetes">';
elements.forEach((element, index) => {
  html += `
    <li class="${index % 2 === 0 ? 'parell' : 'senar'}">
      <article class="targeta" data-id="${element.id}">
        <h3>${element.titol}</h3>
        <span class="categoria">${element.categoria}</span>
      </article>
    </li>
  `;
});
html += '</ul>';
contenidor.innerHTML = html;

// Afegir listeners manualment
elements.forEach(element => {
  const targeta = document.querySelector(`[data-id="${element.id}"]`);
  targeta.addEventListener('click', () => {
    console.log('Clic a:', element.titol);
  });
});

// Total: 35-40 línies només per renderitzar i afegir listeners
// I això sense actualitzacions dinàmiques ni gestió d'errors!

Problemes que genera:

1. Codi repetitiu i verbós
Per mostrar una llista de 50 elements del catàleg, necessiteu escriure:

  • 10-15 línies per seleccionar contenidor i preparar dades
  • 20-25 línies pel bucle forEach i construcció manual d'HTML
  • 10-15 línies per afegir event listeners a cada targeta

Total: 40-55 línies de JavaScript només per renderitzar una llista. Si teniu 3 llistes diferents (elements destacats, recents, per categoria), multipliqueu per 3: 120-165 línies.

Comparativa al catàleg:

  • Mostrar 50 targetes: 40-50 línies JavaScript manual
  • Afegir filtre per categoria: +25 línies
  • Afegir cerca: +30 línies
  • Total projecte: 95-105 línies només per llistes

2. Actualitzacions manuals propenses a errors
Cada vegada que les dades canvien (afegir element, eliminar, ordenar), heu d'actualitzar manualment el DOM:

JAVASCRIPT 
// Afegir nou element: codi manual propens a errors
function afegirElement(nouElement) {
  // Crear estructura HTML
  const li = document.createElement('li');
  const article = document.createElement('article');
  article.className = 'targeta';
  article.dataset.id = nouElement.id;

  const h3 = document.createElement('h3');
  h3.textContent = nouElement.titol;
  article.appendChild(h3);

  const span = document.createElement('span');
  span.className = 'categoria';
  span.textContent = nouElement.categoria;
  article.appendChild(span);

  li.appendChild(article);
  document.querySelector('.grid-targetes').appendChild(li);

  // Afegir listener
  article.addEventListener('click', () => {
    console.log('Clic a:', nouElement.titol);
  });
}

// 20 línies per afegir 1 element!

Errors típics que provoca:

  • Elements no s'actualitzen quan canvien dades → interfície desincronitzada
  • Referències obsoletes (querySelector retorna null) → errors runtime
  • Event listeners duplicats → múltiples execucions per un sol clic
  • Pèrdua d'esdeveniments en recrear elements → funcionalitat trencada
  • Fuites de memòria per no eliminar listeners antics → rendiment degradat

3. Dificultat per mantenir sincronització dades-vista
L'estat de l'aplicació es fragmenta entre múltiples llocs:

  • Array JavaScript amb les dades reals
  • DOM amb els elements visuals
  • Variables globals amb índexs i referències
  • Atributs data-* amb informació duplicada

Exemple real de desincronització:

JAVASCRIPT 
let elements = [
  { id: 1, titol: 'Colors' },
  { id: 2, titol: 'Icones' },
  { id: 3, titol: 'Tipografia' }
];

// Renderitzar llista inicial (3 elements al DOM)
renderitzarLlista(elements);

// Eliminar element amb id=2 de l'array
elements = elements.filter(el => el.id !== 2);
// Ara: elements = [{id:1}, {id:3}]

// Problema: El DOM encara mostra 3 elements!
// Cal actualitzar manualment:
document.querySelector('[data-id="2"]').remove();

// Però si oblides aquesta línia, la interfície mostra dades incorrectes!

Desincronitzacions habituals:

  • L'array té 10 elements però el DOM mostra 12 (2 obsolets)
  • Actualitzar un element a l'array no actualitza la targeta visual
  • Ordenar l'array no reordena els elements al DOM
  • Afegir element nou no apareix fins refrescar pàgina

4. Rendiment degradat amb llistes grans
Sense optimitzacions intel·ligents, cada petit canvi recrea tota la llista:

JAVASCRIPT 
// Rendiment dolent: recreació completa
function actualitzarLlista(elements) {
  const contenidor = document.querySelector('.grid-targetes');
  contenidor.innerHTML = ''; // DESTRUEIX TOT (inclosos listeners!)

  elements.forEach(element => {
    // Recrea TOTS els elements de zero
    const li = document.createElement('li');
    // ... 15 línies més per crear estructura completa
    contenidor.appendChild(li);
  });
}

// Cada tecla al camp de cerca → recreació completa!
inputCerca.addEventListener('input', (event) => {
  const filtrats = elements.filter(el =>
    el.titol.includes(event.target.value)
  );
  actualitzarLlista(filtrats); // Recrea tot el DOM
});

Impacte en rendiment mesurat:

  • Llista de 50 elements: 80-120ms per actualització
  • Llista de 100 elements: 150-200ms per actualització
  • Llista de 500 elements: 800-1200ms (1-1.2 segons)
  • Llista de 1000 elements: 1500-2500ms (1.5-2.5 segons)

Experiència d'usuari: Cada tecla a la cerca recrea tots els elements → interfície que "peta", scroll que salta, inputs que perden focus.

5. Escalabilitat limitada i mantenibilitat baixa
Afegir funcionalitats noves requereix modificar múltiples parts del codi i és propens a trencar funcionalitat existent.

Exemple real: Afegir numeració als elements

  • Canviar el bucle forEach per afegir índex
  • Modificar construcció d'HTML per incloure número
  • Actualitzar els estils CSS
  • Verificar que funciona amb filtre, cerca, ordenació
  • Provar que no trenca event listeners

Temps necessari: 30-45 minuts de feina + 15 minuts de testing → 45-60 minuts per afegir un simple número.

Risc: Alta probabilitat de trencar funcionalitat existent per la interconnexió de tot el codi.

1.2.3. Solució amb blocs de control de flux

Angular 22 simplifica la gestió de llistes dinàmiques amb @for:

Plantilla HTML (declarativa i clara):

HTML 
<!-- Angular: sintaxi declarativa -->
<ul class="grid-targetes">
  @for (element of elements; track element.id; let i = $index; let esParell = $even) {
  <li
      [class.parell]="esParell"
      [class.senar]="!esParell">
    <article class="targeta" (click)="onClicElement(element)">
      <span class="numero">{{ i + 1 }}</span>
      <h3>{{ element.titol }}</h3>
      <span class="categoria">{{ element.categoria }}</span>
    </article>
  </li>
  }
</ul>

Component TypeScript (lògica separada):

TYPESCRIPT 
export class CatalegComponent {
  elements: Element[] = [
    { id: 1, titol: 'Colors corporatius', categoria: 'Paletes' },
    { id: 2, titol: 'Pack d\'icones', categoria: 'Icones' },
    { id: 3, titol: 'Sistema tipogràfic', categoria: 'Tipografia' }
    // ... més elements
  ];

  onClicElement(element: Element): void {
    console.log('Clic a:', element.titol);
  }
}

// Total: 10 línies vs 40-50 del JavaScript manual

Avantatges principals:

  • Codi declaratiu: Descriviu què voleu mostrar, Angular gestiona el com.
  • Actualitzacions automàtiques: Canvis a l'array → actualització automàtica del DOM.
  • Rendiment optimitzat: Angular actualitza només els elements que canvien (amb track).
  • Sincronització garantida: Una única font de veritat (l'array del component).
  • Mantenibilitat alta: Canvis concentrats en un sol lloc.
  • Menys codi: Reducció del 75-80% de línies (40-50 → 10 línies).

1.2.4. Exemple real complet: Llista del catàleg

Sense control de flux Angular (JavaScript manual - 45 línies):

// JavaScript pur: gestió manual completa
const contenidor = document.getElementById('cataleg');
const elements = [
  { id: 1, titol: 'Colors', categoria: 'Paletes', preu: 0 },
  { id: 2, titol: 'Icones', categoria: 'Icones', preu: 29 },
  { id: 3, titol: 'Tipografia', categoria: 'Tipografia', preu: 0 }
];

function renderitzarCataleg() {
  let html = '<ul class="grid">';

  elements.forEach((element, index) => {
    const classe = index % 2 === 0 ? 'parell' : 'senar';
    html += `
      <li class="${classe}">
        <article data-id="${element.id}">
          <span class="num">${index + 1}</span>
          <h3>${element.titol}</h3>
          <span class="cat">${element.categoria}</span>
          <span class="preu">${element.preu === 0 ? 'Gratuït' : element.preu + '€'}</span>
        </article>
      </li>
    `;
  });

  html += '</ul>';
  contenidor.innerHTML = html;

  // Afegir listeners
  elements.forEach(element => {
    const article = document.querySelector(`[data-id="${element.id}"]`);
    article.addEventListener('click', () => {
      alert('Element: ' + element.titol);
    });
  });
}

function afegirElement(nou) {
  elements.push(nou);
  renderitzarCataleg(); // Recrea tot!
}

function eliminarElement(id) {
  elements = elements.filter(el => el.id !== id);
  renderitzarCataleg(); // Recrea tot!
}

renderitzarCataleg();

1.2.7. Quan usar / quan no usar @for

Usar @for quan:

  • Mostrar llistes dinàmiques: Qualsevol col·lecció amb N elements desconeguts o variables (catàlegs, resultats cerca, feeds).
  • Generar opcions de formularis: Elements <option> dins de <select>, checkboxes o radios dinàmics.
  • Crear taules amb dades: Files de taules amb dades provinents de bases de dades, APIs o serveis.
  • Mostrar grids de targetes: Galeries d'imatges, catàlegs de productes, grids de contingut (Pinterest-style).

No usar @for (alternativa millor) quan:

1. Nombre fix i conegut d'elements: Si sempre són exactament 3 botons o 5 seccions, escriviu-los manualment per claredat.

HTML 
<!-- No cal @for per 3 elements fixos -->
<button>Opció 1</button>
<button>Opció 2</button>
<button>Opció 3</button>

2. Opcions exclusives conegudes: Per múltiples opcions mútuament exclusives, useu @switch en lloc de @for.

HTML 
<!-- Millor amb @switch -->
@switch (estat) {
  @case ('carregant') { <p>Carregant...</p> }
  @case ('error') { <p>Error!</p> }
  @case ('exit') { <p>Carregat</p> }
}

3. Un sol element condicional: Si només mostreu/amageu un element, useu @if.

HTML 
<!-- Millor amb @if -->
@if (teResultats) { <p>Trobats {{ resultats.length }} elements</p> }

1.2.8. Característiques principals de @for

1. Sintaxi declarativa de bloc
La sintaxi @for forma part del control de flux integrat d'Angular 22 i expressa directament la repetició i la identitat de cada element.

2. Variables locals contextuals
Cada iteració disposa de variables especials que proporcionen context sobre la posició: $index (posició numèrica), $first/$last (booleans primers/últims), even/odd (booleans paritat). Aquestes variables permeten aplicar estils alterns, numeracions i comportaments condicionals.

3. Optimització amb track
L'expressió track identifica cada element de manera única, evitant recreacions innecessàries quan les dades canvien.

4. Change Detection automàtic
Quan l'array canvia (afegir, eliminar, ordenar elements), Angular detecta automàticament els canvis i actualitza només les parts del DOM afectades, sense necessitat de codi manual.

5. Integració amb components fills
@for funciona perfectament amb components personalitzats, passant dades mitjançant @Input() i rebent esdeveniments amb @Output(), creant una arquitectura modular i reutilitzable.

1.2.9. Integració amb el projecte del curs

Al projecte de l'alumne, utilitzarem @for (...; track ...) per implementar:

Funcionalitats principals:

  • Grid de targetes: Mostrar tots els elements amb @for sobre el component de targeta.
  • Llistes de categories: Iterar categories i, dins de cada categoria, iterar els seus elements (llistes niades).
  • Numeració d'elements: Utilitzar la variable $index per mostrar "Element 1 de 50".
  • Estils zebrats: Aplicar classes CSS diferents a files parells/senars amb variables $even/$odd.
  • Optimització: Implementar track element.id per garantir rendiment.
  • Filtres dinàmics: Filtrar elements per cerca o categoria actualitzant l'array, amb re-renderització automàtica.

Aquest patró de @for (...; track ...) serà fonamental per mostrar contingut dinàmic de manera eficient i mantenible al vostre projecte.

1.4. Què són els blocs de control de flux

1.4.1. Objectiu

Entendre què són els blocs de control de flux i com modifiquen l'estructura del DOM.

1.4.2. Contingut

Els blocs de control de flux modifiquen l'estructura del DOM afegint, eliminant o repetint elements. A Angular 22 són @for, @if i @switch (les antigues directives estructurals *ngFor/*ngIf feien aquest paper).

Diferència amb vinculació de propietats:

Aspecte Vinculació propietats Blocs de control de flux
Què fa Canvia valors atributs Modifica estructura DOM
Sintaxi [prop]="valor" @for (…) { … }, @if (…) { … }
Exemple [src]="imatge" @for (x of xs; track x.id) { … }

Transformació interna:

El control de flux integrat expressa directament la iteració a la plantilla:

HTML 
@for (element of elements; track element.id) {
  <li>{{ element }}</li>
}

Avantatges:

  • Codi declaratiu (què en lloc de com)
  • Gestió automàtica del cicle de vida
  • Optimitzacions internes d'Angular
Èxit
Clau: Els blocs de control de flux canvien QUANTS elements hi ha al DOM, no només el seu contingut.

1.5. Sintaxi bàsica de @for

1.5.1. Objectiu

Dominar la sintaxi fonamental de @for i crear la primera iteració.

1.5.2. Contingut

Sintaxi bàsica:

HTML 
@for (item of colleccio; track item.id) {
  <element>{{ item.nom }}</element>
}

Components:

  • @for: directiva d'iteració
  • let item: variable local accessible dins del bloc
  • of col·lecció: array o iterable a recórrer

Important: Utilitzeu of (no in). of itera valors; in itera claus.

Exemple mínim:

TYPESCRIPT 
// Component
titols: string[] = ['Angular', 'TypeScript', 'RxJS'];
HTML 
<!-- Plantilla -->
<ul>
  @for (titol of titols; track titol) {
    <li>{{ titol }}</li>
  }
</ul>

Resultat:

HTML 
<ul>
  <li>Angular</li>
  <li>TypeScript</li>
  <li>RxJS</li>
</ul>

Col·leccions suportades:

  • Arrays de primitius: ['A', 'B', 'C']
  • Arrays d'objectes: [{id:1}, {id:2}] (més comú)
  • Sets: new Set([1,2,3])
  • Maps (amb pipe keyvalue)

1.7. Optimització amb track

1.7.1. Objectiu

Implementar l'expressió track de @for per millorar rendiment i preservar estat de components.

1.7.2. Contingut

Per què track és crucial:

A @for l'expressió track és obligatòria: diu a Angular com reconèixer cada element entre una renderització i la següent. Segons quina trieu, Angular pot reutilitzar les vistes existents (moure-les, actualitzar-les) o ha de destruir-les i crear-ne de noves, perdent l'estat dels components fills (scroll, focus, animacions).

Les tres opcions habituals:

Expressió Identitat Quan és adequada Què passa quan la llista canvia
track element.id Un identificador estable de les dades Recomanada per a llistes que s'afegeixen, s'eliminen, es filtren o es reordenen Angular mou o actualitza només les vistes afectades; les altres es conserven
track $index La posició a l'array Llistes estàtiques o que només canvien al final (un registre de missatges, opcions fixes) Si l'ordre canvia, la vista de la posició 0 mostrarà l'element nou de la posició 0: Angular actualitza el contingut de moltes vistes i pot perdre'n l'estat
track element La referència de l'objecte Només si els objectes es conserven entre renderitzacions (mateixes instàncies) Si cada càrrega crea objectes nous (resposta HTTP, map), cap referència coincideix i Angular recrea totes les vistes

Per al catàleg, on els elements arriben d'una API i es filtren i s'ordenen, track element.id és l'opció correcta.

Sintaxi:

HTML

<li>
  {{ element.titol }}
</li>
}

Important:

  • L'expressió track identifica cada element
  • Useu un identificador únic, normalment element.id
  • NO utilitzeu l'índex com a identificador si l'array pot reordenar-se

Exemple complet:

    }

Èxit

2.2. Marc conceptual

2.2.1. Què són els blocs condicionals

Els blocs condicionals (@if, @else, @switch) són els blocs de control de flux d'Angular que permeten mostrar o amagar elements del DOM segons condicions booleanes. A diferència d'ocultar amb CSS (display: none), els blocs condicionals no renderitzen l'element al DOM si la condició és falsa: el DOM queda més lleuger i l'estat de l'element (listeners, components fills) desapareix amb ell.

Característiques clau:

  • @if: Mostra element si condició és certa, el destrueix si és falsa
  • @if ... @else: Defineix contingut alternatiu sense plantilles auxiliars
  • @switch: Gestiona múltiples opcions exclusives de manera clara

2.2.2. Problema sense blocs condicionals

Situació abans d'Angular: Gestionar condicions i estats visuals requeria manipular el DOM manualment amb JavaScript:

JAVASCRIPT 
// JavaScript pur: gestió manual d'estats i condicions
const spinner = document.getElementById('spinner');
const missatgeError = document.getElementById('missatge-error');
const llistaElements = document.getElementById('llista-elements');

let estat = 'carregant';

function actualitzarInterficie() {
  // Ocultar tots els elements primer
  spinner.style.display = 'none';
  missatgeError.style.display = 'none';
  llistaElements.style.display = 'none';

  // Mostrar segons estat
  if (estat === 'carregant') {
    spinner.style.display = 'block';
  } else if (estat === 'error') {
    missatgeError.style.display = 'block';
    missatgeError.textContent = 'Error en carregar';
  } else if (estat === 'disponible') {
    llistaElements.style.display = 'block';
  }
}

// Total: 25-30 línies només per canviar visibilitat

Problemes que genera:

1. Gestió manual de visibilitat amb display
Per cada estat, heu d'ocultar manualment tots els elements i després mostrar només el necessari. Si afegiu un nou estat, heu de modificar múltiples llocs.

2. Elements al DOM encara que no siguin visibles

2.2.3. Solució amb blocs condicionals

Angular 22 simplifica la gestió de condicions amb @if i @else:

Plantilla HTML (declarativa i clara):

HTML 
<!-- Angular: sintaxi declarativa -->
@if (estat() === 'carregant') {
<div>
  Carregant...
</div>
} @else if (estat() === 'error') {
<div>
  Error en carregar els elements
</div>
} @else if (elements().length > 0) {
<ul>
  @for (element of elements(); track element.id) { <li>{{ element.titol }}</li> }
</ul>
} @else {
<p>
  No hi ha elements disponibles
</p>
}

Component TypeScript (lògica separada):

TYPESCRIPT 
export class CatalegComponent {
  // Estat que canvia quan arriba la resposta: signals (es llegeixen amb parèntesis)
  estat = signal<'carregant' | 'error' | 'disponible'>('carregant');
  elements = signal<Element[]>([]);

  ngOnInit(): void {
    this.carregarElements();
  }

  carregarElements(): void {
    this.estat.set('carregant');
    this.apiService.getElements().subscribe({
      next: (data) => {
        this.elements.set(data);
        this.estat.set('disponible');
      },
      error: () => {
        this.estat.set('error');
      }
    });
  }
}

// Total: 15 línies vs 40-50 del JavaScript manual
Informació
Nota Angular 22: estat i elements es declaren amb signal() perquè canvien dins d'una resposta asíncrona. En un projecte sense zone.js, assignar una propietat normal des d'un subscribe no repintaria la vista; el canvi d'un signal, sí. Els signals s'expliquen a fons a la Unitat 3.

Avantatges principals:

  • Declaratiu: Descriviu què mostrar segons condició, Angular gestiona el com.
  • No al DOM si fals: Elements no existeixen al DOM si la condició és falsa → DOM més lleuger i sense estat residual.
  • Actualització automàtica: Canvis a l'estat → re-renderització automàtica.
  • Codi net: Reducció del 60-70% de línies (40-50 → 15 línies).

2.4.2. Contingut

Els blocs condicionals permeten decidir si un element es renderitza o no al DOM segons una condició booleana.

Diferència fonamental:

Tècnica Efecte Element al DOM Inspeccionable
CSS display: none Oculta visualment Sí Sí (DevTools)
@if No renderitza No No

Per què és important:

  • Estat viu: Els elements ocults amb CSS mantenen listeners i components fills en memòria. Amb @if, l'element no existeix.
  • Rendiment: 100 elements ocults ocupen memòria. Amb @if, només els visibles consumeixen recursos.

Sintaxi bàsica:

HTML 
@if (teElements) { <p>Hi ha elements disponibles</p> }

Com funciona:

  • Angular avalua l'expressió teElements
  • Si és true (o truthy), crea l'element al DOM
  • Si és false (o falsy), no crea l'element
  • Quan el valor canvia, Angular actualitza automàticament
Èxit
Clau: @if controla l'existència de l'element al DOM, no només la seva visibilitat.

2.4.3. Resultat esperat

Compreneu la diferència entre ocultar amb CSS i no renderitzar amb @if.

2.5. Sintaxi bàsica: condició simple i negació

2.5.1. Objectiu

Dominar la sintaxi de @if amb condicions simples, negació i expressions.

2.5.2. Contingut

Condició simple:

HTML 
@if (disponible) { <div>Element disponible</div> }

Negació:

HTML 
@if (!disponible) { <div>Element no disponible</div> }

Expressions complexes:

HTML 
@if (elements.length > 0) { <div>
  Hi ha {{ elements.length }} elements
</div> }

@if (estatLlista === 'error') { <div>
  Error en carregar
</div> }

@if (elements.length > 0 && !carregant) { <div>
  Llista carregada
</div> }

Valors truthy i falsy:

Angular avalua com false: false, null, undefined, 0, '' (string buit), NaN

Angular avalua com true: true, qualsevol número ≠ 0, qualsevol string no buit, arrays i objectes (fins i tot buits)

}

}

2.7. Control de selecció múltiple: @switch

2.7.1. Objectiu

Utilitzar @switch per gestionar múltiples opcions exclusives de manera clara.

2.7.2. Contingut

Quan usar @switch: no és una regla d'Angular sinó de llegibilitat: @switch normalment queda més clar que una cadena d'@if/@else if quan hi ha tres o més opcions mútuament exclusives sobre un mateix valor.

Sintaxi:

HTML 
@switch (estatLlista) {
  @case ('carregant') { <p>Carregant elements...</p> }
  @case ('error') { <p>Error en carregar</p> }
  @case ('buit') { <p>No hi ha elements</p> }
  @case ('disponible') { <p>Llista disponible</p> }
  @default { <p>Estat desconegut</p> }
}

Components:

  • @switch (valor): Expressió que selecciona el cas actiu
  • @case ('opcio'): Cas específic
  • @default: Cas per defecte quan cap cas coincideix

HTML 
<!-- Amb múltiples @if (menys clar) -->
@if (estat === 'carregant') {

<p>Error</p>
}
@if (estat === 'buit') {
<p>Buit</p>
}
@if (estat === 'disponible') {
<p>Disponible</p>
}

@switch (estat) {
  @case ('carregant') { <p>Carregant...</p> }
  @case ('error') { <p>Error</p> }
  @case ('buit') { <p>Buit</p> }
  @case ('disponible') { <p>Disponible</p> }
}
Èxit

2.8. Estats de la interfície: loading, empty, error, success

2.8.1. Objectiu

2.8.2. Contingut

Els 4 estats habituals:

  1. Carregant (loading): Dades en procés d'obtenció
  2. Buit (empty): No hi ha dades disponibles
  3. Error: Ha fallat l'obtenció de dades
  4. Disponible (success): Dades carregades correctament

Implementació amb tipus union:

TYPESCRIPT 
import { Component, signal } from '@angular/core';

type EstatLlista = 'carregant' | 'buit' | 'error' | 'disponible';

export class CatalegComponent {
  // Estat que canvia quan arriba una resposta asíncrona: signals
  estatLlista = signal<EstatLlista>('carregant');
  elements = signal<Element[]>([]);
  missatgeError = signal('');

  ngOnInit(): void {
    this.carregarElements();
  }

  carregarElements(): void {
    this.estatLlista.set('carregant');

    this.servei.obtenirElements().subscribe({
      next: (data) => {
        if (data.length === 0) {
          this.estatLlista.set('buit');
        } else {
          this.elements.set(data);
          this.estatLlista.set('disponible');
        }
      },
      error: (err) => {
        this.missatgeError.set('Error en carregar els elements');
        this.estatLlista.set('error');
      }
    });
  }
}

Una resposta HTTP o un temporitzador que assigni una propietat normal no repintaria la vista. Per això l'estat de càrrega es guarda en signals, es modifica amb .set() i es llegeix a la plantilla amb parèntesis: estatLlista(). Els signals s'expliquen a fons a la Unitat 3.

3.2. Marc conceptual

3.2.1. Què són els transformadors (pipes)

Els transformadors (pipes) són filtres de presentació que permeten formatar les dades que es mostren a la plantilla sense alterar les dades originals del component. Angular proporciona transformadors integrats (date, uppercase, lowercase, currency, percent, number, titlecase) que s'apliquen amb l'operador de canonada (|).

3.2.2. Problema sense transformadors

Imagineu que teniu un element del catàleg amb aquesta informació:

TYPESCRIPT 
export class App {
  elementsCataleg = [
    {
      id: 2,
      titol: 'Catàleg de colors corporatius',
      preu: 49.99,
      dataActualitzacio: '2025-01-15T10:00:00Z',
      categoria: 'paletes',
      percentatgeDisponibilitat: 0.85
    }
  ];
}

Voleu mostrar aquestes dades de manera llegible:

  • El preu 49.99 hauria de mostrar-se com 49,99 €
  • La data ISO hauria de ser 15 de gener de 2025
  • La categoria hauria d'aparèixer com PALETES
  • El percentatge 0.85 hauria de mostrar-se com 85%

Sense transformadors, heu de crear mètodes al component:

TYPESCRIPT 
// Component amb formatació manual - NO RECOMANAT
export class App {
  elementsCataleg = [/* ... */];

  formatarPreu(preu: number): string {
    return `${preu.toFixed(2).replace('.', ',')} €`;
  }

  formatarData(dataISO: string): string {
    const data = new Date(dataISO);
    const mesos = ['gener', 'febrer', 'març', /*...*/];
    return `${data.getDate()} de ${mesos[data.getMonth()]} de ${data.getFullYear()}`;
  }

  formatarCategoria(categoria: string): string {
    return categoria.toUpperCase();
  }

  formatarPercentatge(decimal: number): string {
    return `${Math.round(decimal * 100)}%`;
  }
}

Problemes que genera:

  • Barreja de responsabilitats: La classe conté lògica de presentació barrejada amb lògica de negoci.
  • Codi repetitiu: Si necessiteu formatar preus a diversos components, heu de copiar el mètode.
  • Rendiment degradat: Cridar mètodes a la plantilla provoca execucions en cada cicle de detecció de canvis.
  • Localització complicada: Adaptar formats a diferents idiomes requereix modificar manualment cada mètode.

HTML

  • Separació clara: La classe conté només dades i lògica de negoci.
  • Reutilitzable: Els transformadors es poden utilitzar en qualsevol plantilla.
  • Rendiment optimitzat: S'executen només quan canvia l'entrada (un valor primitiu diferent o una referència nova d'objecte/array; una mutació interna del mateix objecte no ho activa).
  • Localització automàtica: Respecten la configuració LOCALE_ID.

L'operador | s'utilitza per aplicar transformadors:

HTML 
{{ valor | transformador }}
{{ valor | transformador:param1:param2 }}

3.4. Què són els transformadors (pipes): filtres de presentació

3.4.1. Objectiu

Comprendre la funció i necessitat dels transformadors com a mecanisme de formatació declarativa.

3.4.2. Contingut

Els transformadors són eines de presentació que s'apliquen a les dades just abans de mostrar-les. Angular els proporciona com a classes independents amb un únic propòsit: formatar valors sense alterar-los.

Així funciona internament:

TYPESCRIPT 
@Pipe({ name: 'uppercase' })
export class UpperCasePipe implements PipeTransform {
  transform(value: string): string {
    return value.toUpperCase();
  }
}

Quan escriviu {{ 'hola' | uppercase }}, Angular:

  1. Detecta l'operador | i identifica el pipe uppercase
  2. Crida UpperCasePipe.transform('hola')
  3. Rep el resultat 'HOLA'
  4. Mostra HOLA al navegador

Transformadors integrats d'Angular:

  • date: formata dates i hores
  • currency: formata valors monetaris
  • percent: formata decimals com a percentatges
  • uppercase / lowercase: converteix text
  • number: formata números amb separadors
  • titlecase: primera lletra de cada paraula en majúscula
Èxit
Clau: Els transformadors són filtres de presentació que s'apliquen amb |, formatant dades sense modificar-les.

3.4.3. Resultat esperat

Enteneu què són els transformadors, per què existeixen, i com Angular els utilitza.

3.5. Sintaxi bàsica: operador de canonada |

3.5.1. Objectiu

Aprendre la sintaxi fonamental per aplicar transformadors a la plantilla.

3.5.2. Contingut

Sintaxi general:

HTML 
{{ valor | nomTransformador }}

Exemple amb uppercase:

HTML 
<p>{{ 'catàleg' | uppercase }}</p>
<!-- Mostra: CATÀLEG -->

Aplicar a diferents expressions:

HTML 
<!-- Propietat del component -->
<h3>{{ element.categoria | uppercase }}</h3>

<!-- Literal -->
<p>{{ 'text constant' | lowercase }}</p>

<!-- Resultat d'operació -->
<span>{{ element.preu * 1.21 | number:'1.2-2' }}</span>

Cada pipe té la seva classe: uppercase → UpperCasePipe, lowercase → LowerCasePipe, number → DecimalPipe. Per fer servir aquests tres exemples en un component caldria importar-los tots tres (vegeu més avall).

Transformadors amb paràmetres:

HTML 
{{ valor | transformador:param1:param2:param3 }}
HTML 
<!-- Exemple date amb format personalitzat -->
<p>{{ element.data | date:'dd/MM/yyyy' }}</p>
<!-- Mostra: 15/01/2025 -->

<!-- Exemple currency amb moneda -->
<p>{{ element.preu | currency:'EUR':'symbol':'1.2-2' }}</p>
<!-- Mostra: 49,99 € -->

Importar el transformador al component: en un component standalone, cada pipe integrat s'ha de declarar a l'array imports del decorador, igual que un component fill. Els pipes integrats viuen a @angular/common:

TYPESCRIPT 
import { Component } from '@angular/core';
import { CurrencyPipe, DatePipe, UpperCasePipe } from '@angular/common';

@Component({
  imports: [DatePipe, CurrencyPipe, UpperCasePipe],
  selector: 'app-targeta-element',
  styleUrl: './targeta-element.component.scss',
  templateUrl: './targeta-element.component.html',
})
export class TargetaElementComponent {
  // ...
}

Si un component fa servir molts pipes o directives de @angular/common (com NgClass), podeu importar CommonModule sencer en lloc de cada classe; és més curt, però menys explícit. Si oblideu la importació, Angular atura la compilació amb l'error NG8004: No pipe found with name 'date'.

Formats en català: els paràmetres de locale com 'ca' o 'ca-ES' només funcionen si abans s'han registrat les dades del locale. Es fa un sol cop, a app.config.ts:

TYPESCRIPT 
import { ApplicationConfig, LOCALE_ID, provideBrowserGlobalErrorListeners } from '@angular/core';
import { registerLocaleData } from '@angular/common';
import localeCa from '@angular/common/locales/ca';
import { provideRouter } from '@angular/router';
import { routes } from './app.routes';

registerLocaleData(localeCa);

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideRouter(routes),
    { provide: LOCALE_ID, useValue: 'ca' },
  ],
};

Amb LOCALE_ID configurat, date, currency, number i percent ja formaten en català sense haver de passar el locale a cada crida.

Èxit
Clau: L'operador | aplica transformadors; els paràmetres es passen amb : després del nom. Cada pipe s'ha d'importar al component que l'utilitza.

3.10. Limitacions: no modifiquen dades originals

3.10.1. Objectiu

Comprendre que els transformadors NO modifiquen les dades originals.

3.10.2. Contingut

Exemple demostratiu:

TYPESCRIPT 
export class App {
  preu = 49.99;
}
HTML

<p>Original de nou: {{ preu }}</p>       <!-- 49.99 (no canvia!) -->

Implicacions:

  • Els transformadors són només per presentació
  • Les dades al component segueixen en format original
  • Si necessiteu modificar les dades, feu-ho al component, NO amb pipes

Quan NO usar transformadors:

  • Càlculs complexos que necessiten resultat persistent
  • Transformacions que s'han de guardar a base de dades
  • Lògica de negoci (utilitzeu getters o mètodes al component)
Èxit
Clau: Els transformadors són una capa de presentació. Les dades originals NO canvien mai.

3.11. Quan crear transformadors personalitzats

3.11.1. Objectiu

Entendre quan crear transformadors personalitzats (visió general).

3.11.2. Contingut

Crear un transformador personalitzat quan:

  • Necessiteu una formatació específica del vostre domini (ex: format DNI, codi postal)
  • Els transformadors integrats no cobreixen la vostra necessitat
  • Teniu lògica de formatació repetida en múltiples components

Exemple conceptual (NO implementar ara):

TYPESCRIPT 
// Generat amb: ng generate pipe pipes/dni
import { Pipe, PipeTransform } from '@angular/core';

@Pipe({ name: 'dni' })
export class DniPipe implements PipeTransform {
  transform(value: string): string {
    // 12345678Z → 12.345.678-Z
    return value.replace(/(\d{2})(\d{3})(\d{3})(\w)/, '$1.$2.$3-$4');
  }
}
HTML 
<!-- Ús -->
<p>DNI: {{ client.dni | dni }}</p>

Com qualsevol pipe, el personalitzat també s'ha d'afegir a imports del component que el faci servir: imports: [DniPipe].

Criteris per decidir:

Situació Solució
Format estàndard (data, moneda) Usar transformador integrat
Format específic domini (DNI, matrícula) Crear transformador personalitzat
Càlcul complex amb estat Usar getter al component
