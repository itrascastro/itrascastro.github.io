Introducció

En aquest cas d'ús pràctic, integrareu tots els conceptes treballats a la Unitat 1 per preparar l'entorn complet de desenvolupament Angular. Configurareu les eines necessàries, creareu el vostre primer projecte i el publicareu a GitHub, establint així les bases per a tot el curs.

Aquest cas d'ús representa un flux de treball realista que us permetrà aplicar els coneixements adquirits sobre instal·lació d'eines, configuració de l'entorn, generació de projectes i control de versions en un context integrat.

Objectius

En finalitzar aquest cas d'ús, hauríeu de ser capaços de:

  • Verificar i configurar l'entorn tècnic complet (Node.js, npm, Angular CLI, VS Code, Git)
  • Generar el projecte base ioc-angular-[nom-app]-[nom-alumne] amb Angular 22 i estructura funcional
  • Validar servidor de desenvolupament amb hot reload operatiu
  • Publicar el projecte a GitHub amb main i les branques ra1-setup, ra2-components, ra3-serveis i ra4-navegacio
  • Documentar el procés i preparar el projecte per a les següents unitats

Criteris d'avaluació (RA1)

Aquest cas d'ús cobreix els següents criteris del Resultat d'Aprenentatge 1:

  • RA1.1: Identifica les eines imprescindibles i comprova que compleixen els requisits del sistema
  • RA1.2: Instal·la i configura l'entorn de desenvolupament amb les eines i dependències necessàries
  • RA1.3: Crea l'estructura base del projecte organitzant carpetes i fitxers de manera coherent
  • RA1.4: Configura els fitxers d'execució i comprova que l'entorn arrenca correctament
  • RA1.5: Verifica el funcionament global amb proves o exemples senzills

4. Configuració Git i GitHub

4.1. Objectiu

Configurar Git amb identitat global i crear compte GitHub funcional per al control de versions remot.

4.2. Context d'integració

Aplica conceptes de Lectures 1.2.2 (Git local) i 1.2.3 (GitHub remot).

4.3. Pas 1: Configurar identitat Git

BASH 
# Configuració global
git config --global user.name "El Vostre Nom"
git config --global user.email "el.vostre.email@example.com"

# Verificar configuració
git config --global --list

Verificació:

BASH 
git config --global user.name
git config --global user.email

Resultat: Mostra el vostre nom i email.

4.4. Pas 2: Crear repositori de prova local

BASH 
# Linux/macOS
cd ~/workspace
mkdir prova-git && cd prova-git
git init

# Windows PowerShell
Set-Location $env:USERPROFILE\workspace
New-Item -ItemType Directory -Name prova-git
Set-Location prova-git
git init

Crear fitxer de prova:

BASH 
echo "# Repositori de prova Git" > README.md
git add README.md
git commit -m "feat: afegir README inicial"

Verificació:

BASH 
git log --oneline

Resultat: Mostra 1 commit amb el missatge "feat: afegir README inicial".

4.5. Pas 3: Crear compte GitHub

  1. Aneu a https://github.com/signup
  2. Completeu registre amb email, contrasenya i nom d'usuari
  3. Verifiqueu el correu electrònic (reviseu safata d'entrada i spam)

Verificació: Inicieu sessió a https://github.com i veieu el vostre perfil.

4.6. Pas 4: Crear repositori remot de prova

  1. A GitHub, cliqueu New repository (botó verd dalt a la dreta)
  2. Repository name: prova-git
  3. Description: "Repositori de prova per verificar Git i GitHub"
  4. Deixeu Public seleccionat
  5. NO marqueu "Add a README file" (ja el teniu)
  6. Cliqueu Create repository

Connectar local amb remot:

BASH 
# Des de ~/workspace/prova-git (o %USERPROFILE%\workspace\prova-git)
git remote add origin https://github.com/EL-VOSTRE-USUARI/prova-git.git
git branch -M main
git push -u origin main

Si demana credencials:

  • Username: el vostre usuari GitHub
  • Password: token d'accés personal (PAT); GitHub ja no accepta la contrasenya del compte

Verificació: Aneu a https://github.com/EL-VOSTRE-USUARI/prova-git i veieu el README.md publicat.

4.7. Troubleshooting

Problema Causa Solució
git: command not found Git no instal·lat Linux: sudo apt install git. macOS: brew install git. Windows: Descarregueu des de https://git-scm.com.
Email no verificat a GitHub No heu clicat l'enllaç Reviseu la safata d'entrada i spam. Reenviï l'email des de GitHub si cal.
git push demana credencials contínuament HTTPS sense cache Configureu cache: git config --global credential.helper cache (Linux/macOS) o git config --global credential.helper manager (Windows).
Error remote: Permission denied Credencials incorrectes Inicieu sessió amb Git Credential Manager o creeu un token PAT fine-grained (Settings → Developer settings → Personal access tokens → Fine-grained tokens) i utilitzeu-lo com a contrasenya.

4.8. Checkpoint

Git configurat amb nom i email globals
Repositori local prova-git inicialitzat amb 1 commit
Compte GitHub creat i email verificat
Repositori remot prova-git creat a GitHub
git push funciona i README.md és visible a GitHub

5. Generació del projecte Angular

5.1. Objectiu

Generar el projecte del mòdul amb Angular 22, seguint el patró de nom ioc-angular-[nom-app]-[nom-alumne], i deixar-lo amb l'estructura de carpetes preparada per a les unitats següents.

5.2. Context d'integració

Aplica conceptes de Lectures 1.3.1 (Angular CLI) i 1.3.2 (estructura projecte).

5.3. Pas 1: Triar el nom del projecte

El nom segueix el patró ioc-angular-[nom-app]-[nom-alumne], tot en minúscules, sense accents ni espais i amb guions com a separador. Per exemple, si l'aplicació és un catàleg i l'alumna es diu Maria Soler, el nom és ioc-angular-cataleg-maria-soler. A partir d'ara, substituïu ioc-angular-[nom-app]-[nom-alumne] pel vostre nom real a totes les comandes.

5.4. Pas 2: Generar projecte amb ng new

BASH 
# Linux/macOS
cd ~/workspace
ng new ioc-angular-[nom-app]-[nom-alumne] --routing --style=scss --ssr=false --standalone=true --file-name-style-guide=2016 --skip-git=true --package-manager=npm

# Windows PowerShell
Set-Location $env:USERPROFILE\workspace
ng new ioc-angular-[nom-app]-[nom-alumne] --routing --style=scss --ssr=false --standalone=true --file-name-style-guide=2016 --skip-git=true --package-manager=npm

Què fixa cada flag:

Flag Efecte
--routingCrea app.routes.ts i registra el Router a app.config.ts.
--style=scssEls fulls d'estil dels components són .scss.
--ssr=falseSense renderització al servidor: aplicació només de client, sense fitxers de servidor.
--standalone=trueComponents standalone (és el valor per defecte, però així queda explícit).
--file-name-style-guide=2016Els fitxers es diuen app.component.ts, app.component.html i app.component.scss, no app.ts.
--skip-git=trueNo inicialitza Git: ho fareu manualment a la secció 6 per controlar el primer commit.
--package-manager=npmInstal·la i registra npm com a gestor de paquets del projecte.

Espera: La instal·lació de dependències pot trigar 3-5 minuts. Anoteu la comanda exacta que heu executat: la necessitareu per al README.

Verificació:

BASH 
cd ioc-angular-[nom-app]-[nom-alumne]
ls -la    # Linux/macOS
dir       # Windows

Resultat: Veieu les carpetes src/, public/ i node_modules/, i els fitxers angular.json, package.json, tsconfig.json, .gitignore i README.md, entre d'altres. No hi ha cap carpeta .git/: és el resultat esperat de --skip-git=true.

5.5. Pas 3: Explorar estructura generada

Obriu el projecte a VS Code:

BASH 
code .

Carpetes principals:

  • src/app/ → Components i codi de l'aplicació
  • public/ → Recursos estàtics (imatges, fonts, favicon.ico); en versions antigues d'Angular aquesta carpeta era src/assets/
  • node_modules/ → Dependències npm (NO pujar a Git)

Fitxers clau:

  • angular.json → Configuració Angular CLI (aquí queda registrat que els components es generen amb estil SCSS i noms *.component.*)
  • package.json → Dependències i scripts npm
  • tsconfig.json → Configuració TypeScript
  • .gitignore → Fitxers exclosos de Git (ja inclou /node_modules, /dist i /.angular/cache)
  • src/app/app.component.ts → Component arrel. Amb Angular 22 la classe generada es diu App, tot i que el fitxer conserva el nom app.component.ts
  • src/app/app.config.ts → Configuració global de l'aplicació (proveïdors, entre ells provideRouter(routes))
  • src/app/app.routes.ts → Mapa de rutes, de moment buit
  • src/main.ts → Punt d'entrada: bootstrapApplication(App, appConfig)

Obriu src/app/app.component.ts i observeu el contingut generat:

TYPESCRIPT 
import { Component, signal } from '@angular/core';
import { RouterOutlet } from '@angular/router';

@Component({
  imports: [RouterOutlet],
  selector: 'app-root',
  styleUrl: './app.component.scss',
  templateUrl: './app.component.html',
})
export class App {
  protected readonly title = signal('ioc-angular-[nom-app]-[nom-alumne]');
}

Fixeu-vos que el decorador no porta standalone: true: des d'Angular 19 tots els components són standalone per defecte. Tampoc no hi ha cap app.module.ts.

Verificació: A VS Code, l'explorador lateral mostra totes aquestes carpetes i fitxers.

5.9. Troubleshooting

Problema Causa Solució
ng new falla amb error de permisos Permisos insuficients Linux/macOS: NO useu sudo. Canvieu ownership: sudo chown -R $USER:$USER ~/workspace. Windows: Executeu PowerShell com a administrador.
npm ERR! network durant instal·lació Connexió internet Verifiqueu connexió. Proveu npm config set registry https://registry.npmjs.org/.
Instal·lació triga més de 10 minuts npm lent o cache corrupte Cancel·leu (Ctrl+C), esborreu la carpeta creada a mitges i proveu npm cache clean --force abans de tornar a executar ng new.
Els fitxers es diuen app.ts i app.html Falta --file-name-style-guide=2016 Esborreu la carpeta i torneu a executar la comanda completa. Angular 22 genera noms curts si no s'indica aquest flag.
Apareix una carpeta .git/ o server.ts Falta --skip-git=true o --ssr=false Esborreu la carpeta i torneu a executar la comanda completa amb tots els flags.
Carpetes preparatòries no es veuen a Git Carpetes buides Assegureu-vos que .gitkeep està dins de cada carpeta buida.

6. Control de versions i publicació del projecte base

6.1. Objectiu

Inicialitzar Git al projecte, fer el primer commit amb el projecte base net, publicar-lo en un repositori públic de GitHub amb totes les branques del mòdul i situar-se a ra1-setup per treballar-hi.

6.2. Context d'integració

Aplica conceptes de Lectures 1.2.2 (Git local) i 1.2.3 (GitHub remot). L'ordre és important: primer es publica el projecte base a main i es creen les branques; només després es personalitza l'aplicació a ra1-setup. Així main i les branques futures queden netes.

6.3. Pas 1: Inicialitzar repositori Git

BASH 
# Des de l'arrel del projecte ioc-angular-[nom-app]-[nom-alumne]/
git init
git branch -M main

Si a la secció 4 no vau configurar la identitat global, o voleu una identitat només per a aquest projecte, feu-ho ara sense --global:

BASH 
git config user.name "Nom Cognom"
git config user.email "correu-vinculat-a-github@example.com"

Verificació:

BASH 
git status

Resultat: Mostra On branch main i tots els fitxers com "Untracked files". No hi apareix node_modules/, perquè el .gitignore generat ja l'exclou.

6.4. Pas 2: Primer commit amb el projecte base

BASH 
git add .
git status
git commit -m "chore: crear projecte Angular base"

Verificació:

6.10. Troubleshooting

Problema Causa Solució
git push falla amb error 403 Credencials incorrectes Inicieu sessió amb Git Credential Manager o creeu un token PAT fine-grained (Settings → Developer settings → Personal access tokens → Fine-grained tokens) limitat al vostre repositori amb Contents: Read and write, i useu-lo com a contrasenya.
git remote add diu "remote origin already exists" Remote ja configurat Elimineu-lo amb git remote remove origin i torneu a afegir-lo amb l'URL correcta.
Error "updates were rejected" El repositori remot no estava buit (README o llicència creats des de GitHub) Esborreu el repositori a GitHub i torneu-lo a crear sense cap fitxer, o bé feu git pull --rebase origin main abans de tornar a publicar.
Fitxers molt grans o push lentíssim node_modules/ sense ignorar Verifiqueu que .gitignore conté /node_modules. Si ja s'ha afegit, elimineu-lo de l'índex: git rm -r --cached node_modules i torneu a fer commit.
Una branca futura conté canvis que no hi haurien de ser S'ha creat després de modificar fitxers Situeu-vos a la branca i igualeu-la a main: git switch ra2-components, git reset --hard main, git push --force-with-lease origin ra2-components. Torneu a ra1-setup.
El commit surt amb un autor incorrecte Identitat no configurada Configureu git config user.name i git config user.email al projecte i refeu el commit amb git commit --amend --reset-author --no-edit.

Problema Causa Solució
Port 4200 is already in use Servidor previ executant-se Atureu l'altre servidor amb Ctrl+C al seu terminal, o arrenqueu-ne un altre en un port lliure: ng serve --port 4201 i obriu http://localhost:4201.
Hot reload no funciona Watch mode no detecta canvis (unitats de xarxa, carpetes sincronitzades) Atureu el servidor (Ctrl+C) i proveu: ng serve --poll=2000.
Canvis HTML no es reflecteixen Cache del navegador Premeu Ctrl+Shift+R (hard refresh) al navegador.
Error NG8113 o avís d'import no utilitzat S'ha esborrat <router-outlet /> però es manté RouterOutlet a imports Torneu a posar <router-outlet /> al final de la plantilla.
Error de compilació per title() La plantilla generada encara fa servir la propietat title Substituïu tot el contingut de app.component.html per la plantilla nova, no només una part.
Els canvis han anat a parar a main No s'ha fet git switch ra1-setup Si encara no heu fet commit: git stash, git switch ra1-setup, git stash pop. Si ja hi ha commit a main: git switch ra1-setup, git merge main, i després git switch main, git reset --hard origin/main.
