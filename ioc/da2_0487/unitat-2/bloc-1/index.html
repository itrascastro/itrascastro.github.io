1. Programa, dades i maquinari

Un programa informàtic és una seqüència d'instruccions que l'ordinador executa sobre unes dades. La idea és molt semblant a una recepta: no n'hi ha prou amb tenir els ingredients; cal indicar quines operacions s'han de fer i en quin ordre.

Quan executeu un programa, hi intervenen diverses peces del sistema:

PeçaPaper simplificatExemple
EmmagatzematgeConserva el programa i les dades quan no s'estan utilitzant.SSD amb el fitxer .jar.
Memòria RAMManté codi i dades que s'estan utilitzant en aquell moment.Variables i objectes de l'aplicació.
ProcessadorExecuta les instruccions que finalment arriben en un format que pot processar.Operacions aritmètiques, salts i comparacions.
PerifèricsPermeten entrada i sortida d'informació.Teclat, pantalla, xarxa, disc.
Informació

Idea clau

El fitxer que heu programat no «fa coses» tot sol. Cal carregar-lo i executar-lo en un entorn capaç de convertir les seves instruccions en operacions que el maquinari pugui dur a terme.

Un programa mínim

JAVA Hola.java 
public class Hola {
    public static void main(String[] args) {
        String nom = "Ada";
        System.out.println("Hola, " + nom);
    }
}

El codi conté una dada (nom) i dues accions: construir una cadena i enviar-la a la sortida. El processador no entén directament aquestes línies Java; abans caldrà traduir-les.

Exercici: Ordres i dades
Penseu en una calculadora que llegeix dos nombres i mostra la suma. Separeu en dues llistes les dades que necessita i les ordres que ha d'executar.
Bàsic 5 min
Veure pistes
  • Les dades són els valors que canvien.
  • Les ordres indiquen què fem amb aquests valors.

2. Codi font, codi objecte i executable

Quan escrivim un programa en un llenguatge d'alt nivell obtenim codi font. És text pensat perquè el programador el pugui llegir i modificar. El processador, en canvi, necessita instruccions molt més properes al llenguatge màquina.

Definició

Codi font: Conjunt de fitxers de text que contenen les instruccions escrites en un llenguatge de programació.

Definició

Codi objecte: Resultat de traduir el codi font a una representació de nivell més baix. En un procés de compilació nadiu encara pot necessitar l'enllaçament amb altres peces abans de ser executable.

Definició

Codi executable: Programa ja preparat perquè el sistema d'execució corresponent el pugui posar en marxa.

Què fa una biblioteca?

Una biblioteca és codi ja escrit que podem reutilitzar. Quan un programa crida funcionalitats que no hem implementat nosaltres, el procés de construcció ha de saber on trobar-les i com incorporar-les o referenciar-les.

Per exemple, si una aplicació en C utilitza una funció d'una biblioteca gràfica, el compilador pot generar codi objecte correctament, però l'enllaçador ha de resoldre la referència a aquella funció per obtenir el programa final.

Important

No confongueu «codi objecte» amb «programació orientada a objectes». Són conceptes diferents. Aquí «objecte» descriu una etapa de traducció del programa, no una instància d'una classe.

Exercici: Ordena la cadena
Ordeneu aquests elements en un procés de compilació nativa: executable, codi font, enllaçador, codi objecte, compilador i biblioteques.
Bàsic 5 min
Veure pistes
  • El programador escriu el primer element.
  • Les biblioteques entren en joc abans d'obtenir el resultat final.

3. Compilar, interpretar i enllaçar

Hi ha diverses maneres de passar d'un llenguatge d'alt nivell a instruccions executables. Per al mòdul convé distingir tres funcions:

Eina o procésQuè fa?Moment principal
CompiladorTradueix el programa a una representació de nivell més baix abans d'executar-lo.Construcció.
EnllaçadorUneix codi objecte i resol les referències a biblioteques per formar el programa final.Després de compilar, en el model nadiu clàssic.
IntèrpretLlegeix i executa instruccions a través d'un programa intermedi durant l'execució.Execució.

Un exemple tradicional de llenguatge interpretat és JavaScript. En canvi, C o C++ s'utilitzen habitualment en processos de compilació nativa. Java combina idees dels dos mons: primer compila a bytecode i després la JVM s'encarrega d'executar-lo.

Informació

Model del material oficial

Per resoldre les preguntes conceptuals del mòdul, feu servir aquesta distinció: el compilador tradueix abans de l'execució; l'intèrpret tradueix/executa a temps d'execució. Els entorns moderns poden incorporar tècniques híbrides, però aquesta classificació és la que permet entendre el procés.

Error de compilació o error d'execució?

JAVA 
int edat = "vint";       // incompatibilitat de tipus: el compilador ho detecta

int divisor = 0;
int resultat = 10 / divisor;  // el codi pot compilar, però falla en executar-se

Aquesta diferència serà important quan treballem amb l'IDE: un bon entorn ens ajuda tant a detectar errors abans d'executar com a diagnosticar què passa quan el programa ja està en marxa.

Exercici: Compilació o execució?
Classifiqueu tres situacions: falta un punt i coma; s'intenta dividir per zero; es crida una funció d'una biblioteca que no s'ha incorporat correctament.
Bàsic 7 min
Veure pistes
  • La sintaxi es comprova abans d'executar.
  • Un valor problemàtic pot aparèixer només durant l'execució.
  • Les referències externes formen part del procés de construcció.

4. Java, bytecode i màquina virtual

Java no acostuma a generar directament un executable nadiu específic per a Windows, Linux o macOS. El compilador javac transforma el fitxer .java en bytecode, emmagatzemat habitualment en fitxers .class.

SiglaQuè representa?Què ens interessa retenir?
JVMJava Virtual Machine.Executa el bytecode en una plataforma concreta.
JREJava Runtime Environment.Concepte d'entorn d'execució: JVM més recursos necessaris per executar Java.
JDKJava Development Kit.Eines de desenvolupament, inclòs el compilador i l'entorn necessari per treballar amb Java.

Proveu el recorregut sense IDE

BASH 
javac Hola.java
java Hola

La primera ordre genera el bytecode. La segona demana a la JVM que carregui i executi la classe. Eclipse automatitza aquests passos, però entendre'ls evita que l'IDE sembli màgia.

Èxit

Portabilitat

La idea essencial de la JVM és separar el programa Java de la plataforma física. El programa s'adreça a una màquina virtual comuna; cada sistema operatiu disposa de la seva implementació de la JVM.

Exercici: Segueix un Hola.java
Dibuixeu amb quatre caixes el recorregut de Hola.java fins que es veu el text a la pantalla d'un ordinador Linux. Indiqueu on apareixen javac, el fitxer .class i la JVM.
Bàsic 8 min
Veure pistes
  • El compilador genera bytecode.
  • La JVM és específica de la plataforma.

5. Generacions de llenguatges de programació

El material oficial utilitza una classificació històrica per generacions. És útil per entendre com els llenguatges s'han anat allunyant de la màquina i apropant al problema que vol resoldre el programador.

GeneracióIdea principalExemple o pista
1aLlenguatge màquina.Instruccions binàries directament lligades al processador.
2aAssemblador.Mnemotècnics com MOV, molt propers a l'arquitectura.
3aLlenguatges d'alt nivell.C, C++, Java, Pascal en la classificació del material.
4aLlenguatges o eines de propòsit específic i alt nivell d'abstracció.Orientats a resoldre dominis concrets amb menys codi.
5aLlenguatges associats històricament a lògica, IA i sistemes experts.Prolog o Lisp apareixen en aquesta classificació del material.
Important

No interpreteu «cinquena generació» com «més modern». És una classificació històrica del material didàctic. Una versió nova de Java no passa a ser automàticament d'una generació diferent.

Per a una pregunta ràpida, fixeu-vos sobretot en la pista: binari → 1a, mnemotècnics → 2a, alt nivell → 3a.

Exercici: Classifica per la pista
Classifiqueu quatre fragments: 10110000 01100001; MOV AX,1; public class Client; una regla lògica del tipus pare(X,Y). Justifiqueu cada resposta amb una sola paraula clau.
Bàsic 6 min
Veure pistes
  • No cal conèixer el programa sencer.
  • Busqueu binari, mnemotècnic, sintaxi d'alt nivell o regla.
