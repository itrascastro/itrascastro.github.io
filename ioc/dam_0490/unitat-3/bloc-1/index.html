1. Què vol dir protegir una aplicació

Dir que una aplicació és "segura" és massa imprecís. Abans de triar cap algorisme hem de saber què volem protegir i contra quin problema. Una mateixa dada pot necessitar diferents garanties.

ObjectiuPreguntaExemple
ConfidencialitatQui pot llegir la informació?Un tercer no ha de poder llegir una contrasenya capturada a la xarxa.
IntegritatLa informació ha canviat?Volem detectar si algú ha modificat un fitxer després de desar-lo.
AutenticacióQui és l'usuari o el servidor?Un client demostra la seva identitat amb unes credencials.
AutoritzacióQuè pot fer aquesta identitat?Un usuari autenticat pot consultar dades però només un administrador pot eliminar-les.
Figura

Una dada, quatre preguntes

Imagineu un fitxer amb una comanda de transport:

TEXT 
comanda.txt
------------
client=ACME
destinacio=Girona
paquets=12

Podem fer preguntes diferents sobre el mateix fitxer:

  • Si ningú més l'ha de llegir, necessitem confidencialitat.
  • Si volem detectar canvis en paquets=12, necessitem integritat.
  • Si el fitxer arriba per xarxa i volem saber qui l'ha enviat, necessitem autenticitat.
  • Si alguns usuaris poden consultar-lo però no modificar-lo, necessitem autorització.
Informació

Idea clau

No comenceu preguntant "quin algorisme faig servir?". Comenceu preguntant "què pot anar malament?". La resposta determina si necessiteu hash, xifrat, autenticació, permisos o una combinació de mecanismes.

Exercici: Classifiqueu el problema
Per a quatre situacions, indiqueu quin objectiu és prioritari: una còpia de seguretat modificada sense permís, una contrasenya enviada per una Wi-Fi pública, un usuari que intenta executar una opció d'administració i un client que diu ser una persona concreta.
Bàsic 8 min
Veure pistes
  • No cal programar.
  • Una situació pot necessitar més d'un objectiu.
  • Distingiu especialment autenticació d'autorització.

2. Bytes, text i Base64: representar no és xifrar

La criptografia treballa amb bytes. Les persones, en canvi, treballem millor amb text. Per passar d'un món a l'altre hem de ser explícits amb la codificació.

JAVA 
import java.nio.charset.StandardCharsets;

String text = "Hola";
byte[] bytes = text.getBytes(StandardCharsets.UTF_8);

String recuperat =
        new String(bytes, StandardCharsets.UTF_8);

System.out.println(recuperat); // Hola

Quan els bytes poden contenir qualsevol valor, imprimir-los directament no és útil. Base64 transforma bytes en caràcters fàcils de transportar en protocols de text.

JAVA Base64Demo.java 
import java.nio.charset.StandardCharsets;
import java.util.Base64;

public class Base64Demo {

    public static void main(String[] args) {
        String original = "alice:s3cr3t";

        String codificat = Base64.getEncoder()
                .encodeToString(
                        original.getBytes(StandardCharsets.UTF_8)
                );

        System.out.println(codificat);

        String recuperat = new String(
                Base64.getDecoder().decode(codificat),
                StandardCharsets.UTF_8
        );

        System.out.println(recuperat);
    }
}
Figura

Codificar, resumir i xifrar no són el mateix

OperacióEs pot invertir?Necessita clau?Per a què serveix?
Base64Sí, directamentNoRepresentar bytes com a text.
Hash criptogràficNo de manera pràcticaNoObtenir una empremta de les dades.
XifratSí, amb la clau adequadaSíOcultar el contingut a qui no té la clau.
Problema

Error conceptual molt habitual: "He passat la contrasenya a Base64, per tant ja està xifrada". Qualsevol que rebi el text Base64 el pot decodificar immediatament. Base64 resol un problema de representació, no de seguretat.

El byte NUL també és una dada

Alguns protocols defineixen camps separats pel byte zero, representat a Java com \0 o \u0000. Base64 és útil precisament perquè permet transportar una seqüència que conté aquests bytes dins d'una línia de text.

JAVA 
String dades = "\0alice\0s3cr3t";

String token = Base64.getEncoder()
        .encodeToString(
                dades.getBytes(StandardCharsets.UTF_8)
        );

System.out.println(token);
Exercici: Mireu què amaga Base64
Codifiqueu tres textos diferents en Base64 i torneu-los a decodificar. Afegiu després un byte NUL entre dues paraules i comproveu que el cicle continua recuperant exactament la mateixa cadena.
Bàsic 10 min
Veure pistes
  • Useu UTF-8 explícitament.
  • Imprimiu també la longitud de la cadena abans i després.
  • La mida del text Base64 no coincideix amb la mida original.

3. Hash criptogràfic i SHA-256 amb MessageDigest

Una funció hash criptogràfica transforma una entrada de mida arbitrària en un resum de mida fixa. Amb SHA-256, el resum sempre té 256 bits, és a dir, 32 bytes.

Definició

Hash criptogràfic: Empremta de mida fixa calculada a partir d'unes dades. La mateixa entrada produeix el mateix resum i un canvi petit a l'entrada produeix normalment un resultat molt diferent.

Per calcular un hash a Java utilitzem MessageDigest:

JAVA PrimerHash.java 
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;

public class PrimerHash {

    static String sha256(String text) throws Exception {

        MessageDigest md =
                MessageDigest.getInstance("SHA-256");

        byte[] resum = md.digest(
                text.getBytes(StandardCharsets.UTF_8)
        );

        StringBuilder hex = new StringBuilder();

        for (byte b : resum) {
            hex.append(
                    String.format("%02x", b & 0xff)
            );
        }

        return hex.toString();
    }

    public static void main(String[] args)
            throws Exception {

        System.out.println(sha256("hola"));
        System.out.println(sha256("Hola"));
    }
}

El resultat en hexadecimal ocupa 64 caràcters perquè cada byte es representa amb dos dígits hexadecimals.

Figura

Què podem deduir d'un hash?

  • Si dues còpies tenen el mateix SHA-256, tenim una evidència molt forta que contenen els mateixos bytes.
  • Si els resums són diferents, les dades són diferents.
  • El hash no permet recuperar el text original.
  • El hash no oculta si una contrasenya candidata és correcta: podem calcular-ne el resum i comparar-lo.
Important

MD5 i SHA-1 no són una bona elecció per a integritat criptogràfica moderna. Presenten debilitats de col·lisions conegudes. Per als exemples de la unitat utilitzarem SHA-256.

AlgorismeMida del resumSituació criptogràficaÚs per verificar integritat
MD5128 bitsLes col·lisions es poden construir de manera pràctica.No és adequat quan hi pot haver manipulació intencionada.
SHA-1160 bitsTambé té col·lisions pràctiques conegudes.No s'ha d'escollir per a nou codi de seguretat.
SHA-256256 bitsNo es coneixen atacs pràctics de col·lisió comparables.És una opció adequada per obtenir una empremta criptogràfica.

Això explica per què substituir SHA-256 per MD5 només perquè "també genera un hash" no és una decisió equivalent. Tots dos detecten canvis accidentals, però la resistència davant d'una manipulació deliberada és molt diferent.

Hash de bytes, no només de Strings

Un fitxer pot ser una imatge, un ZIP o qualsevol altre conjunt de bytes. En aquest cas no cal convertir-lo a text:

JAVA 
import java.nio.file.Files;
import java.nio.file.Path;
import java.security.MessageDigest;

static String sha256(Path fitxer) throws Exception {

    byte[] dades = Files.readAllBytes(fitxer);

    MessageDigest md =
            MessageDigest.getInstance("SHA-256");

    byte[] resum = md.digest(dades);

    StringBuilder hex = new StringBuilder();

    for (byte b : resum) {
        hex.append(String.format("%02x", b & 0xff));
    }

    return hex.toString();
}
Exercici: Un byte, un altre hash
Calculeu el SHA-256 d'un fitxer de text. Canvieu una sola lletra, torneu a calcular-lo i compareu els dos resums. Després restaureu exactament el contingut original.
Bàsic 12 min
Veure pistes
  • No compareu només els primers caràcters.
  • Comproveu que el resum torna al valor inicial quan restaureu els mateixos bytes.
  • Proveu també amb un fitxer buit.

4. Verificar la integritat d'un fitxer

Calcular un hash és útil, però per detectar una modificació futura hem de conservar una referència fiable. Un patró senzill és desar el fitxer i, al costat, un segon fitxer amb el resum esperat.

Figura
TEXT 
mailbox/
  1712150000001.txt
  1712150000001.txt.hash
  1712150000002.txt
  1712150000002.txt.hash

Desar dades i resum

JAVA 
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

static void desarAmbHash(
        Path fitxer,
        String contingut) throws Exception {

    Files.writeString(
            fitxer,
            contingut,
            StandardCharsets.UTF_8
    );

    String hash = sha256(fitxer);

    Path fitxerHash =
            Path.of(fitxer.toString() + ".hash");

    Files.writeString(
            fitxerHash,
            hash,
            StandardCharsets.US_ASCII
    );
}

Verificar més tard

JAVA 
static boolean verificar(Path fitxer)
        throws Exception {

    Path fitxerHash =
            Path.of(fitxer.toString() + ".hash");

    if (!Files.exists(fitxer)
            || !Files.exists(fitxerHash)) {
        return false;
    }

    String esperat = Files.readString(
            fitxerHash,
            StandardCharsets.US_ASCII
    ).trim();

    String actual = sha256(fitxer);

    return actual.equalsIgnoreCase(esperat);
}

La funció no necessita saber què significa el contingut del fitxer. Només compara dues empremtes.

Verificar una carpeta completa

JAVA 
try (var fitxers = Files.list(Path.of("mailbox"))) {

    for (Path fitxer : fitxers
            .filter(p -> p.toString().endsWith(".txt"))
            .toList()) {

        boolean correcte = verificar(fitxer);

        System.out.printf(
                "%s %s%n",
                correcte ? "[OK]" : "[ALERTA]",
                fitxer.getFileName()
        );
    }
}
Important

Un fitxer .hash al mateix directori no és una defensa completa contra un atacant amb control total de la carpeta. Si pot modificar el fitxer i també substituir el hash de referència, pot fer que tornin a coincidir. El patró és perfecte per aprendre verificació d'integritat; per obtenir autenticitat cal protegir la referència o utilitzar mecanismes com HMAC o signatures digitals.

Exercici: Detector de canvis
Creeu una carpeta amb tres fitxers i el seu SHA-256 de referència. Modifiqueu només un dels fitxers i feu un verificador que mostri quants continuen correctes i quants han canviat.
Mitjà 20 min
Veure pistes
  • Filtreu només els fitxers de dades, no els .hash.
  • Controleu també què passa si falta el fitxer de resum.
  • Manteniu separades les funcions calcular, desar i verificar.

5. Contrasenyes: del text pla al resum segur

Guardar una contrasenya en text pla converteix una filtració de la base de dades en una filtració immediata de totes les contrasenyes. Una primera millora conceptual és guardar una verificació en lloc del secret original.

JAVA 
Map<String, String> usuaris = Map.of(
    "anna", sha256("clau-demo-1"),
    "pol",  sha256("clau-demo-2")
);

String hashRebut = sha256(contrasenyaRebuda);

boolean correcte =
        hashRebut.equals(usuaris.get(usuari));

El servidor no necessita recuperar la contrasenya original. Quan arriba una candidata, calcula la mateixa transformació i compara els resultats.

Figura

Per què un SHA-256 simple no és suficient en producció?

SHA-256 és molt ràpid. Aquesta és una virtut per comprovar fitxers, però una debilitat per a contrasenyes: un atacant pot provar enormes quantitats de candidates per segon. A més, si dues persones utilitzen la mateixa contrasenya, un hash simple produeix el mateix resultat.

ÚsMecanisme didàcticPràctica real recomanada
Integritat d'un fitxerSHA-256SHA-256 és adequat per calcular una empremta.
ContrasenyaSHA-256 permet entendre el patró de verificacióFunció específica de derivació de contrasenyes amb salt i cost, com Argon2, bcrypt, scrypt o PBKDF2.
Informació

Separeu el concepte de l'algorisme.

El concepte que ens interessa ara és "no guardar la contrasenya original i verificar una candidata". Als exemples petits podem observar aquest patró amb SHA-256. En una aplicació real no s'ha de dissenyar un sistema de contrasenyes nou basat només en un hash ràpid.

Comparació segura del flux complet

TEXT 
1. L'usuari escriu la contrasenya.
2. El client l'envia pel canal protegit.
3. El servidor calcula la derivació corresponent.
4. El servidor compara amb el valor guardat.
5. Si coincideix, la sessió passa a autenticada.
6. La contrasenya en clar no s'escriu a disc ni als logs.
Important

No confongueu protecció en repòs amb protecció en trànsit. Encara que el servidor guardi un hash, la contrasenya pot ser interceptada mentre viatja si el protocol la transmet per una connexió sense TLS. Ho resoldrem al bloc 3.

Exercici: Mini registre d'usuaris
Construïu un programa de consola amb dos usuaris. Guardeu només un valor derivat de cada contrasenya, demaneu usuari i contrasenya i indiqueu si l'autenticació és correcta. Comproveu que al mapa no hi apareix cap contrasenya en text pla.
Mitjà 20 min
Veure pistes
  • Reutilitzeu la funció sha256 per a l'exercici didàctic.
  • Comproveu primer que l'usuari existeix.
  • No imprimiu la contrasenya als missatges de depuració.
