1. Primer eco TCP: ServerSocket i Socket

Ja tenim el model mental. Ara construirem la comunicació més petita possible: un servidor rep una línia de text i retorna la mateixa línia en majúscules.

En TCP hi ha dues classes amb papers diferents:

Definició

ServerSocket: Sòcol d'escolta del servidor. Està associat a un port i permet acceptar noves connexions.

Definició

Socket: Extrem d'una connexió TCP ja establerta. Tant el client com el servidor utilitzen un Socket per llegir i escriure dades.

Figura

Servidor mínim

JAVA EchoTcpServer.java 
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class EchoTcpServer {

    private static final int PORT = 5000;

    public static void main(String[] args) throws Exception {

        try (ServerSocket servidor =
                     new ServerSocket(PORT)) {

            System.out.println(
                    "Esperant un client al port " + PORT
            );

            try (Socket client = servidor.accept();
                 BufferedReader entrada =
                         new BufferedReader(
                                 new InputStreamReader(
                                         client.getInputStream(),
                                         StandardCharsets.UTF_8));
                 PrintWriter sortida =
                         new PrintWriter(
                                 client.getOutputStream(),
                                 true,
                                 StandardCharsets.UTF_8)) {

                System.out.println(
                        "Connectat: "
                        + client.getRemoteSocketAddress()
                );

                String linia;

                while ((linia = entrada.readLine()) != null) {

                    if (linia.equalsIgnoreCase("fi")) {
                        sortida.println("ADEU");
                        break;
                    }

                    sortida.println(linia.toUpperCase());
                }
            }
        }
    }
}

Observeu el recorregut:

  1. new ServerSocket(PORT) reserva el port d'escolta.
  2. accept() queda bloquejat fins que arriba un client.
  3. accept() retorna un Socket nou per parlar amb aquell client.
  4. El servidor llegeix i escriu pel socket de la sessió.
  5. En acabar, es tanquen els recursos amb try-with-resources.

Client mínim

JAVA EchoTcpClient.java 
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class EchoTcpClient {

    private static final String HOST = "localhost";
    private static final int PORT = 5000;

    public static void main(String[] args) throws Exception {

        try (Socket socket = new Socket(HOST, PORT);
             BufferedReader teclat =
                     new BufferedReader(
                             new InputStreamReader(
                                     System.in,
                                     StandardCharsets.UTF_8));
             BufferedReader entrada =
                     new BufferedReader(
                             new InputStreamReader(
                                     socket.getInputStream(),
                                     StandardCharsets.UTF_8));
             PrintWriter sortida =
                     new PrintWriter(
                             socket.getOutputStream(),
                             true,
                             StandardCharsets.UTF_8)) {

            String linia;

            while (true) {
                System.out.print("Client > ");
                linia = teclat.readLine();

                if (linia == null) {
                    break;
                }

                sortida.println(linia);

                String resposta = entrada.readLine();

                if (resposta == null) {
                    System.out.println(
                            "El servidor ha tancat la connexió"
                    );
                    break;
                }

                System.out.println("Servidor > " + resposta);

                if (linia.equalsIgnoreCase("fi")) {
                    break;
                }
            }
        }
    }
}
Èxit

Proveu tres situacions.

  1. Executeu el client sense servidor.
  2. Executeu primer el servidor i després el client.
  3. Tanqueu el servidor mentre el client encara està actiu.

Les tres proves us ensenyen més sobre TCP que limitar-vos al cas que funciona.

Important

Aquest servidor només atén una sessió. Després de tancar el primer client, també es tanca el ServerSocket i el procés finalitza. És intencionat: primer entenem una connexió. Al bloc següent el convertirem en concurrent.

Exercici: Eco TCP observable
Executeu el servidor i el client en terminals separades. Envieu tres frases i finalitzeu amb fi. Afegiu al servidor la IP i el port remot del client a cada missatge que imprimeix.
Bàsic 20 min
Veure pistes
  • Useu getRemoteSocketAddress().
  • No canvieu encara l'arquitectura del servidor.
  • Comproveu què retorna readLine quan l'altre extrem tanca.

2. Fluxos de text i protocol d'aplicació

Un Socket TCP ens dona dos fluxos:

  • getInputStream(): bytes que arriben de la xarxa;
  • getOutputStream(): bytes que enviem a la xarxa.

El nostre protocol treballa amb text i línies, per això hi afegim capes d'alt nivell:

TEXT 
Socket
  |
  +-- InputStream
  |     |
  |     +-- InputStreamReader (bytes -> caràcters UTF-8)
  |             |
  |             +-- BufferedReader (readLine)
  |
  +-- OutputStream
        |
        +-- PrintWriter (println, flush)

Per què println() és part del protocol?

El salt de línia no és decoratiu. Si el receptor utilitza readLine(), necessita trobar el final de línia abans de poder retornar el missatge.

Problema

Error típic: el client fa print("HOLA") però no envia cap salt de línia ni força el flush. El servidor està esperant que la línia acabi i sembla que "la xarxa s'ha penjat".

Solució

Si el protocol és de línies, utilitzeu println() i assegureu-vos que les dades surten del buffer. En els exemples fem servir un PrintWriter amb autoFlush=true.

Un protocol amb ordres

Fem un pas més. En lloc de tractar qualsevol línia com a text, definim tres ordres:

TEXT 
MAJ text        -> OK TEXT
LONG text       -> OK nombre
FI              -> ADEU
qualsevol altra -> ERROR ordre desconeguda

La funció que interpreta una línia podria ser completament independent de la xarxa:

JAVA 
static String processar(String peticio) {

    if (peticio.equalsIgnoreCase("FI")) {
        return "ADEU";
    }

    if (peticio.startsWith("MAJ ")) {
        String text = peticio.substring(4);
        return "OK " + text.toUpperCase();
    }

    if (peticio.startsWith("LONG ")) {
        String text = peticio.substring(5);
        return "OK " + text.length();
    }

    return "ERROR ordre desconeguda";
}
Informació

Separeu protocol i transport.

El socket s'encarrega de transportar bytes. El mètode processar() decideix què significa una petició. Aquesta separació facilita molt les proves: podeu provar el protocol sense obrir cap port.

Quan el protocol ja no és de text

Java també ofereix DataInputStream i DataOutputStream per enviar enters, booleans i altres valors binaris. Una altra possibilitat és serialitzar formats com JSON. El principi no canvia: les dues parts han d'acordar exactament el format i els límits dels missatges.

JAVA 
DataOutputStream out =
        new DataOutputStream(socket.getOutputStream());

out.writeInt(3);       // longitud o camp del protocol
out.writeUTF("IOC");   // dada
out.flush();
Exercici: Protocol de calculadora
Amplieu l'eco TCP perquè el servidor entengui SUMA 4 7, RESTA 10 3 i FI. Les respostes han de començar per OK o ERROR. Manteniu la lògica de processament en un mètode independent del Socket.
Mitjà 20 min
Veure pistes
  • Separeu la línia amb split.
  • Valideu el nombre d'arguments.
  • Captureu NumberFormatException.
  • El transport continua sent un protocol de línies.

3. Primer eco UDP: DatagramSocket i DatagramPacket

Amb UDP no establim una connexió TCP. Treballem amb datagrames independents. Cada paquet rebut porta la dada i també l'adreça i el port de l'emissor.

Definició

DatagramSocket: Sòcol UDP utilitzat per enviar i rebre datagrames. Un servidor l'associa normalment a un port concret.

Definició

DatagramPacket: Objecte que representa un datagrama: conté bytes i, segons si enviem o rebem, la informació del destí o de l'origen.

Figura

Servidor UDP

JAVA EchoUdpServer.java 
import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.nio.charset.StandardCharsets;

public class EchoUdpServer {

    private static final int PORT = 5001;
    private static final int MAX_BYTES = 1024;

    public static void main(String[] args) throws Exception {

        byte[] buffer = new byte[MAX_BYTES];

        try (DatagramSocket socket =
                     new DatagramSocket(PORT)) {

            System.out.println(
                    "UDP escoltant al port " + PORT
            );

            while (true) {
                DatagramPacket rebut =
                        new DatagramPacket(
                                buffer, buffer.length);

                socket.receive(rebut);

                String text = new String(
                        rebut.getData(),
                        rebut.getOffset(),
                        rebut.getLength(),
                        StandardCharsets.UTF_8
                );

                System.out.printf(
                        "%s:%d -> %s%n",
                        rebut.getAddress().getHostAddress(),
                        rebut.getPort(),
                        text
                );

                if (text.equalsIgnoreCase("fi")) {
                    break;
                }

                byte[] resposta =
                        text.toUpperCase()
                                .getBytes(
                                    StandardCharsets.UTF_8);

                DatagramPacket enviat =
                        new DatagramPacket(
                                resposta,
                                resposta.length,
                                rebut.getAddress(),
                                rebut.getPort()
                        );

                socket.send(enviat);
            }
        }
    }
}

Client UDP

JAVA EchoUdpClient.java 
import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;
import java.nio.charset.StandardCharsets;

public class EchoUdpClient {

    private static final int PORT = 5001;

    public static void main(String[] args) throws Exception {

        InetAddress servidor =
                InetAddress.getByName("localhost");

        try (DatagramSocket socket =
                     new DatagramSocket()) {

            String text = "hola udp";

            byte[] dades =
                    text.getBytes(StandardCharsets.UTF_8);

            DatagramPacket peticio =
                    new DatagramPacket(
                            dades,
                            dades.length,
                            servidor,
                            PORT
                    );

            socket.send(peticio);

            byte[] buffer = new byte[1024];
            DatagramPacket resposta =
                    new DatagramPacket(
                            buffer, buffer.length);

            socket.receive(resposta);

            String rebut = new String(
                    resposta.getData(),
                    resposta.getOffset(),
                    resposta.getLength(),
                    StandardCharsets.UTF_8
            );

            System.out.println("Servidor > " + rebut);
        }
    }
}

La longitud real és important

El buffer pot tenir 1024 bytes, però el missatge rebut pot tenir-ne només 8. Per això construïm el text amb getOffset() i getLength(). Convertir tot el buffer pot afegir bytes que no formen part del datagrama.

Informació

Diferència visible respecte de TCP

El servidor UDP no necessita un socket diferent per a cada client. Pot rebre un datagrama del client A, després un del B i després un altre de l'A pel mateix DatagramSocket. Cada paquet li diu d'on prové.

Exercici: Eco UDP interactiu
Convertiu el client UDP en interactiu: llegiu línies del teclat, envieu cada línia com un datagrama, mostreu la resposta i finalitzeu quan l'usuari escrigui fi.
Mitjà 20 min
Veure pistes
  • Cada iteració crea o reutilitza un DatagramPacket d'enviament.
  • Per a fi podeu decidir si el servidor respon o no; documenteu el contracte.
  • No hi ha accept ni connexió prèvia.

4. Pèrdues, duplicats, ordre i timeout en UDP

L'exemple anterior té una fragilitat: després d'enviar, el client fa receive() i pot quedar-se esperant indefinidament. Si el servidor no està en marxa o la resposta es perd, no hi ha ningú que desbloquegi aquella lectura.

Primer pas: posar un límit

JAVA 
socket.setSoTimeout(1_500);

try {
    socket.send(peticio);
    socket.receive(resposta);

} catch (java.net.SocketTimeoutException e) {
    System.out.println(
            "No s'ha rebut resposta en 1,5 segons"
    );
}

Això evita el bloqueig indefinit, però encara hem de decidir què significa el timeout. Podem donar l'operació per fallida o intentar una retransmissió.

Segon pas: identificar peticions

Si retransmetem, el servidor podria rebre dues vegades la mateixa petició. Un protocol real acostuma a incorporar un identificador.

TEXT 
REQ 1042 HOLA
RES 1042 HOLA

REQ 1043 TEMPERATURA
RES 1043 21.8

Ara el client pot saber a quina petició correspon cada resposta. El servidor també podria recordar temporalment identificadors ja processats si executar dues vegades la mateixa operació fos perillós.

Un patró de reintent simple

JAVA 
socket.setSoTimeout(1000);

boolean rebut = false;

for (int intent = 1; intent <= 3 && !rebut; intent++) {

    socket.send(peticio);

    try {
        socket.receive(resposta);
        rebut = true;

    } catch (SocketTimeoutException e) {
        System.out.println(
                "Intent " + intent + " sense resposta"
        );
    }
}

if (!rebut) {
    System.out.println("Operació fallida");
}
Important

Un reintent canvia el protocol.

No n'hi ha prou amb repetir send(). Si la primera petició va arribar però només es va perdre la resposta, el servidor rebrà la mateixa operació dues vegades. Per això les operacions idempotents i els identificadors de petició són conceptes importants en sistemes distribuïts.

Reutilitzar un DatagramPacket de recepció

Si reutilitzeu el mateix DatagramPacket diverses vegades, recordeu que després d'una recepció la seva longitud queda ajustada a la mida rebuda. Abans de la següent recepció convé restaurar la capacitat:

JAVA 
byte[] buffer = new byte[1024];
DatagramPacket paquet =
        new DatagramPacket(buffer, buffer.length);

while (true) {
    paquet.setLength(buffer.length);
    socket.receive(paquet);

    // processar paquet...
}
Exercici: UDP que no es queda penjat
Afegiu un timeout al client d'eco UDP i un màxim de tres intents. Proveu-lo amb el servidor aturat. Després executeu el servidor i comproveu que la resposta correcta finalitza els reintents.
Mitjà 20 min
Veure pistes
  • Useu setSoTimeout.
  • Captureu SocketTimeoutException dins del bucle.
  • No confongueu nombre d'intents amb nombre de respostes.

5. Unicast i multicast amb MulticastSocket

Fins ara cada missatge tenia un únic destí. Això és unicast. Amb multicast, un emissor envia un datagrama a una adreça de grup i diversos receptors que s'hi han unit poden rebre'l.

Figura
Informació

Multicast utilitza UDP.

TCP crea una connexió entre dos endpoints. Una transmissió multicast, en canvi, està pensada per lliurar datagrames a un grup variable de receptors.

Emissor

JAVA EmissorMulticast.java 
import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;
import java.nio.charset.StandardCharsets;

public class EmissorMulticast {

    private static final String GRUP = "226.1.2.3";
    private static final int PORT = 9876;

    public static void main(String[] args) throws Exception {

        InetAddress grup = InetAddress.getByName(GRUP);
        byte[] dades =
                "Missatge per al grup"
                        .getBytes(StandardCharsets.UTF_8);

        DatagramPacket paquet =
                new DatagramPacket(
                        dades, dades.length, grup, PORT);

        try (DatagramSocket socket =
                     new DatagramSocket()) {
            socket.send(paquet);
        }
    }
}

Receptor: unir-se al grup

La forma conceptualment més simple és associar un MulticastSocket al port i unir-lo a l'adreça de grup:

JAVA ReceptorMulticast.java 
import java.net.DatagramPacket;
import java.net.InetAddress;
import java.net.MulticastSocket;
import java.nio.charset.StandardCharsets;

public class ReceptorMulticast {

    private static final String GRUP = "226.1.2.3";
    private static final int PORT = 9876;

    public static void main(String[] args) throws Exception {

        InetAddress grup = InetAddress.getByName(GRUP);

        try (MulticastSocket socket =
                     new MulticastSocket(PORT)) {

            socket.joinGroup(grup);

            byte[] buffer = new byte[1024];
            DatagramPacket paquet =
                    new DatagramPacket(
                            buffer, buffer.length);

            socket.receive(paquet);

            String text = new String(
                    paquet.getData(),
                    paquet.getOffset(),
                    paquet.getLength(),
                    StandardCharsets.UTF_8
            );

            System.out.println(text);

            socket.leaveGroup(grup);
        }
    }
}
Important

API moderna de Java.

Les sobrecàrregues joinGroup(InetAddress) i leaveGroup(InetAddress) són antigues i apareixen com a deprecades en JDK recents. En aplicacions noves és preferible indicar també la interfície de xarxa amb joinGroup(SocketAddress, NetworkInterface). Aquí les fem servir primer perquè mostren el concepte amb molt poc codi.

Versió amb interfície de xarxa explícita

JAVA 
InetAddress grup =
        InetAddress.getByName("226.1.2.3");

NetworkInterface interf =
        NetworkInterface.getByInetAddress(
                InetAddress.getLocalHost());

InetSocketAddress grupIPort =
        new InetSocketAddress(grup, 9876);

try (MulticastSocket socket =
             new MulticastSocket(9876)) {

    socket.joinGroup(grupIPort, interf);

    // receive(...)

    socket.leaveGroup(grupIPort, interf);
}

En una màquina amb diverses interfícies, VPN o contenidors, triar explícitament la interfície és important. A més, la xarxa real pot filtrar multicast; que el codi sigui correcte no implica que tots els routers el propagaran.
