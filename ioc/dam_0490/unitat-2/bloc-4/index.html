1. Serveis estàndard i arquitectura del correu

Fins ara hem inventat els nostres propis protocols. Internet funciona perquè moltes aplicacions comparteixen protocols estàndard. Això permet que programes creats per equips diferents puguin interoperar.

ServeiProtocol o famíliaTransport habitualIdea principal

Informació

El patró es repeteix.

Els protocols estàndard continuen sent una conversa entre processos. Defineixen comandes, respostes, formats i errors. Les llibreries d'alt nivell ens estalvien escriure manualment aquesta conversa, però per sota continuen utilitzant mecanismes de xarxa.

Localitzar un recurs: URL i URLConnection

Abans d'obrir un sòcol manualment, convé entendre com es representa un recurs remot. Una URL combina el protocol, l'autoritat, el port, el camí i, si n'hi ha, els paràmetres de consulta. Aquesta idea apareix al material oficial perquè permet passar d'una cadena com https://servidor/cami?x=1 a objectes Java que saben extreure'n cada part.

JAVA DesmuntarUrl.java 
import java.net.URI;
import java.net.URL;

public class DesmuntarUrl {
    public static void main(String[] args) throws Exception {

        URL url = URI.create(
                "https://example.org:8443/docs/index.html?q=java"
        ).toURL();

        System.out.println("Protocol:  " + url.getProtocol());
        System.out.println("Autoritat: " + url.getAuthority());
        System.out.println("Host:      " + url.getHost());
        System.out.println("Port:      " + url.getPort());
        System.out.println("Camí:      " + url.getPath());
        System.out.println("Query:     " + url.getQuery());
    }
}

La classe URL no serveix només per separar una adreça. També pot obrir una URLConnection. Aquesta classe representa una connexió d'alt nivell cap al recurs i ens permet consultar metadades i obtenir-ne el contingut sense gestionar directament el Socket.

JAVA LlegirRecurs.java 
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.net.URI;
import java.net.URLConnection;
import java.nio.charset.StandardCharsets;

public class LlegirRecurs {

    public static void main(String[] args)
            throws Exception {

        URLConnection con =
                URI.create("https://example.org/")
                   .toURL()
                   .openConnection();

        con.setConnectTimeout(3_000);
        con.setReadTimeout(3_000);

        System.out.println(
                "Tipus: " + con.getContentType()
        );
        System.out.println(
                "Longitud: " + con.getContentLengthLong()
        );

        try (BufferedReader in =
                     new BufferedReader(
                             new InputStreamReader(
                                     con.getInputStream(),
                                     StandardCharsets.UTF_8))) {

            System.out.println(in.readLine());
        }
    }
}
Informació

Canvi de nivell d'abstracció.

Amb Socket controleu la conversa byte a byte o línia a línia. Amb URLConnection demaneu un recurs i la biblioteca resol part del protocol. Saber baixar i pujar de nivell és una de les idees més importants de la unitat.

HTTP amb HttpURLConnection

El material oficial treballa amb HttpURLConnection, una especialització de URLConnection que fa visibles conceptes propis d'HTTP: mètode, capçaleres, codi d'estat i cos de la resposta. Encara és útil per entendre aquests conceptes, tot i que en codi modern sovint preferirem HttpClient.

JAVA ClientHttpURLConnection.java 
import java.io.BufferedReader;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.net.HttpURLConnection;
import java.net.URI;
import java.nio.charset.StandardCharsets;

public class ClientHttpURLConnection {

    public static void main(String[] args)
            throws Exception {

        HttpURLConnection con =
                (HttpURLConnection)
                URI.create("https://example.org/")
                   .toURL()
                   .openConnection();

        con.setRequestMethod("GET");
        con.setConnectTimeout(3_000);
        con.setReadTimeout(3_000);
        con.setRequestProperty(
                "Accept", "text/html");

        int status = con.getResponseCode();

        System.out.println("Estat: " + status);
        System.out.println(
                "Content-Type: "
                + con.getContentType()
        );

        InputStream stream =
                status >= 400
                ? con.getErrorStream()
                : con.getInputStream();

        if (stream != null) {
            try (BufferedReader in =
                         new BufferedReader(
                                 new InputStreamReader(
                                         stream,
                                         StandardCharsets.UTF_8))) {

                in.lines()
                  .limit(10)
                  .forEach(System.out::println);
            }
        }

        con.disconnect();
    }
}

Observeu el paral·lelisme: GET és la petició, getResponseCode() ens dona l'estat de la resposta i getInputStream() ens dona el cos. Si la resposta és d'error, el cos pot arribar per getErrorStream().

Enviar dades amb POST

Amb POST les dades acostumen a viatjar al cos de la petició. En una petició de formulari senzilla, el tipus application/x-www-form-urlencoded representa parelles nom=valor.

JAVA EnviarPost.java 
import java.io.OutputStream;
import java.net.HttpURLConnection;
import java.net.URI;
import java.net.URLEncoder;
import java.nio.charset.StandardCharsets;

String body =
        "nom="
        + URLEncoder.encode(
                "Anna Serra",
                StandardCharsets.UTF_8)
        + "&modul=0490";

byte[] dades =
        body.getBytes(StandardCharsets.UTF_8);

HttpURLConnection con =
        (HttpURLConnection)
        URI.create("https://example.org/form")
           .toURL()
           .openConnection();

con.setRequestMethod("POST");
con.setDoOutput(true);
con.setRequestProperty(
        "Content-Type",
        "application/x-www-form-urlencoded; charset=UTF-8"
);
con.setFixedLengthStreamingMode(dades.length);

try (OutputStream out =
             con.getOutputStream()) {
    out.write(dades);
}

System.out.println(
        "Estat: " + con.getResponseCode()
);

con.disconnect();

La diferència important no és memoritzar dues receptes. És saber on viatgen les dades: en un GET poden formar part de la query de la URL; en un POST acostumen a formar part del cos.

Un servidor HTTP mínim per veure l'altra banda

Per entendre un servei web no cal començar per un contenidor complet. Aquest servidor didàctic accepta una connexió, llegeix la primera petició HTTP i retorna una resposta 200 OK. No és un servidor de producció: només serveix per veure com els conceptes de ServerSocket i protocol d'aplicació encaixen amb HTTP.

JAVA MiniHttpServer.java 
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.OutputStream;
import java.net.ServerSocket;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class MiniHttpServer {

    public static void main(String[] args)
            throws Exception {

        try (ServerSocket server =
                     new ServerSocket(8080)) {

            System.out.println(
                    "Obriu http://localhost:8080/"
            );

            try (Socket client = server.accept();
                 BufferedReader in =
                         new BufferedReader(
                                 new InputStreamReader(
                                         client.getInputStream(),
                                         StandardCharsets.US_ASCII));
                 OutputStream out =
                         client.getOutputStream()) {

                String requestLine = in.readLine();
                System.out.println(requestLine);

                String line;
                while ((line = in.readLine()) != null
                        && !line.isEmpty()) {
                    System.out.println(line);
                }

                byte[] body =
                        "<h1>Hola des de Java</h1>"
                        .getBytes(StandardCharsets.UTF_8);

                String headers =
                        "HTTP/1.1 200 OK\r\n"
                        + "Content-Type: text/html; charset=UTF-8\r\n"
                        + "Content-Length: " + body.length + "\r\n"
                        + "Connection: close\r\n"
                        + "\r\n";

                out.write(
                        headers.getBytes(
                                StandardCharsets.US_ASCII));
                out.write(body);
                out.flush();
            }
        }
    }
}

Si executeu el programa i visiteu http://localhost:8080/, el navegador es converteix en el client. Veureu a la consola una línia similar a GET / HTTP/1.1 i les capçaleres que el navegador ha enviat.

FTP: control i dades en canals diferents

FTP també és un protocol client-servidor sobre TCP, però introdueix una idea interessant: separa el canal de control del canal de dades. Les comandes i respostes textuals mantenen una connexió de control, habitualment associada al port 21 del servidor, mentre que una transferència de fitxer utilitza una connexió de dades temporal.

TEXT 
Canal de control (persistent)
Client  <----------------->  Servidor
        USER, PASS, PWD,
        CWD, RETR, STOR...
        respostes 220, 230...

Canal de dades (temporal)
Client  <=================>  Servidor
        bytes del fitxer

En mode actiu, el client indica on escoltarà i el servidor inicia la connexió de dades. En mode passiu, el servidor indica una adreça i un port i és el client qui inicia la connexió. El mode passiu acostuma a encaixar millor amb clients situats darrere de NAT o tallafocs.

Figura

Veure la conversa FTP

Una sessió de control FTP és textual. El client envia comandes i el servidor respon amb codis numèrics. Per exemple:

TEXT 
S: 220 Servei FTP preparat
C: USER alumne
S: 331 Cal contrasenya
C: PASS ****
S: 230 Sessió iniciada
C: PWD
S: 257 "/"
C: PASV
S: 227 Entering Passive Mode (...)
C: LIST
S: 150 Obrint canal de dades
   ... llistat pel canal de dades ...
S: 226 Transferència completada
C: QUIT
S: 221 Adeu

La comanda PASV no transfereix encara el llistat. Primer prepara el canal de dades. Després, comandes com LIST, RETR o STOR utilitzen aquest segon canal.

Client mínim del canal de control

Aquest exemple es pot executar contra un servidor FTP de proves que tingueu disponible. No implementa la transferència de fitxers: el seu objectiu és que veieu la mateixa estructura petició-resposta que ja coneixeu de SMTP i HTTP.

JAVA FtpControlClient.java 
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class FtpControlClient {

    public static void main(String[] args)
            throws Exception {

        String host = args.length > 0
                ? args[0]
                : "localhost";

        int port = args.length > 1
                ? Integer.parseInt(args[1])
                : 21;

        try (Socket socket =
                     new Socket(host, port);
             BufferedReader in =
                     new BufferedReader(
                             new InputStreamReader(
                                     socket.getInputStream(),
                                     StandardCharsets.US_ASCII));
             PrintWriter out =
                     new PrintWriter(
                             socket.getOutputStream(),
                             true,
                             StandardCharsets.US_ASCII)) {

            System.out.println("S: " + in.readLine());

            enviar(out, in, "USER anonymous");
            enviar(out, in, "PASS alumne@example.test");
            enviar(out, in, "PWD");
            enviar(out, in, "QUIT");
        }
    }

    private static void enviar(
            PrintWriter out,
            BufferedReader in,
            String ordre) throws Exception {

        System.out.println("C: " + ordre);
        out.print(ordre + "\r\n");
        out.flush();

        System.out.println("S: " + in.readLine());
    }
}
Important

Una implementació FTP real ha de fer més feina.

Les respostes poden ocupar diverses línies i les ordres de transferència necessiten el canal de dades. Aquí només fem visible el mecanisme essencial abans de delegar-lo en una llibreria FTP.

Informació

Una mateixa idea, protocols diferents.

HTTP, FTP i SMTP defineixen converses diferents, però tots necessiten adreçament, transport, framing, gestió d'errors i un estat de sessió més o menys complex. Entendre sockets us permet veure què hi ha sota les llibreries de protocol.

El correu no viatja directament del vostre programa a la bústia

En una arquitectura típica intervenen diversos rols:

Figura

      | SMTP
      v

      | SMTP

Això explica una confusió freqüent: SMTP no és el protocol per llegir la bústia. El seu objectiu principal és transferir missatges.

IMAP i POP3 no resolen exactament el mateix problema

ProtocolModel mentalQuan és útil
IMAPLa bústia continua al servidor i el client sincronitza carpetes, missatges i estats.Diversos dispositius que consulten la mateixa bústia.
POP3Model més simple orientat a recuperar missatges de la bústia.Clients senzills o fluxos de descàrrega.

Les llibreries de correu acostumen a oferir una API comuna i un proveïdor específic per a SMTP, IMAP o POP3.

Ports estàndard i ports de pràctiques

Els serveis reals tenen ports convencionals. Per exemple, SMTP històricament utilitza el port 25 entre servidors i la submissió autenticada acostuma a utilitzar el 587. En els nostres programes de pràctiques utilitzarem ports no privilegiats com 2525 per no interferir amb serveis reals.

Important

No implementeu un servidor de correu d'Internet complet amb els exemples d'aquesta unitat.

Els protocols reals inclouen seguretat, autenticació, TLS, extensió ESMTP, polítiques antispam, DNS, cues persistents i molts altres detalls. El nostre objectiu és entendre el mecanisme de comunicació i l'estat de la sessió.

2. Format d'un missatge: capçaleres i cos

El protocol SMTP transporta un missatge, però el format del missatge és una altra especificació. El model modern prové de la família RFC 822 / RFC 2822 i actualment queda recollit principalment a RFC 5322.

La idea bàsica és molt fàcil de reconèixer:

TEXT 
Capçalera: valor
Capçalera: valor
Capçalera: valor

Cos del missatge
Segona línia del cos
...

Una línia en blanc separa les capçaleres del cos. Aquesta línia és estructural.

Exemple complet en text pla

To: Biel Roca <biel@example.test>

I Bcc?

La còpia oculta és especial. Els destinataris Bcc s'utilitzen durant l'enviament, però no s'ha de deixar una capçalera que reveli aquests destinataris a les còpies entregades. Aquesta és precisament la idea de la còpia oculta.

Important

No confongueu sobre SMTP i capçaleres.

MAIL FROM i RCPT TO formen part de l'envolupant SMTP. From: i To: formen part del contingut del missatge. En un sistema real poden no coincidir exactament.

MIME: quan el correu deixa de ser text pla simple

Per enviar HTML, adjunts o continguts de diferents tipus s'utilitzen extensions MIME. Apareixen capçaleres com:

TEXT 
MIME-Version: 1.0
Content-Type: text/plain; charset=UTF-8
Content-Transfer-Encoding: quoted-printable

No implementarem un parser MIME complet a mà. El que ens interessa és entendre que una llibreria com Jakarta Mail construeix aquestes estructures per nosaltres.

Construir una data correcta amb Java

JAVA 
ZonedDateTime ara =
        ZonedDateTime.now(
                ZoneId.of("Europe/Madrid"));

        DateTimeFormatter.ofPattern(
                "EEE, dd MMM uuuu HH:mm:ss xx",
                Locale.ENGLISH
        );

System.out.println(format.format(ara));
Informació

Separar formats ajuda.

Un missatge té el seu format propi. SMTP és el protocol que el transporta. MIME amplia el format per representar continguts més rics. Pensar en aquestes capes evita barrejar conceptes.

3. SMTP: comandes, respostes i estat de sessió

SMTP és un protocol textual de petició-resposta sobre TCP. El client envia una comanda i el servidor respon amb un codi numèric de tres dígits i, normalment, un text descriptiu.

Figura

Una sessió mínima

TEXT 
S: 220 localhost Simple SMTP ready
C: EHLO client.local
S: 250 Hello client.local

C: MAIL FROM:<anna@example.test>
S: 250 Sender OK

C: RCPT TO:<biel@example.test>
S: 250 Recipient OK

C: DATA
S: 354 End data with <CRLF>.<CRLF>

C: From: anna@example.test
C: To: biel@example.test
C: Subject: Prova
C:
C: Hola Biel
C: .
S: 250 Message accepted

C: QUIT
S: 221 Bye

Les marques C: i S: només serveixen per indicar qui parla; no formen part dels bytes enviats.

Comandes que convé conèixer

ComandaFunció
EHLO domini / HELO dominiEl client inicia el diàleg SMTP i s'identifica.
MAIL FROM:<adreça>Defineix el remitent de l'envolupant.
RCPT TO:<adreça>Afegeix un destinatari de l'envolupant.
DATADemana començar a enviar el contingut del missatge.
RSETDescarta l'envolupant actual i torna a començar una transacció.
NOOPNo fa cap operació; el servidor només confirma que continua disponible.
QUITFinalitza la sessió de manera ordenada.

Alguns codis de resposta

CodiIdea
220Servei preparat.
221El servidor tanca el canal.
250Operació completada correctament.
354Comenceu l'entrada del missatge.
421Servei no disponible; es tancarà.
450Error temporal sobre la bústia o destinatari.
500Comanda no reconeguda o error de sintaxi general.
501Error de sintaxi als paràmetres.
503Seqüència de comandes incorrecta.

Per què necessitem estat?

No podem acceptar DATA abans de saber qui envia i a qui. El servidor ha de recordar on es troba la sessió.

JAVA 
enum Estat {
    CONNECTED,
    GREETED,
    MAIL_FROM,
    RCPT_TO,
    DATA
}

Una versió simplificada de les transicions podria ser:

TEXT 
CONNECTED --EHLO--> GREETED
GREETED   --MAIL--> MAIL_FROM
MAIL_FROM --RCPT--> RCPT_TO
RCPT_TO   --RCPT--> RCPT_TO
RCPT_TO   --DATA--> DATA
DATA      --"."----> GREETED

RSET pot tornar la transacció a GREETED
QUIT pot aparèixer fora del mode DATA i tanca la sessió

DATA és un mode especial

Després de respondre 354, les línies ja no són comandes SMTP: són el contingut del missatge. El final arriba quan el servidor rep una línia que conté només un punt.

Important

El punt final no forma part del missatge.

En SMTP real també existeix el mecanisme de dot-stuffing: si una línia del contingut ha de començar literalment amb un punt, el client l'escapa. En el nostre servidor didàctic podem començar pel cas simple i afegir aquesta regla després.

Llegir respostes multilínia

ESMTP pot respondre a EHLO amb diverses línies. El guió després del codi indica que encara en venen més; l'espai indica l'última.

TEXT 
250-localhost Hello
250-SIZE 10485760
250-8BITMIME
250 OK

Un client robust no ha d'assumir que tota resposta és una única línia.

4. Construir un servidor i un client SMTP senzills

1. El missatge en memòria

JAVA SmtpMessage.java 
import java.util.ArrayList;
import java.util.List;

public class SmtpMessage {

    private String from;
    private final List<String> recipients =
            new ArrayList<>();
    private final StringBuilder data =
            new StringBuilder();

    public String getFrom() {
        return from;
    }

    public void setFrom(String from) {
        this.from = from;
    }

    public List<String> getRecipients() {
        return List.copyOf(recipients);
    }

    public void addRecipient(String recipient) {
        recipients.add(recipient);
    }

    public void addDataLine(String line) {
        data.append(line)
            .append(System.lineSeparator());
    }

    public String getData() {
        return data.toString();
    }

    public void reset() {
        from = null;
        recipients.clear();
        data.setLength(0);
    }
}

2. Guardar un missatge

Per fer observable el servidor, podem desar cada missatge acceptat en una carpeta local. No és una bústia real, però ens permet verificar què ha rebut el servei.

JAVA 
static Path desar(SmtpMessage message)
        throws IOException {

    Path carpeta = Path.of("mailbox");
    Files.createDirectories(carpeta);

    String nom =
            "mail-" + System.currentTimeMillis()
            + "-" + UUID.randomUUID()
            + ".txt";

    Path fitxer = carpeta.resolve(nom);

    String contingut =
            "Envelope-From: " + message.getFrom()
            + System.lineSeparator()
            + "Envelope-To: "
            + String.join(", ", message.getRecipients())
            + System.lineSeparator()
            + System.lineSeparator()
            + message.getData();

    return Files.writeString(
            fitxer,
            contingut,
            StandardCharsets.UTF_8
    );
}

3. La sessió SMTP

Aquesta implementació és deliberadament petita. Admet EHLO/HELO, MAIL FROM, RCPT TO, DATA, RSET, NOOP i QUIT.

JAVA SmtpSession.java 
public final class SmtpSession implements Runnable {

    private enum Estat {
        CONNECTED, GREETED, MAIL_FROM, RCPT_TO
    }

    private final Socket socket;
    private final SmtpMessage message =
            new SmtpMessage();

    private Estat estat = Estat.CONNECTED;

    public SmtpSession(Socket socket) {
        this.socket = socket;
    }

    @Override
    public void run() {

        try (socket;
             BufferedReader in =
                     new BufferedReader(
                             new InputStreamReader(
                                     socket.getInputStream(),
                                     StandardCharsets.UTF_8));
             PrintWriter out =
                     new PrintWriter(
                             socket.getOutputStream(),
                             true,
                             StandardCharsets.UTF_8)) {

            out.println(
                    "220 localhost Simple SMTP ready"
            );

            String line;

            while ((line = in.readLine()) != null) {

                if (line.regionMatches(
                        true, 0, "EHLO ", 0, 5)
                    || line.regionMatches(
                        true, 0, "HELO ", 0, 5)) {

                    message.reset();
                    estat = Estat.GREETED;
                    out.println("250 Hello");
                    continue;
                }

                if (line.regionMatches(
                        true, 0, "MAIL FROM:", 0, 10)) {

                    if (estat != Estat.GREETED) {
                        out.println(
                                "503 Bad sequence of commands");
                        continue;
                    }

                    String from =
                            line.substring(10).trim();

                    if (from.isEmpty()) {
                        out.println(
                                "501 Missing sender");
                        continue;
                    }

                    message.reset();
                    message.setFrom(from);
                    estat = Estat.MAIL_FROM;
                    out.println("250 Sender OK");
                    continue;
                }

                if (line.regionMatches(
                        true, 0, "RCPT TO:", 0, 8)) {

                    if (estat != Estat.MAIL_FROM
                            && estat != Estat.RCPT_TO) {
                        out.println(
                                "503 Bad sequence of commands");
                        continue;
                    }

                    String to =
                            line.substring(8).trim();

                    if (to.isEmpty()) {
                        out.println(
                                "501 Missing recipient");
                        continue;
                    }

                    message.addRecipient(to);
                    estat = Estat.RCPT_TO;
                    out.println("250 Recipient OK");
                    continue;
                }

                if (line.equalsIgnoreCase("DATA")) {

                    if (estat != Estat.RCPT_TO) {
                        out.println(
                                "503 Need MAIL and RCPT first");
                        continue;
                    }

                    out.println(
                            "354 End data with <CRLF>.<CRLF>");

                    llegirData(in);

                    Path fitxer = desar(message);

                    System.out.println(
                            "Desat: " + fitxer
                    );

                    message.reset();
                    estat = Estat.GREETED;

                    out.println("250 Message accepted");
                    continue;
                }

                if (line.equalsIgnoreCase("RSET")) {
                    message.reset();

                    if (estat != Estat.CONNECTED) {
                        estat = Estat.GREETED;
                    }

                    out.println("250 Reset OK");
                    continue;
                }

                if (line.equalsIgnoreCase("NOOP")) {
                    out.println("250 OK");
                    continue;
                }

                if (line.equalsIgnoreCase("QUIT")) {
                    out.println("221 Bye");
                    break;
                }

                out.println("500 Command unrecognized");
            }

        } catch (IOException e) {
            System.err.println(
                    "Sessió SMTP: " + e.getMessage()
            );
        }
    }

    private void llegirData(BufferedReader in)
            throws IOException {

        String line;

        while ((line = in.readLine()) != null) {

            if (line.equals(".")) {
                return;
            }

            if (line.startsWith("..")) {
                line = line.substring(1);
            }

            message.addDataLine(line);
        }

        throw new EOFException(
                "Connexió tancada durant DATA"
        );
    }
}
Informació

Fixeu-vos en l'estat.

Després d'acceptar un missatge, la sessió torna a GREETED. Això permet enviar un segon correu dins de la mateixa connexió SMTP sense repetir obligatòriament tota la connexió TCP.

4. El servidor concurrent

JAVA SmtpServer.java 
public class SmtpServer {

    private static final int PORT = 2525;

    public static void main(String[] args)
            throws Exception {

        ExecutorService pool =
                Executors.newFixedThreadPool(8);

        try (ServerSocket server =
                     new ServerSocket(PORT)) {

            System.out.println(
                    "SMTP escoltant al port " + PORT
            );

            while (true) {
                Socket client = server.accept();
                pool.execute(
                        new SmtpSession(client)
                );
            }

        } finally {
            pool.shutdown();
        }
    }
}

5. Un client que parla SMTP

Per entendre el protocol és útil escriure un client que faci visible cada comanda i cada resposta.

JAVA SmtpClient.java 
public class SmtpClient {

    public static void main(String[] args)
            throws Exception {

        try (Socket socket =
                     new Socket("localhost", 2525);
             BufferedReader in =
                     new BufferedReader(
                             new InputStreamReader(
                                     socket.getInputStream(),
                                     StandardCharsets.UTF_8));
             PrintWriter out =
                     new PrintWriter(
                             socket.getOutputStream(),
                             true,
                             StandardCharsets.UTF_8)) {

            llegir(in);

            enviar(out, in, "EHLO client.local");
            enviar(out, in,
                    "MAIL FROM:<anna@example.test>");
            enviar(out, in,
                    "RCPT TO:<biel@example.test>");

            System.out.println("C: DATA");
            out.println("DATA");

            String resposta = llegir(in);

            if (!resposta.startsWith("354")) {
                throw new IOException(
                        "DATA rebutjat: " + resposta
                );
            }

            out.println(
                    "From: anna@example.test");
            out.println(
                    "To: biel@example.test");
            out.println("Subject: Prova");
            out.println();
            out.println("Hola des del client Java");
            out.println(".");

            llegir(in);

            enviar(out, in, "QUIT");
        }
    }

    private static void enviar(
            PrintWriter out,
            BufferedReader in,
            String ordre) throws IOException {

        System.out.println("C: " + ordre);
        out.println(ordre);
        llegir(in);
    }

    private static String llegir(
            BufferedReader in) throws IOException {

        String resposta = in.readLine();

        if (resposta == null) {
            throw new EOFException(
                    "El servidor ha tancat la connexió"
            );
        }

        System.out.println("S: " + resposta);
        return resposta;
    }
}

5. Jakarta Mail: del protocol manual a una API d'alt nivell

Hem implementat SMTP a mà per entendre'l. En una aplicació real, repetir aquest codi seria mala idea. Una llibreria especialitzada ja coneix el protocol, els formats de missatge i moltes extensions.

L'API moderna és Jakarta Mail. Una implementació habitual és Eclipse Angus Mail.

API i implementació no són exactament el mateix.

Enviar al nostre servidor local

JAVA EnviarAmbJakartaMail.java 
import jakarta.mail.Message;
import jakarta.mail.Session;
import jakarta.mail.Transport;
import jakarta.mail.internet.InternetAddress;
import jakarta.mail.internet.MimeMessage;

import java.nio.charset.StandardCharsets;
import java.util.Properties;

public class EnviarAmbJakartaMail {

    public static void main(String[] args)
            throws Exception {

        Properties props = new Properties();

        props.put("mail.smtp.host", "localhost");
        props.put("mail.smtp.port", "2525");

        props.put("mail.smtp.auth", "false");
        props.put(
                "mail.smtp.starttls.enable", "false");

        props.put(
                "mail.smtp.connectiontimeout", "3000");
        props.put("mail.smtp.timeout", "3000");
        props.put("mail.smtp.writetimeout", "3000");

        Session session =
                Session.getInstance(props);

        session.setDebug(true);

        MimeMessage message =
                new MimeMessage(session);

        message.setFrom(
                new InternetAddress(
                        "anna@example.test"));

        message.setRecipient(
                Message.RecipientType.TO,
                new InternetAddress(
                        "biel@example.test"));

        message.setSubject(
                "Prova amb Jakarta Mail",
                StandardCharsets.UTF_8.name());

        message.setText(
                "Hola des d'una API d'alt nivell.",
                StandardCharsets.UTF_8.name());

        Transport.send(message);

        System.out.println("Missatge enviat");
    }
}

Si session.setDebug(true) està activat, podreu observar el diàleg SMTP que la llibreria genera. És un exercici molt útil: compareu les línies del debug amb el client manual de l'apartat anterior.

Abans de l'API: què fa POP3?

POP3 és un bon exemple de protocol textual simple per accedir a una bústia. Després d'autenticar-se, el client pot llistar, recuperar o marcar per eliminar missatges. Les respostes comencen habitualment per +OK o -ERR.

Fixeu-vos en el paral·lelisme amb SMTP: tots dos són protocols textuals amb estat, però resolen problemes diferents. SMTP transfereix missatges; POP3 permet recuperar-los d'una bústia.

Accedir a una bústia

Jakarta Mail no serveix només per SMTP. Per llegir una bústia treballa amb un Store. El protocol concret pot ser POP3 o IMAP. Després obtenim una Folder, habitualment INBOX, i d'allà recuperem objectes Message.

Llegir INBOX amb POP3

JAVA LlegirPop3.java 
import jakarta.mail.Folder;
import jakarta.mail.Message;
import jakarta.mail.Session;
import jakarta.mail.Store;

import java.util.Properties;

public class LlegirPop3 {

    public static void main(String[] args)
            throws Exception {

        String host = "mail.example.test";
        String usuari = "alumne";
        String contrasenya = System.getenv(
                "MAIL_PASSWORD"
        );

        Properties props = new Properties();
        props.put("mail.pop3.host", host);
        props.put("mail.pop3.port", "110");

        Session session =
                Session.getInstance(props);

        Store store =
                session.getStore("pop3");

        Folder inbox = null;

        try {
            store.connect(
                    host,
                    usuari,
                    contrasenya
            );

            inbox = store.getFolder("INBOX");
            inbox.open(Folder.READ_ONLY);

            Message[] missatges =
                    inbox.getMessages();

            System.out.println(
                    "Missatges: " + missatges.length
            );

            for (Message m : missatges) {
                System.out.println(
                        "Assumpte: " + m.getSubject()
                );
            }

        } finally {
            if (inbox != null && inbox.isOpen()) {
                inbox.close(false);
            }

            if (store.isConnected()) {
                store.close();
            }
        }
    }
}

POP3 té un model senzill orientat a la recuperació. Jakarta Mail continua presentant la bústia com una Folder, però en POP3 la carpeta útil és essencialment INBOX.

Canviar a IMAP

Amb IMAP, la mateixa abstracció permet treballar amb diverses carpetes mantingudes al servidor. El canvi conceptual és petit perquè la biblioteca amaga moltes diferències del protocol:

JAVA 
Store store = session.getStore("imap");

try {
    store.connect(host, usuari, contrasenya);

        System.out.println(
                carpeta.getFullName()
        );

    try {
        inbox.open(Folder.READ_ONLY);

        for (Message m : inbox.getMessages()) {
            System.out.println(m.getSubject());
        }

    } finally {
        if (inbox.isOpen()) {
            inbox.close(false);
        }
    }

} finally {

        store.close();
    }
}

Quan utilitzar cada nivell

  • Sockets: quan esteu dissenyant un protocol propi o necessiteu entendre/controlar la comunicació de baix nivell.
  • Llibreria de protocol: quan el protocol ja és estàndard i existeix una implementació madura.
  • HTTP client, Jakarta Mail, clients FTP...: eviten reimplementar parsers, extensions i casos límit que ja estan resolts.
