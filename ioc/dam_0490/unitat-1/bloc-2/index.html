1. Primer procés fill amb ProcessBuilder

Java pot iniciar altres programes. La classe principal per preparar l'ordre és ProcessBuilder i l'objecte que representa el programa ja iniciat és Process.

Informació

Model mental

ProcessBuilder prepara com s'executarà el programa. start() el posa en marxa. A partir d'aquell moment, Process representa el procés fill i ens permet esperar-lo, consultar si continua viu, llegir-ne la sortida o finalitzar-lo.

Exemple mínim: executar el Java instal·lat

Comencem amb una ordre que no depèn del sistema operatiu: executar el mateix Java que està utilitzant l'aplicació.

JAVA PrimerProces.java 
import java.nio.file.Path;

public class PrimerProces {
    public static void main(String[] args) throws Exception {
        String java = Path.of(
                System.getProperty("java.home"),
                "bin",
                "java"
        ).toString();

        ProcessBuilder pb = new ProcessBuilder(java, "-version");
        pb.redirectErrorStream(true);

        Process proces = pb.start();

        proces.getInputStream().transferTo(System.out);

        int codi = proces.waitFor();
        System.out.println("Codi de sortida: " + codi);
    }
}

Hi ha quatre passos importants:

  1. Construïm l'ordre.
  2. Creem el ProcessBuilder.
  3. Cridem start().
  4. Esperem el final i obtenim el codi de sortida.
Èxit

Observeu-ho

El programa principal no executa les instruccions de l'altre programa dins de la seva JVM. El sistema operatiu crea un procés independent.

Executar una altra classe Java

Per executar una classe del mateix projecte com un programa independent necessitem indicar el Java actual, el classpath actual i el nom complet de la classe que conté main.

JAVA 
import java.nio.file.Path;
import java.util.List;

public static List<String> ordreJava(Class<?> classe, String... arguments) {
    String java = Path.of(
            System.getProperty("java.home"),
            "bin",
            "java"
    ).toString();

    String classpath = System.getProperty("java.class.path");

    List<String> ordre = new java.util.ArrayList<>();
    ordre.add(java);
    ordre.add("-cp");
    ordre.add(classpath);
    ordre.add(classe.getName());
    ordre.addAll(List.of(arguments));

    return ordre;
}
Important

No construïu tota l'ordre en una única cadena si no és necessari. ProcessBuilder accepta cada argument com un element separat. Això evita molts problemes amb espais, cometes i rutes.

Exercici: Un fill molt petit
Creeu una classe Salutador amb main(String[] args) que rebi un nom i mostri Hola, nom. Des d'una altra classe, executeu-la com a procés independent.
Bàsic 15 min
Veure pistes
  • Primer feu que Salutador funcioni directament.
  • Després construïu l'ordre amb java.home i java.class.path.
  • No oblideu esperar la finalització.

2. Arguments, sortides i codis de retorn

Un procés fill necessita una manera d'entrar dades i una manera de comunicar el resultat. Tres mecanismes molt útils són els arguments, els streams i el codi de sortida.

Figura

Un programa fill amb codis de sortida

JAVA ClassificadorNumero.java 
public class ClassificadorNumero {

    public static void main(String[] args) {
        if (args.length != 1) {
            System.err.println("Cal indicar un enter");
            System.exit(10);
        }

        try {
            int numero = Integer.parseInt(args[0]);

            if (numero >= 0) {
                System.out.println("RESULTAT=NO_NEGATIU");
                System.exit(0);
            } else {
                System.out.println("RESULTAT=NEGATIU");
                System.exit(2);
            }

        } catch (NumberFormatException e) {
            System.err.println("L'argument no és un enter");
            System.exit(10);
        }
    }
}

El text de la sortida pot contenir informació detallada. El codi de sortida permet al procés pare prendre una decisió senzilla:

CodiSignificat en aquest exemple
0El programa ha acabat correctament i el nombre no és negatiu.
2El programa ha acabat correctament, però el resultat és negatiu.
10Hi ha un problema amb els arguments.
Informació

Important

El significat dels codis és un contracte de l'aplicació. El sistema operatiu només veu un enter. El vostre programa decideix què significa cada valor.

Capturar la sortida

JAVA 
ProcessBuilder pb = new ProcessBuilder(ordre);
pb.redirectErrorStream(true);

Process proces = pb.start();

String sortida;
try (var lector = proces.inputReader()) {
    sortida = lector.lines()
            .collect(java.util.stream.Collectors.joining(System.lineSeparator()));
}

int codi = proces.waitFor();

System.out.println("CODI=" + codi);
System.out.println(sortida);

Amb redirectErrorStream(true) la sortida d'error es combina amb la sortida estàndard. Això simplifica molts casos on només necessitem un únic registre del procés.

Redirigir la sortida a un fitxer

JAVA 
Path directori = Path.of("logs");
Files.createDirectories(directori);

Path log = directori.resolve("proces-01.txt");

ProcessBuilder pb = new ProcessBuilder(ordre);
pb.redirectErrorStream(true);
pb.redirectOutput(log.toFile());

Process proces = pb.start();
Important

Si un procés genera molta sortida i ningú consumeix els seus streams, el buffer es pot omplir i el procés es pot bloquejar. Llegir la sortida o redirigir-la a un fitxer evita aquest problema.

Exercici: Tres resultats observables

Veure pistes
  • Feu primer una funció que construeixi l'ordre.
  • Executeu cada cas per separat.
  • Comproveu que el procés pare no necessita interpretar el text per saber com ha acabat.

3. Esperar sense bloquejar-se: timeout i finalització

waitFor() sense límit espera fins que el procés acabi. Això és correcte si tenim la garantia que el fill finalitzarà. En programes robustos sovint és millor establir un temps màxim.

JAVA 
import java.util.concurrent.TimeUnit;

boolean haAcabat = proces.waitFor(3, TimeUnit.SECONDS);

if (haAcabat) {
    int codi = proces.exitValue();
    System.out.println("Ha acabat amb codi " + codi);
} else {
    proces.destroyForcibly();
    proces.waitFor();
    System.out.println("Procés finalitzat per timeout");
}

La seqüència és important:

  1. esperem com a màxim el temps permès;
  2. si ha acabat, llegim exitValue();
  3. si no ha acabat, demanem o forcem la finalització;
  4. tornem a esperar perquè el sistema operatiu confirmi que el procés ja ha acabat.
Problema

Problema típic: cridar exitValue() abans que el procés hagi acabat.

Solució

Comproveu primer el resultat de waitFor(timeout, unitat). Només si retorna true és segur obtenir el codi amb exitValue().

Finalització suau o forçada

destroy() demana la finalització del procés. destroyForcibly() és més contundent. En general és millor donar una oportunitat a una finalització ordenada quan el programa fill la pugui gestionar.

Informació

Disseny robust

Un timeout no és només una tècnica de rendiment. És una garantia que una tasca defectuosa no deixarà tota l'aplicació bloquejada indefinidament.

Exercici: Procés lent
Creeu un programa fill que dormi cinc segons. Executeu-lo des d'un pare que només estigui disposat a esperar-ne dos. Comproveu que el pare recupera el control.
Mitjà 15 min
Veure pistes
  • Useu Thread.sleep al fill.
  • Useu waitFor amb TimeUnit.SECONDS al pare.
  • Després de destroyForcibly, espereu de nou el procés.

4. Llançar diversos processos concurrentment

Hi ha una diferència decisiva entre crear diversos processos i permetre que estiguin actius alhora.

Patró seqüencial

JAVA 
for (String valor : valors) {
    Process proces = crearProces(valor).start();
    proces.waitFor();       // esperem immediatament
}

Aquí només hi ha un procés fill actiu cada vegada. El següent no comença fins que l'anterior ha acabat.

Patró concurrent: primer llançar, després recollir

JAVA 
List<Process> processos = new ArrayList<>();

// Fase 1: llançament
for (String valor : valors) {
    Process proces = crearProces(valor).start();
    processos.add(proces);
}

// Fase 2: recollida
for (Process proces : processos) {
    boolean acabat = proces.waitFor(3, TimeUnit.SECONDS);

    if (acabat) {
        System.out.println(proces.exitValue());
    } else {
        proces.destroyForcibly();
        proces.waitFor();
    }
}
Èxit

Aquesta separació és fonamental: iniciar totes les tasques abans d'esperar-ne cap permet que diversos processos avancin durant el mateix interval de temps.

Conservar la informació de cada procés

En aplicacions reals normalment necessitem recordar quin procés correspon a quina entrada i on s'ha desat la seva sortida. Un record petit és una solució clara:

JAVA 
record ProcesEnCurs(
        String identificador,
        Process proces,
        Path fitxerSortida
) {}

Així podem crear una List<ProcesEnCurs>, llançar totes les tasques i després recollir els resultats sense perdre la relació entre entrada, procés i log.

Temps real i suma de temps

Si cinc processos triguen aproximadament dos segons cadascun, la suma dels temps de treball és d'uns deu segons. Però si poden avançar alhora, el temps real observat per l'usuari pot acostar-se molt més a dos segons que a deu.

5. Monitoratge, fitxers i depuració

Treballar amb processos exigeix observar què està passant. Java ofereix informació útil tant des de Process com des de ProcessHandle.

JAVA 
Process proces = pb.start();

System.out.println("PID=" + proces.pid());
System.out.println("VIU=" + proces.isAlive());

ProcessHandle handle = proces.toHandle();

handle.info().command().ifPresent(
        cmd -> System.out.println("ORDRE=" + cmd)
);

Una caixa d'eines mínima amb Path i Files

Moltes aplicacions multiprocés necessiten preparar directoris, llegir entrades o escriure resultats. Aquestes operacions no són concurrència, però formen part del codi robust que envolta els processos.

JAVA 
Path carpeta = Path.of("dades");
Path fitxer = carpeta.resolve("entrada.txt");

if (!Files.isDirectory(carpeta)) {
    throw new IllegalArgumentException("La carpeta no existeix");
}

if (!Files.isRegularFile(fitxer)) {
    throw new IllegalArgumentException("Falta el fitxer d'entrada");
}

String contingut = Files.readString(fitxer).trim();

Path resultats = Path.of("resultats");
Files.createDirectories(resultats);

Validar precondicions

Els mètodes públics han de fallar de manera clara quan reben dades que no poden processar.

JAVA 
public static ProcessBuilder prepararProces(
        List<String> ordre,
        Path sortida) {

    if (ordre == null || ordre.isEmpty()) {
        throw new IllegalArgumentException("L'ordre no pot ser buida");
    }

    if (ordre.stream().anyMatch(s -> s == null || s.isBlank())) {
        throw new IllegalArgumentException("L'ordre conté arguments invàlids");
    }

    if (sortida == null) {
        throw new IllegalArgumentException("La sortida no pot ser null");
    }

    ProcessBuilder pb = new ProcessBuilder(ordre);
    pb.redirectErrorStream(true);
    pb.redirectOutput(sortida.toFile());
    return pb;
}
Important

No amagueu excepcions sense entendre-les. Un catch (Exception e) {} pot convertir un error clar en un resultat misteriós. Durant el desenvolupament, conserveu informació suficient per saber quin procés, quina entrada i quina operació han fallat.

Checklist d'una aplicació multiprocés robusta

Construeixo les ordres amb arguments separats
Valido les precondicions dels mètodes públics
Gestiono stdout i stderr perquè cap buffer bloquegi el procés
Interpreto el codi de sortida només quan el procés ha acabat
Tinc un timeout quan un procés podria quedar penjat
Si vull concurrència, llanço diverses tasques abans de començar a esperar-les
Conservo la relació entre cada procés i les seves dades
Puc observar PID, estat i logs quan depuro
Suggeriment

Per ampliar: ProcessHandle.allProcesses() permet inspeccionar processos visibles per a la JVM. És útil per entendre les eines de monitoratge, però una aplicació normalment ha de controlar sobretot els processos que ella mateixa ha creat.
