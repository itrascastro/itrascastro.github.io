1. Crear processos amb ProcessBuilder

Java pot iniciar un altre programa. La classe principal és ProcessBuilder.

JAVA 
import java.io.IOException;

public class ExempleProces {
    public static void main(String[] args)
            throws IOException, InterruptedException {

        ProcessBuilder pb = new ProcessBuilder("java", "-version");
        Process proces = pb.start();

        int codi = proces.waitFor();
        System.out.println("Codi de sortida: " + codi);
    }
}

Aquí hi ha dues execucions diferents:

TEXT 
procés pare
    |
    | pb.start()
    v
procés fill

El programa que crea el ProcessBuilder és el procés pare. El programa iniciat és el procés fill.

start() inicia el fill. waitFor() fa que el fil actual del pare esperi fins que el fill acabi.

Executar una altra classe Java

En l'EAC, el procés fill també és un programa Java. Per llançar-lo necessitem tres coses:

  1. l'executable de Java;
  2. el classpath;
  3. la classe amb el seu main() i els arguments.

Podem obtenir el Java i el classpath de la JVM actual:

JAVA 
import java.nio.file.Path;
import java.util.List;

String javaActual = Path.of(
        System.getProperty("java.home"),
        "bin",
        "java"
).toString();

String classpathActual = System.getProperty("java.class.path");

List<String> ordre = List.of(
        javaActual,
        "-cp",
        classpathActual,
        "demo.Validador",
        "alumne01",
        "dades/alumne01"
);

ProcessBuilder pb = new ProcessBuilder(ordre);

És preferible construir la comanda com una llista. Així cada element és un argument i no hem de muntar manualment una cadena amb espais i cometes.

2. Comunicació amb processos

Un procés independent no pot llegir directament les variables locals d'un altre procés. Necessitem algun mecanisme de comunicació.

Els més habituals en aquest nivell són:

  • arguments de línia de comandes;
  • entrada estàndard, stdin;
  • sortida estàndard, stdout;
  • sortida d'error, stderr;
  • fitxers;
  • codi de sortida.

Més endavant al mòdul apareixeran altres mecanismes, com els sockets.

Codis de sortida

Un procés pot acabar amb un valor enter.

Per convenció, el 0 acostuma a indicar que tot ha anat bé. Altres valors permeten diferenciar errors o resultats.

JAVA 
public class ComprovaNumero {
    public static void main(String[] args) {
        if (args.length != 1) {
            System.err.println("Cal indicar un número");
            System.exit(10);
        }

        int numero = Integer.parseInt(args[0]);

        if (numero >= 0) {
            System.out.println("Número vàlid");
            System.exit(0);
        }

        System.out.println("Número negatiu");
        System.exit(2);
    }
}

El pare pot recuperar aquest valor:

JAVA 
int codi = proces.waitFor();

if (codi == 0) {
    System.out.println("Tot correcte");
} else {
    System.out.println("El procés ha acabat amb codi " + codi);
}

Redirigir la sortida a un fitxer

JAVA 
Path fitxerSortida = Path.of("resultats", "alumne01.txt");

ProcessBuilder pb = new ProcessBuilder(ordre);
pb.redirectErrorStream(true);
pb.redirectOutput(fitxerSortida.toFile());

Process proces = pb.start();

redirectErrorStream(true) uneix stderr amb stdout. La redirecció s'ha de configurar abans de start().

Llegir la sortida des del programa pare

JAVA 
Process proces = pb.start();

try (var lector = proces.inputReader()) {
    lector.lines().forEach(System.out::println);
}

Si un procés escriu molta informació i el pare no consumeix la sortida ni la redirigeix, el buffer es pot omplir i el fill pot quedar bloquejat. Per això, en una aplicació real, la sortida s'ha de gestionar.

3. Espera, timeout i execució concurrent

Aquest codi pot esperar indefinidament:

JAVA 
proces.waitFor();

Quan no controlem completament el procés fill, és millor posar un límit.

JAVA 
import java.util.concurrent.TimeUnit;

boolean haAcabat = proces.waitFor(5, TimeUnit.SECONDS);

if (haAcabat) {
    int codi = proces.exitValue();
    System.out.println("Codi: " + codi);
} else {
    proces.destroyForcibly();
    System.out.println("Procés cancel·lat per timeout");
}

La idea és senzilla:

TEXT 
iniciar
  |
esperar amb límit
  |
  +-- acaba -> obtenir el resultat
  |
  +-- no acaba -> cancel·lar

waitFor() també és un mecanisme de sincronització. El procés pare pot necessitar esperar que el fill acabi abans de llegir un fitxer que aquest està generant o abans de considerar definitiu el seu resultat.

Llançar diversos processos de manera concurrent

Suposem que tenim diverses tasques.

Aquesta versió les converteix, en la pràctica, en una seqüència:

JAVA 
for (Tasca tasca : tasques) {
    Process p = crearProces(tasca).start();
    p.waitFor();
}

El segon procés no comença fins que el primer ha acabat.

Si volem que puguin coexistir, primer els iniciem:

JAVA 
List<Process> processos = new ArrayList<>();

for (Tasca tasca : tasques) {
    processos.add(crearProces(tasca).start());
}

for (Process p : processos) {
    p.waitFor();
}

La diferència important és quan esperem.

TEXT 
Seqüencial
P1 ----------
            P2 ----------
                        P3 ----------

Concurrent
P1 ----------------
P2 ------------
P3 ----------------------

Aquest patró tornarà a aparèixer amb Future: primer enviem feina, després recollim els resultats.

4. Laboratori, fitxers i monitoratge

Creem un programa fill que només espera un temps.

JAVA 
public class TascaLenta {
    public static void main(String[] args) throws Exception {
        String nom = args[0];
        long ms = Long.parseLong(args[1]);

        System.out.println("INICI " + nom);
        Thread.sleep(ms);
        System.out.println("FI " + nom);
    }
}

El programa pare ha de llançar:

TEXT 
A: 3000 ms
B: 1000 ms
C: 2000 ms

Feu dues versions. A la primera, espereu cada procés abans de crear el següent. A la segona, inicieu els tres abans d'esperar.

Mesureu el temps real:

JAVA 
long inici = System.nanoTime();

// feina

long fi = System.nanoTime();
double segons = (fi - inici) / 1_000_000_000.0;

En la versió seqüencial, el temps s'aproxima a la suma de les tres durades. En la concurrent, pot acostar-se a la durada de la tasca més lenta.

Fitxers i validació d'entrada

L'EAC utilitza Path i Files abans d'entrar en la part concurrent. És important separar la lògica de validació de la lògica que crea processos o fils.

JAVA 
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Locale;

public static String llegirContingut(Path ruta) throws IOException {
    if (ruta == null) {
        throw new IllegalArgumentException("La ruta no pot ser null");
    }

    if (!Files.isRegularFile(ruta) || !Files.isReadable(ruta)) {
        throw new IOException("No es pot llegir: " + ruta);
    }

    return Files.readString(ruta)
            .trim()
            .toLowerCase(Locale.ROOT);
}

Operacions que convé dominar:

JAVA 
ruta.resolve("lliurament.txt")
Files.isDirectory(ruta)
Files.isRegularFile(ruta)
Files.isReadable(ruta)
Files.readString(ruta)

També cal validar les precondicions dels mètodes públics.

JAVA 
public static void processar(String id, Path ruta) {
    if (id == null || id.isBlank()) {
        throw new IllegalArgumentException("L'identificador és obligatori");
    }

    if (ruta == null) {
        throw new IllegalArgumentException("La ruta és obligatòria");
    }

    // ...
}

Un error detectat al principi és molt més fàcil de localitzar que un NullPointerException que apareix moltes instruccions després.

Monitorar i depurar processos

El sistema operatiu permet veure els processos en execució. En Linux i macOS són habituals eines com:

BASH 
ps
ps aux
top

Amb un JDK també podem utilitzar:

BASH 
jps

Des de Java, Process i ProcessHandle permeten consultar informació del procés. Per exemple:

JAVA 
long pid = proces.pid();
System.out.println("PID=" + pid);

Per depurar una aplicació multiprocés convé registrar, com a mínim, la tasca que s'està executant, el PID o identificador del procés, el codi de sortida i qualsevol timeout.

5. Connexió amb l'EAC

La primera part de l'EAC combina exactament aquests conceptes:

TEXT 
CorrectorLliurament
    |
    | lògica comuna de validació
    v
ValidadorLliurament
    |
    | s'executa com un procés Java independent
    v
CorrectorProcessos
    |
    | crea diversos processos amb ProcessBuilder
    | espera amb timeout
    | recull codis de sortida
    v
resum final

Per resoldre aquesta part cal entendre Path, Files, precondicions, ProcessBuilder, arguments, redirecció de sortida, codis de retorn, timeout i el patró de llançar tots els processos abans de recollir-los.
